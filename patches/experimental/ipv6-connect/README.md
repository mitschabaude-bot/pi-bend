# Numeric IPv6 connection primitive

This is an additive, isolated implementation of `TCP.connect_ipv6(a, b, c, d, port, scope)`. The four U32 address words are in network order; the native interface scope ID is separate. The effect constructs a sockaddr, starts a nonblocking socket connection, uses the existing writable-poll scheduler, checks `SO_ERROR` on completion, and transfers the socket only on success. Failed connections close their descriptor. Ports above 65,535 fail before creating a socket. The effect contains no DNS, URL parsing or HTTP behavior.

`packages/runtime/src/ipv6-connect.bend` unwraps the existing immutable IPv6 address value. URL parsing and address normalization remain pure Bend. URL IPv6 hosts use scope zero; interface-scoped addresses can supply a numeric OS scope ID. This does not provide interface-name lookup, connection cancellation, DNS, TLS or Happy Eyeballs. Those are further implementation work, not upstream blockers.

Create a fresh compiler copy with `python3 scripts/prepare-ipv6-candidate.py build/FRESH-NAME`. The optional `--base DIRECTORY` can compose this addition with another isolated candidate. The script verifies that every existing compiler/effect file is unchanged and Base contains only the appended declarations. It never installs the candidate.

Run `python3 tests/ipv6_connect_check.py build/FRESH-NAME` for real IPv6 loopback and IPv4-mapped loopback exchanges, connection refusal, and port-bound rejection on native one/four threads and Bun. Each case performs 64 serial lifecycles. Descriptor counts sampled while each successful connection is held open detect growth across these runs; this finite Linux check does not prove general leak freedom or exercise every connect race. The test peer exchanges literal bytes locally; no external address is contacted.

`python3 tests/ipv6_sockaddr_check.py build/FRESH-NAME` uses a disposable copy to intercept only the connect syscall boundary. It verifies address length/family, all four network-order address words, network-order port, native-order scope and zero flow information, including high-bit and maximum U32 values. That copy synthesizes EINVAL instead of contacting the supplied addresses. The production candidate is unchanged. These tests validate Linux; Darwin-specific struct layout is implemented but unverified.

`python3 scripts/benchmark-tcp-bytes.py build/FRESH-NAME OUTPUT_JSON tcp_connect_ipv6.c tcp_connect_ipv6.js` compares existing text-TCP and UTF-8 compiler workloads against the otherwise identical installation, with two warmups and 20 alternating-order pairs. It requires byte-identical emitted C. This measures compiler loading/checking/emission, not networking throughput. Additional JS output comparisons are recorded separately. Adoption requires correctness and relevant performance evidence; shared-host timing uncertainty must remain explicit. The candidate remains uninstalled.

Validation on 2026-09-20: all real loopback/refusal/port tests and all sockaddr field tests pass on Linux native one/four threads and Bun. Each backend completes 128 successful exchanges and 192 expected failures. Measured descriptors remain bounded across successful serial runs. The 20-round median compiler wall ratios (candidate/baseline) are 0.995 for text TCP and 0.998 for UTF-8; median peak RSS is 152,278/151,820 KiB and 412,214/420,214 KiB respectively. These small timing and mixed memory differences do not establish universal performance neutrality. Every measured C output and separate JS controls match byte-for-byte. No scheduler/compiler code was changed or installed.
