# Owned cancellable connection attempts

This isolated additive primitive provides `Connect.ipv4`, `Connect.ipv6`, `Connect.wait`, `Connect.cancel` and `Connect.close`. Numeric address inputs reuse the native IPv4/IPv6 representations; no DNS, address parsing, HTTP or TLS is implemented in the effects. Compiler and scheduler code are unchanged. Prepare a fresh copy with `python3 scripts/prepare-connect-candidate.py build/FRESH-NAME`; optional `--base DIRECTORY` composes it with another isolated candidate. The script verifies every pre-existing compiler/effect file remains byte-identical and Base contains only the appended declarations. Nothing is installed.

A start operation returns either an OS error or an affine attempt owner with an independently copyable cancellation capability. `wait` consumes the owner and transfers exactly one socket on success; failures retire the attempt and close its descriptor. `close` consumes an unawaited owner without returning a socket. Owners must be waited or closed explicitly: discarding an affine value is not automatic resource disposal. The owner-copy negative test is rejected by Bend's type checker.

Cancellation wins until wait completion is committed. Before wait, it closes the socket and leaves the owner available for wait/close; wait reports the platform's ECANCELED. While parked, cancellation removes the existing poll activation, closes the descriptor and resumes it with that error. A second cancellation or any cancellation after retirement returns false. Native polling commits completion while packing the ready activation; Bun treats a wait already selected by the poller as committed even before its continuation executes. Only one of concurrent cancellers can win.

Native cancellation handles contain registry index/generation pairs so stale capabilities cannot affect a reused socket/attempt. Slots are reused; generation wrap retires the slot permanently. Table capacity tracks peak concurrent attempts and is retained for reuse. Bun uses an opaque object marked retired. Cancellation scans the existing parked queue/array; this new path is linear in the number of parked operations. Existing scheduler paths incur no new work when the effects are unused. There are no forced collections or scheduler-wide layout changes.

## Validation

`python3 tests/connect_owned_check.py CANDIDATE` covers real IPv4/IPv6 completion, cancellation before waiting, cancellation of actual parked waits, unawaited close and stale post-retirement capabilities on native one/four threads and Bun. A saturated local listen queue holds attempts pending; a nonblocking control probe verifies this condition. Instrumentation must observe all 32 parked cancellations in the parked case, so passing by cancelling only before wait is insufficient. Successful returned sockets exchange bytes and are closed before the next connection.

Add `--races` to test competing cancellers, four cohorts of 64 parked attempts retired in reverse creation order, and stale handles after native slot reuse. These concurrent-canceller tests use pending connections; they do not establish every ordering between OS completion and cancellation. The core successful-completion tests separately verify that cancellation after completion loses. Audits require zero live attempt rows, owned descriptors and waiters at exit. Native slot count stays at one for serial cases and 64 for cohorts. These finite Linux observations are not proof of general leak freedom or all interleavings. Generation exhaustion itself is not simulated.

Both modes also pass with `--production`, which compiles unchanged effects without instrumentation. `python3 tests/connect_failures_check.py CANDIDATE` verifies refusal and out-of-range ports for both address families on all three backends. Darwin-specific sockaddr/errno branches are implemented but unverified. Deadlines, DNS, Happy Eyeballs, TLS and provider integration remain implementation work.

`python3 scripts/benchmark-tcp-bytes.py CANDIDATE OUTPUT_JSON connect.c connect.js` compares existing text-TCP and UTF-8 compiler workloads against the installation: two warmups, 20 alternating-order pairs, byte-identical C required after every sample. Median wall ratios were 0.988 and 0.993; median peak RSS was 151,698/153,188 KiB and 410,864/416,294 KiB (baseline/candidate). Small shared-host time differences and mixed memory observations do not establish universal performance neutrality. Separate JS output controls are also byte-identical. These measure compiler loading/checking/emission, not new-operation throughput or cancellation scaling. The candidate remains uninstalled.

## Pure Bend AbortSignal adapter

`packages/runtime/src/abortable-connect.bend` composes the primitive with the existing typed AbortSignal and removable deferred observations. It accepts native IPv4/IPv6 address values and returns either an owned socket, a retained typed abort reason, or a socket error. A pre-aborted signal returns before starting any connection. Otherwise it registers an observation before starting, forks one cancellation watcher, consumes the connection owner through wait, removes the observation and joins the watcher before returning. Immediate start failures also drain the observation. The signal remains caller-owned.

A final reason check follows the existing abortable-socket policy: if abort is observed after connection completion, the completed socket is closed before returning that reason. Abort after the final check may follow a successful return. This is an explicit settlement policy, not a promise that abort and OS completion have one universal ordering.

`python3 tests/abortable_connect_check.py CANDIDATE` builds and checks both families on native one/four threads and Bun. Add `--production` for unchanged generated programs; `--no-build` reuses the native binary. Tests cover serial success, refusal, invalid ports, pre-abort/default reasons, 32 concurrent pending attempts sharing one signal, preservation of the first reason, and a deterministic exercise of the post-completion closure branch. The latter calls the settlement helper after obtaining a real socket; it does not claim end-to-end coverage of every completion race. Local peers require EOF for successful and post-completion-aborted sockets. Disposable audit copies require zero remaining attempts, descriptors, waiters and channels. Pre-abort must make zero primitive calls, and pending cancellation must include actual parked waits.

All 42 cases pass in both [audited](../../../docs/runtime-validation/2026-09-20-abortable-connect-result.json) and [production](../../../docs/runtime-validation/2026-09-20-abortable-connect-production-result.json) modes. The [native build](../../../docs/runtime-validation/2026-09-20-abortable-connect-native-build.json) completed in 19.24 seconds with 3,288,208 KiB sampled process-group peak RSS under a 16 GiB guard. These are finite Linux checks and one build observation, not a general leak or performance proof. The adapter adds no compiler or effect changes; it currently requires the isolated connection candidate.
