# Native BMP decoding

`packages/runtime/src/bmp.bend` provides `decode(bytes, pixelLimit) -> Result<Error, Image.Raster>`. It produces the shared row-major straight-alpha RGBA8 raster; it has no file IO, native codec, or JavaScript dependency. The caller supplies a maximum pixel count, checked before palette construction or pixel allocation. Input byte values, dimensions, header and pixel offsets, complete row extents, palette indices, bit masks, and RLE cursor bounds are checked with typed failures.

Supported formats match the BMP decoder paths used by pinned Photon 0.3.4: CORE DIB size 12 with depths 1/4/8/24; INFO/V2/V3/V4/V5 DIB sizes 40/52/56/108/124 with uncompressed depths 1/2/4/8/16/24/32; 16/32-bit bitfields; RLE4 and RLE8 encoded runs, absolute runs, deltas, end-of-line and end-of-bitmap. Rows support padding, bottom-up and permitted top-down order. Indexed images support default and explicit palette counts. Plain 16-bit color uses RGB555; plain 32-bit color ignores the stored fourth byte, matching Photon. V3/V4/V5 bitfields support alpha. Channel expansion matches image-rs's rounding, seven-bit replication, and high-eight-bit truncation for wider channels. Unwritten RLE pixels become opaque black, independently of palette entry zero.

The implementation was checked against [image-rs 0.24.8's BMP decoder](https://github.com/image-rs/image/blob/v0.24.8/src/codecs/bmp/decoder.rs); actual pinned Photon 0.3.4 output is the decisive pixel oracle. JPEG/PNG-compressed BMP, CMYK BMP, and unrecognized DIB headers remain typed `Unsupported` results, as they are unsupported by the reference decoder. This module decodes complete BMP files; clipboard DIBs without the `BM` file header and ICO embedding are different formats and outside this API.

Deliberate strictness differences follow the project's invalid-input policy: zero dimensions, pixel offsets overlapping required metadata, references beyond the declared palette, overlapping/noncontiguous/out-of-depth bit masks, and RLE runs/deltas outside the image are rejected. Both positive and negative stored heights are limited to an absolute 65535, avoiding the reference's asymmetric signed-height bound. Header file-size/image-size advisory fields, printing resolution, color profiles, and unused trailing bytes are not interpreted; the decoder checks the actual byte extent needed for its selected format. It does not attempt to color-manage pixels. These choices preserve supported valid images without recreating corrupt-file fallback colors or signed-overflow behavior.

Header access has a fixed maximum size. Image and RLE bytes are consumed forward; palette lookup takes at most eight tree steps per pixel. Decoding takes linear time in input plus output size, with logarithmic array insertion into the shared raster. Temporary storage is linear in decoded pixels, plus a fixed 256-entry palette. Every accepted RLE transition stays within the pixel budget before materializing skipped pixels; compressed streams cannot expand beyond the configured dimensions.

Run `python3 tests/bmp_check.py --photon /path/to/photon-node-0.3.4/photon_rs.js`. The test-only Photon package may be obtained using the existing `tests/png_check.py --fetch-oracle` integrity-checked download; production code never calls it. The driver builds isolated Bun and native artifacts using ordinary compiler settings, then tests Bun and native one/four-thread execution. It reuses the existing test-only `png_reference.cjs` byte-decoding oracle, whose Photon entry point accepts all supported image formats. Independently generated expected pixels cover every supported header/depth combination, bitfield layouts/alpha, palettes, row order/padding, and RLE modes. A 65,280-pixel RLE fixture checks substantial expansion through a full raster digest. Separate malformed fixtures cover truncation, offsets, dimensions, extreme depth fields, masks, palette indices, RLE bounds, invalid byte values, and the pixel budget. This establishes BMP decoder behavior; it does not mark Pi's full image pipeline complete.
