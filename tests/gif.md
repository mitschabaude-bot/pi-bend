# Native GIF first-frame decoding

`packages/runtime/src/gif.bend` provides `decode(bytes, pixelLimit) -> Result<Error, Image.Raster>`. It decodes GIF87a/89a's first image to the shared RGBA8 logical-screen raster. It supports global and local palettes of 2–256 entries, four-pass interlacing, frame offsets, graphic-control transparency, extension subblocks, and GIF LZW code widths through 12 bits. The implementation uses an owned 4096-entry prefix/suffix dictionary with clear/reset, dictionary-full behavior, and the special current-code-equals-next-code case. Codes may cross subblock boundaries.

Behavior follows [image-rs 0.24.8's still-image GIF decoder](https://github.com/image-rs/image/blob/v0.24.8/src/codecs/gif.rs), verified against the actual pinned Photon 0.3.4 decoder. Pixels outside the first frame are transparent black, irrespective of the logical background index. A transparent palette index retains its palette RGB channels with alpha zero, matching Photon. A local table overrides the global table. The first frame is returned independently of later frames, animation timing, loop counts, or disposal; the parser does not validate subsequent animation data. Comments, plain text, and application data are skipped as bounded extension subblocks. This is the default still-image decode API, not an animation iterator or GIF encoder.

Strict adaptations follow the project's invalid-input policy: an image rectangle outside its logical screen is rejected instead of cropped; zero dimensions, invalid palette references, reserved image-descriptor/control bits, malformed graphic-control framing, invalid code sizes/codes, and incomplete subblocks produce typed failures. The LZW stream must start with a clear code, terminate with an end code, and yield exactly the image rectangle's pixel count. Neither missing decoded pixels nor excess pixels are silently accepted. The parser validates every input byte value. It interprets only first-frame metadata; it is not a full validator for the contents of ignored extension payloads.

The explicit pixel limit checks logical-screen area before image allocation. Frame bounds imply its area fits that limit. Dictionary storage is fixed at 4096 entries; prefix references point to earlier entries and every expansion is bounded. Emission tracks remaining pixels and cannot grow output beyond the frame area. Input scanning and symbol emission are linear; dictionary and raster arrays add logarithmic lookup/insertion factors. Temporary storage consists of input subblocks, decoded frame indices, the bounded dictionary/palette, and the output raster. No host codec or foreign production primitive is used.

Run `python3 tests/gif_check.py --photon /path/to/photon-node-0.3.4/photon_rs.js`. The test-only package can be obtained using the existing PNG harness's integrity-checked `--fetch-oracle` download. The driver builds ordinary Bun and native artifacts and runs Bun plus native one/four threads. Its independent Python fixture encoder writes LZW streams; Photon must agree with independently generated RGBA pixels before Bend is compared. Cases cover palette sizes, local overrides, small interlace heights and all four passes, offset/transparent frames, both GIF versions, extensions, first-frame animation behavior, long runs and random data, code widths 3–12, special dictionary references, dictionary saturation, and resets after saturation. Large results are checked with a full raster digest. Separate fixtures exercise malformed/truncated data and allocation budgets. These checks cover the GIF utility, not the full Pi image-processing suite.
