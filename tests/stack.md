# Stack and direct-child viewport layout

`packages/tui/src/components/stack.bend` owns the upstream entry options, visibility predicate, deterministic grow/shrink distribution and immutable child list. `v-stack.bend` and `h-stack.bend` implement their standalone rendering paths. `layout.bend` builds a viewport frame with child rectangles, clipping, painted rows and hit geometry for a direct stack of leaf components.

`tests/stack_reference.ts` pins the upstream layout and stack sources and compares ten cases: vertical grow, min-size shrink, visibility gaps, allocated horizontal widths, zero-width painting, hit geometry, standalone V/H rendering, max-size grow redistribution and weighted shrink. `tests/stack_check.py` runs the differential comparison on Bun and native one/four threads after `BEND=/home/agent/code/pi-bend-tls/build/bend-process-files/bend2/main.ts sh scripts/build-pure.sh tests/stack.bend build/stack`.

The upstream `renderLayoutFrame(root: Component, width, height, requestRender)` accepts arbitrary layout nodes, including nested stacks and ScrollView. The current Bend `renderLayoutFrame(stack: Stack, width, height)` handles direct leaf children; nested stacks, scroll state and image/scrollbar composition remain pending. Bend's `Nat` and explicit `Maybe` model replace JavaScript's floating-point option values; the default maximum is the largest `Nat` literal, and fractional/non-finite numeric options have no Bend representation. `LayoutBox` omits cyclic parent references; its child tree and `getLayoutBoxesAt` retain the visual geometry needed for hit testing in this milestone.
