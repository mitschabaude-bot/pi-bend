# Native RPC protocol

The endpoint in `packages/coding-agent/src/modes/rpc.bend` accepts already decoded Unicode chunks through `feed(handle, chunk)`, flushes a final unterminated JSON record through `finish(handle)`, and emits newline-terminated JSON records through a caller-owned callback. `start(session, sink)` subscribes to AgentSession events and starts one prompt worker. `stop(owner)` closes its work queue, waits for an accepted prompt to finish, then unsubscribes its listener; the caller may dispose the sink after `stop`. Draining at EOF is an intentional native lifecycle choice; upstream exits its process at EOF.

The endpoint handles every upstream command: `prompt`, `steer`, `follow_up`, `abort`, `clear_queue`, `new_session`, `get_state`, `set_model`, `cycle_model`, `get_available_models`, `set_thinking_level`, `cycle_thinking_level`, `get_available_thinking_levels`, `set_steering_mode`, `set_follow_up_mode`, `compact`, `set_auto_compaction`, `set_auto_retry`, `abort_retry`, `bash`, `abort_bash`, `get_session_stats`, `export_html`, `switch_session`, `fork`, `clone`, `get_fork_messages`, `get_entries` (including `since`), `get_tree`, `get_last_assistant_text`, `set_session_name`, `get_messages` and `get_commands`. Session replacement goes through the host's `newSession`/`switchSession`/`fork` callbacks, then later commands and events use the installed session. A second prompt without `streamingBehavior` while one is active is rejected; `steer` and `followUp` behavior queue into AgentSession. Image blocks are decoded to native `Ai.ImageContent` with strict field types. Response envelopes, session state, slash commands, bash results, cleared queues and the entry tree are encoded by the typed codecs of `modes/rpc-types.bend` (upstream `rpc-types.ts`), which `modes/rpc-client.bend` decodes; absent optional fields are omitted as upstream's `JSON.stringify` omits `undefined` (`get_state` without a model, `get_last_assistant_text` without text). JSONL framing is `modes/jsonl.bend` (upstream `rpc/jsonl.ts`). Reusable `core/session-stats.bend` aggregates all stored message, tool-call, usage, compaction and branch-summary entries; its context usage reuses the native projected-context estimator and returns unknown tokens immediately after a compaction until a later assistant usage is available. The native session entry union does not yet contain upstream standalone `usage` entries, so those cannot contribute. `Rpc.start` receives an optional asset directory and loads viewer assets only for `export_html`; missing assets and in-memory sessions produce correlated errors. Unknown commands return a correlated error. Invalid JSON and non-object records return parse errors. The JSON parser's error text is stable and language-independent rather than reproducing the host JavaScript engine's exception prose. A session-event conversion failure is reported on stderr instead of silently dropping it from the JSONL stream.

Extensions of the served session are bound to an RPC UI context in `rpc` mode (upstream `createExtensionUIContext`, via `ExtensionRunner.setUIContext`) and rebound when the host replaces the session: `select`, `confirm`, `input` and `editor` emit an `extension_ui_request` and wait for the `extension_ui_response` with its id (`cancelled`, `value` and `confirmed` read as upstream's dialogs read them); a dialog's positive `timeout` (sent with the request) or abort signal dismisses it as cancelled, and an already aborted signal answers without a request; `notify`, `setStatus`, `setWidget` (lines or removal; component factories are not sent), `setTitle` and `set_editor_text` (also for `pasteToEditor`) are fire-and-forget requests; `getEditorText` answers `""` and `custom` answers at once; extension errors become `extension_error` records. Every input line other than an `extension_ui_response` runs as its own task, as upstream handles each line without awaiting the previous one: the reader waits until the line finishes (keeping response order) or until a dialog opens, then goes on, so a handler that asks the client (for example `session_before_compact` during `compact`) can receive its answer; `stop` answers open dialogs as cancelled and joins such tasks. Extension command-context actions (`waitForIdle`, `newSession`, `fork`, `navigateTree`, `switchSession`, `reload`) are bound through the RPC host and the current session; a host failure is reported to the extension as a cancelled change, since the context's result carries only `cancelled`.

The prompt response is written from AgentSession's prompt preflight (upstream `preflightResult`): success once the prompt runs, is queued or is handled, its error when it is rejected first; prompts, steers and follow-ups reach input handlers with source `rpc`. An extension's ctx.shutdown() is bound as the session's shutdown handler (`Session.setShutdownHandler`, upstream `shutdownRequested`): RPC mode then disposes the runtime and exits after the command's response, or at `agent_settled` when a run is under way. Upstream answers a prompt before its run starts, while the native endpoint answers once the run has started, so a shutdown the run requests waits for `agent_settled` as upstream's does. `tests/rpc_mode_check.py` covers both paths with a recording host. Remaining gaps: native streaming stdin and strict UTF-8 chunk decoding belong to the caller's transport.

The protocol fixture covers strict LF and CRLF framing, U+2028/U+2029 inside payloads, an unterminated final record, a record split over chunks, and success/error response ordering. `rpc_protocol_check.py` pins the hashes of pi v0.87.1's `rpc/jsonl.ts` and `rpc/rpc-mode.ts`, calls the actual upstream `attachJsonlLineReader` and `serializeJsonLine`, and compares six byte-exact outputs on Bun, native one thread and native four threads. The faux-provider lifecycle fixture checks prompt ACK before the first event, typed image preservation, strict malformed input, populated steering/follow-up queue clearing, nested session-tree serialization, and drain through `agent_settled` on EOF, on all three backends.

Run `bun build/bend-process-files/bend2/main.ts tests/rpc-protocol.bend -o build/rpc-protocol.js`, `BEND=build/bend-process-files/bend2/main.ts sh scripts/build-pure.sh tests/rpc-protocol.bend build/rpc-protocol-native`, then `python3 tests/rpc_protocol_check.py`. Build `tests/rpc-session.bend` to `build/rpc-session.js` and `build/rpc-session-native` with the same two commands, then run `python3 tests/rpc_session_check.py`. An isolated worktree may set `BEND` to the main checkout's compiler path.

`RpcClient` (`modes/rpc-client.bend`) drives a child `--mode rpc` process with a typed method per command; see `packages/coding-agent/test/rpc-client.bend` and `tests/rpc_client_cli_check.py`, which runs upstream `rpc.test.ts` through the client against the native CLI and a local fake provider.

`tests/rpc_mode_check.py` runs upstream `rpc-prompt-response-semantics.test.ts` and `suite/regressions/5868-rpc-unknown-command-id.test.ts` against the endpoint (`tests/rpc-mode.bend`) on Bun and native one/four threads. `tests/rpc_client_check.py` runs the three `rpc-client-*` suites.
