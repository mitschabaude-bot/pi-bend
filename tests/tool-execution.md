# Interactive tool execution display

`packages/coding-agent/src/modes/interactive/components/tool-execution.bend` retains immutable tool-call arguments, partial/final result content, error status, expansion and execution flags. Generic display uses native Text, pretty JSON and theme colors. Definition-style display uses native Box painting with fallback preview and borrowed call/result renderer callbacks. Self-rendered callbacks supply their own framing. `fromAiToolCall` and `updateFromAgent` let the transcript reducer update one retained tool row as events arrive.

`tests/tool_execution_check.py` compares terminal frames, including xterm cells, colors and attributes with upstream `f07218c4d` under a controlled colored terminal (`FORCE_COLOR=1`, `TERM=xterm-256color`, `NO_COLOR` unset). The oracle hashes upstream ToolExecutionComponent, the four built-in renderer modules, result-text normalization, theme asset, Box/Text and key-hint implementations. Cases cover generic pending/args/start/partial/success/error, fallback and custom slots, read/bash/edit/write pending/partial/final/error, read range and expanded result, wide/narrow/expanded read-error overflow hints, bash five-line tail preview, write ten-line preview and expansion, image placeholders and iTerm2 image output. The mounted Kitty check asserts a stable image packet across elapsed-time redraws and a placeholder when images are hidden. Build `tests/tool-execution.bend`, then run the checker on Bun and native one/four threads. Equivalent ANSI span boundaries are allowed; visible styling must match. Failed builtin executions use a fresh upstream component to avoid its cached Container/Text cast failure after success.

This is a partial port. The built-ins cover text output with ordinary relative paths. Bash's five-visual-line tail preview and skipped-line count match a wrapped-output terminal parity scenario. Image results use the native terminal capability detector and image component; Kitty receives PNG payloads, converting other formats through the native image codec. Conversion currently runs synchronously during rendering, so large non-PNG images can pause input. The `show-images` setting updates existing tool rows and future mounts. Path hyperlinks/home shortening, result truncation metadata, keyboard focus/input through retained custom components and shared mutable renderer state remain incomplete. The fixture pins colored terminal behavior; honoring `NO_COLOR` at runtime is separate.

Rendered lines are cached per component and reused until the tool state, the width or the shown elapsed time changes, as upstream's components keep their text between frames. Write previews keep upstream's highlight cache: streamed arguments highlight new lines one at a time and the first 50 lines together, complete arguments are highlighted as a whole. `tests/write_highlight_check.py` streams 19 writes (TypeScript, Python and plain text, 5 to 120 lines, CRLF, tabs, block comments and strings crossing line 50, rewritten content) in random chunks and compares all 343 previews with upstream `writeRenderers.renderCall` reusing its component:

```sh
bun build/bend-native-toolchain/bend2/main.ts tests/write-highlight.bend -o build/write-highlight.js
python3 tests/write_highlight_check.py bun build/write-highlight.js
```

`tests/edit-tool-no-full-redraw.bend` ports the three named upstream preflight contracts with an injected native read callback and actual Screen plans. `tests/edit_tool_no_full_redraw_check.py` checks large preview settlement without a full redraw, replay from saved diff details after file deletion, and preflight errors without fabricated diffs. A controlled A→B→A read sequence also checks stale-completion rejection and disposal joining owned reads. The transcript owns the computation callback and supplies the current session cwd.

Mounted read components receive an explicit cwd, package root and expand-key context. The differential fixture exercises compact skill/docs/resource labels, their precedence, ordinary paths and expanded calls across thirteen path cases. An unfinished read has no result section, including when expanded.
