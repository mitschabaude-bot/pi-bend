# HTTP keep-alive

`runtime/fetch.bend` pools connections per fetch callback like undici's Agent as bundled with Node 24 (undici 7.28): a response read to completion (`MessageComplete` with no leftover bytes) on a persistent HTTP/1.1 connection parks its connection for the next request to the same origin (scheme, host, port), oldest first. The idle limit is 4 s, or a `Keep-Alive: timeout=N` hint minus 2 s capped at 600 s; a hint of 2 s or less, `Connection: close`, HEAD, an aborted request or an unfinished upload close the connection instead. Before reuse an idle socket is checked with `TCP.readable` (undici's idle-socket validation): pending data or a peer close discards it and the request opens a new connection. A request that fails on a reused connection is not retried (`ReusedExchangeFailure`/`ReusedHeaderFailure`, classified like their fresh counterparts), as undici does.

Each pooled connection runs under its own abort controller; the request's signal is linked to it (`Abort.link`) while the request is in flight, so aborting a request still destroys its connection and reports the request's reason, and a request deadline that fires later no longer reaches the parked connection. `Fetch.dispose` closes the idle connections of every callback created from the runtime. The agent runtime passes its shared fetch to the OpenAI Responses provider, as upstream providers share the global fetch.

`tests/fetch_keepalive_check.py` runs `tests/fetch-keepalive.bend` against a local HTTP/1.1 server that counts connections: persistent responses reuse one connection, `Connection: close` and `Keep-Alive: timeout=2` prevent reuse, a longer hint allows it, an idle socket the server closed is replaced without an error, and connections idle past 4 s are not reused. Bun and native one/four threads pass. Live: a two-request gpt-6-luna tool turn opens one TLS connection (6.3–8.4 s wall against pi 0.87.1's 6.2–7.2 s; 14.5 s before).

Not ported: HTTP/1.1 pipelining (undici's default of 1 is what is implemented), Node's fetch default request fields (after `host` it writes `connection: keep-alive`, then the caller's fields, then `accept: */*`, `accept-language: *`, `sec-fetch-mode: cors`, `user-agent: node` when absent and `accept-encoding: gzip, deflate`, the last requiring response decompression; the port writes only `host` and the caller's fields, and HTTP/1.1 defaults to persistent), revalidating TLS post-handshake records on an idle connection (such a connection is conservatively discarded), and per-origin connection limits (undici's default is unlimited).
