# Image component

`packages/tui/src/components/image.bend` ports `components/image.ts` from pi-mono `46c9de402` into one immutable component. `ImageTheme` borrows the native fallback-color callback; `ImageOptions` retains optional width/height limits, filename and explicit Kitty ID. `new(data,mime,theme,options,dimensions)` returns a typed result. The state is named `ImageComponent` because Bend's Base already reserves `Image`. `getImageId` and `invalidate` are pure; `render(image,width,terminalState,environment,tmuxHyperlinks)` returns `IO(Result<Error,Rendered{image,terminal,lines}>)`. Callers retain the returned component and shared terminal state, and own callback disposal. Renderer adapters to the shared Component interface remain a separate ownership boundary, as for native Text.

The width-only cache preserves upstream's intentional behavior: repeated widths return cached lines without consulting changed capabilities or invoking the theme, and invalidation clears the cache while preserving the Kitty ID. IDs are allocated only on an uncached Kitty render; explicit IDs are preserved, including after an iTerm transition. Default image width leaves two terminal columns and caps at 60; default height caps the image to a square pixel box using actual cell dimensions. Kitty places the transmission first with empty trailing rows and disables terminal cursor movement. iTerm places empty rows first, then moves the cursor up before its transmission. Fallback styling runs before ANSI/grapheme-aware truncation with Pi's three-dot ellipsis.

Unknown/unreadable header dimensions intentionally retain Pi's 800×600 estimate; the real PNG header path is also exercised. Explicit invalid dimensions/options and malformed displayed payloads reject rather than reproducing coercion or permissive base64 decoding. Unused image payloads can still produce a text fallback. Header interpretation inherits the documented terminal-image corrections, including lossless JPEG metadata. Entropy failures and image errors remain distinct typed errors. No host renderer, mutable JS object or global capability state supplies production behavior.

`image_component_reference.ts` hash-checks and executes the actual source modules and all three original Image component tests from `terminal-image.test.ts`: “caps Image component height to a square pixel box by default”, “places image sequence on first line with empty padding rows”, and “truncates long image fallback lines to render width”. Complete rendered lines are compared, including ANSI styling and cursor movement; generated IDs are normalized only after checking their permitted range and stability across renders. The broader 115-case corpus compares multi-render cache/callback counts, narrow/zero widths, explicit/automatic IDs, Kitty/iTerm/text fallback, changed capabilities, invalidation, square bounds, filenames, fractional cell dimensions and header discovery. Five additional malformed cases verify rejection without invoking the theme. The callback owner disposes its handle after each sequence, checking that the component has not consumed it.
