# AgentSessionRuntime contracts

[The native harness](agent-session-runtime.bend) exercises `core/agent-session-runtime.bend` with the existing faux provider. [The checker](agent_session_runtime_check.py) compares observable state, persisted entries and extension event order with the upstream runtime and branching suites. Its factory restores the stored context into each replacement agent; its release callback disposes fixture services after the host disposes the session.

`persisted` and `memory` cover new sessions, parent headers, resume, missing-cwd refusal, invalid fork IDs, cloning at the leaf and forking before a user message. Cloning compares complete immutable message snapshots before and after replacement. `branching` covers single-message, in-memory and middle-of-history forks. `events` checks startup, new/resume/fork lifecycle events, cancellation and invalidate/rebind ordering. Retired-context rejection is a separate remaining assertion of the runtime-events suite; event-order checks alone do not cover it.

`fork_during_tool` and `switch_during_tool` synchronize on the existing blocking tool's start channel. Replacement must settle the outgoing turn before teardown; the persisted switch case checks the tool result and terminal assistant entry, while the in-memory fork case checks that the outgoing aborted turn never reaches the replacement history.

`extra` covers the exact unsaved-session error, import filename collision protection and cross-directory replacement. `sdk_restore` uses the production SDK factory with an injected model catalog and no model/thinking override: destination session state must win over settings defaults. Its JSONL fixture reuses messages actually written by the native provider fixture. Upstream's split SDK construction is represented by `createAgentSession`; the missing split public APIs remain a source-coverage gap.

Build with `BEND_TUS=64 BEND_CFLAGS='-DBEND_APP_ARGV -DBEND_DEFAULT_THREADS=1' sh scripts/build-incremental.sh tests/agent-session-runtime.bend build/agent-session-runtime-native`. Run `python3 tests/agent_session_runtime_check.py --runner build/agent-session-runtime-native --threads 1`, then repeat with `--threads 4`. The checker supplies isolated directories and faux credentials; it makes no live provider request.
