# EXIF orientation

`packages/coding-agent/src/utils/exif-orientation.bend` ports the meaningful metadata and pixel behavior of pinned Pi `46c9de402`, `packages/coding-agent/src/utils/exif-orientation.ts`. `getExifOrientation` returns a typed result containing an orientation from 1 through 8. `applyExifOrientation` consumes a shared `Image.Raster`, parses the original encoded bytes, and delegates all pixel geometry to `Image.orient`.

The parser recognizes JPEG APP1 Exif and WebP EXIF chunks, including WebP's optional `Exif\0\0` prefix and odd-length chunk padding. TIFF supports both byte orders and an unsigned IFD0 offset. Missing Exif, missing orientation, and a null IFD0 pointer mean orientation 1. Unknown TIFF fields are skipped; orientation must be one inline SHORT with count 1 and value 1–8. The parser reads IFD0 only: thumbnail directories, unknown-field payloads, and the next-IFD pointer's target are not interpreted. It requires complete IFD0 entries and the trailing next-IFD pointer field.

Under the project's strict parsing policy, invalid byte values, invalid TIFF headers, duplicate orientation tags, malformed orientation type/count/value, and truncated or out-of-chunk metadata return typed errors. Unlike Pi's JavaScript parser, offsets cannot become negative through bitwise arithmetic or read into later JPEG segments/WebP chunks. WebP requires the declared RIFF extent to match the input and validates padding for each traversed chunk, including EXIF. JPEG stops at SOS or EOI. Neither parser validates compressed image content or metadata after the first recognized Exif block; image decoding remains the codec's responsibility. The raster API consumes its input on both success and failure, without Photon identity/free conventions.

Parsing validates byte values once, then traverses container sections forward. It takes time linear in the input and inspected directory size, with linear temporary list storage for bounded chunk slices. It never repeatedly indexes or measures a whole byte list per TIFF entry or chunk.

Run `python3 tests/exif_orientation_check.py`. The driver builds isolated Bun and native artifacts with the ordinary compiler settings, then checks Bun and native one/four-thread execution. Its oracle is the actual pinned TypeScript source, including `applyExifOrientation`; a small RGBA container supplies only Photon storage and horizontal/vertical flips, while Pi's rotation code runs unchanged. Coverage includes both TIFF byte orders, every orientation on a nonsquare colored raster, unrelated fields/segments/chunks, optional prefix and padding, and long forward scans. Separate malformed fixtures assert typed rejection and propagation through the public apply function. This establishes the EXIF utility behavior; it does not mark image decoding/resizing or Pi's broader image suites complete.
