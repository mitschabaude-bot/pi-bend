# Native public find tool

`core/tools/find.bend` implements the native `AgentTool`, typed `FindToolInput`/`FindToolDetails`, injectable `FindOperations.exists/glob`, `FindGlobOptions`, context cwd, result normalization, cancellation and owned execution-callback retirement. Injected operations remain caller-owned and receive `ignore: ["**/node_modules/**", "**/.git/**"]` and the exact limit. Their order and result count are preserved, including results beyond their requested limit. The native default performs Bend directory traversal and matching directly; it never invokes fd, Git or another host search implementation.

Native traversal uses `runtime/path-glob.bend`, filesystem directory snapshots and `Ignore.testEntry`. A slashless pattern matches basenames; a path-containing pattern matches the absolute candidate with the same implicit `**/` prefix as Pi. Hidden entries, directories, symlinks and other metadata entries participate. Symlinks are emitted without a directory suffix and are never followed recursively; FIFO contents are never opened. Default traversal does not invent the injected-operation exclusions: `.git` and `node_modules` remain searchable when ignore rules allow them.

Ignore files retain their containing-directory scope and source priority: `.fdignore`, `.ignore`, `.gitignore`, Git `info/exclude`, global Git excludes, then global fd excludes; nearer rules win within each source kind. Git sources stop at the nearest `.git` boundary when the search starts in a repository. Outside a repository, Pi passes fd's `--no-require-git`, so inherited Git rules cross nested repository boundaries; native traversal preserves that distinction. Ancestor ignore files are loaded, but an explicitly chosen search root is not itself pruned. The shared `testEntry` API permits this without changing the existing ancestor-aware `Ignore.test` API.

Global sources include `$HOME/.gitconfig` and `$XDG_CONFIG_HOME/git/config` `core.excludesFile`, the default `$XDG_CONFIG_HOME/git/ignore`, and `$XDG_CONFIG_HOME/fd/ignore`, with `~` expansion and the usual `~/.config` fallback. Global anchored patterns see the absolute POSIX path without its leading slash, matching fd's absolute search path behavior. Ordinary `.git` directories and linked Git metadata with `gitdir:` and `commondir` are supported without a HEAD requirement. No general Git-config/include evaluator is claimed: this port reads the excludes setting needed by fd, which likewise does not implement Git's full configuration evaluation.

## Reference assertions and executed checks

The reference is pi-mono `46c9de402` and the installed test-only fd **10.3.0**. `find_public_check.py` exercises 85 public scenarios on Bun and optimized native one/four workers, including actual fd directory comparisons. It covers the five relevant `tools.test.ts` assertions: **“should include hidden files that are not gitignored”**, **“should respect .gitignore”**, **“should surface fd glob parse errors”**, **“should treat flag-like patterns as search text”**, and **“find uses ctx.cwd when provided”**.

The four path-glob assertions from `3302-find-path-glob.test.ts` are covered, together with absolute paths and separator-boundary controls. The sibling and deep-subtree scoping assertions from `3303-find-nested-gitignore.test.ts` are covered separately before and after extending the scoped tree. The six POSIX/root/outside-root/injected-tool assertions from `6104-find-root-relativization.test.ts` are covered, including literal backslashes in POSIX filenames and preservation of directory suffixes. Its five Windows `path.win32` cases remain outside this native POSIX implementation.

Additional checks exercise source priority, inherited ignore files, nested repositories both inside/outside Git, linked worktree excludes, unreadable directories, root files, broken/cyclic symlinks, FIFO metadata, global configuration, injected error and cancellation stages, caller-owned callback reuse after disposal, invalid limits, exact/overrun/zero result limits, 1,001-file traversal, UTF-8 byte truncation, whitespace/newline filenames and Unicode scalar matching. Unreadable entries and optional ignore files are skipped as fd does. The runner uses `/var/tmp` because this server currently has `/tmp/.git`; treating temporary paths as outside Git without checking that ancestor would invalidate the boundary tests. Flag-like patterns use a fixture-only argv prefix to bypass the older private Bend runtime's `--help` interception; the public tool receives the original pattern unchanged.

## Explicit native behavior and remaining boundaries

Native traversal selects entries in deterministic scalar path order, including directory suffixes. fd sorts buffered fast searches but can emit concurrent discovery order for slow searches; at a result limit, the selected subset may therefore differ. This decision is independent of the unresolved locale-sensitive default ordering for `ls`. Zero means unlimited traversal, as in fd; Pi's unusual `0 results limit reached` notice is retained for nonempty results. Native and injected result-limit notices retain their different upstream wording.

Unicode scalar glob matching and simple folding replace fd's UTF-8-byte wildcard/case limitations; the exact oracle scope is documented in `path-glob.md`. Native filenames retain whitespace and newlines instead of Pi's fd line-reader trimming/splitting corruption. Negative, fractional, nonfinite and out-of-range limits, malformed glob/ignore syntax, invalid UTF-8 and malformed quoted excludes settings return typed errors. These follow the user's strict-invalid-input and native-string policy; fd may silently skip malformed ignore patterns or decode bytes lossily. Native Git configuration respects `[core]` and permits quoted whitespace paths rather than applying fd's loose regex across arbitrary sections. Relative linked Git paths use proper lexical resolution rather than reproducing the reference ignore crate's resolution bugs.

The shared native `TruncationResult.maxLines` sentinel is `4294967295` rather than JavaScript's `Number.MAX_SAFE_INTEGER`; the 51,200-byte cap wins first, so output is unaffected. Typed filesystem errors use the project's native `Error N: message` rendering rather than platform-specific fd diagnostics. `AgentTool` still lacks the shared extension `ToolDefinition` renderer/prompt-contribution interface, so renderer adapters remain separate shared work, not claimed complete here. The registry now includes find as an explicitly selected tool (`--tools find`), with typed error/detail conversion and JSON event serialization; the default read/bash/edit/write selection is preserved. `PI_BEND_FIND_LIVE=1 python3 tests/print_cli_check.py` exercises the complete native model/tool loop using stored Codex OAuth, including the result-limit notice and serialized details. These integration/differential checks are not claimed universal proofs.

```sh
BEND=/path/to/private/bend2/main.ts BEND_TUS=8 sh scripts/build-pure.sh tests/find-public.bend build/find-public
/path/to/private/bend2/main.ts tests/find-public.bend -o build/find-public.js
python3 tests/find_public_check.py bun native-1 native-4 --fd /path/to/fd-10.3.0
```

A small throughput check used 20 directories with 100 files each, pattern `*.txt`, warm filesystem cache and the median of five runs after one warmup. The full native one-worker fixture took about 37 ms at the default 1,000-result cap and 73 ms with an unlimited 2,000-result traversal; fd 10.3.0 took about 6.3 ms and 6.2 ms respectively. This is not a matched-output microbenchmark: the native fixture also performs public-tool normalization/truncation and Base64 report encoding, while fd emits raw paths. Guarding unreachable matcher states reduced the same native fixture from roughly 41/76 ms to 37/73 ms. No throughput parity claim is made from these measurements.
