# pi-ai library port

Reference: pi-mono `46c9de402`, `packages/ai`. This is a partial library port, separate from the bootstrap executable. Providers, authentication, the model registry and complete schema validation remain unported.

`src/types.bend` defines content, usage/cost, calls/results, messages, contexts, models, provider options and the twelve assistant event variants. Numeric fields use binary64, optional fields use `Maybe`, and constructors carry the role/event discriminators. Generic arguments, diagnostic details and provider dependencies retain their typed interfaces. Library-owned data is immutable; callbacks and cancellation/stream state remain explicit resources.

`utils/event-stream.bend` implements buffered delivery, deferred final results, per-iterator request queues and the assistant stream specialization. Each iterator serializes its pending requests; separate iterators compete for the stream queue. Completion delivers its event to one waiter; explicit end wakes remaining waiters, and buffered events drain before termination. Assistant events and final messages are immutable snapshots. The generic stream can also transport caller-supplied resource handles without inspecting them.

All five upstream generic event-stream tests retain their names and assertions. `sh tests/event-stream.sh` also checks iterator serialization, completion/end separation, late result settlement, resource-handle transport and assistant event variants. Async-generator return/throw, recoverable extraction callback failures and complete concurrent producer scheduling remain open. Iterators, deferred tickets and streams currently require explicit disposal after their users retire.

`utils/transcript.bend` contains pure normalization, replay, system-message collapse, tool history/state calculation and transport anchoring. All nine upstream system-message-replay cases have native equivalents; run `sh tests/transcript.sh`. Tool declarations contain immutable schema values, so projection requires no cloning. Equality is structural: dictionary field order is ignored while list order and values matter. Reordering schema fields alone no longer signals a redefinition; this is an approved language adaptation.

`runtime/schema-value.bend` represents schema/argument data using null, boolean, number, text, list and dictionary variants. `utils/schema-json.bend` converts these to the explicit JSON codec domain. Sampling uses typed variants and optional grammar strings. There are no prototypes, reflective properties, callable schema hooks or stringify/parse copies.

`models.bend` and utility modules implement thinking metadata, API matching and pricing calculations. `calculateCost` returns a value without mutating usage. Its binary64 operation order and tier rules are checked against the upstream function, including the original request-wide pricing-tier test. The max-thinking and models-runtime upstream suites remain partial.

Provider option projection preserves inherited fields and callback handles. Header values distinguish absent entries, explicit null and empty strings with typed values. Signals, fetch and telemetry are caller-typed dependencies, not completed transports. `tests/provider_option_types.py` verifies inherited field sets, projection and rejected type combinations.

`utils/validation.bend` implements schema type extraction, matching and primitive/type-union coercion on native data. Supplemental source-derived vectors cover that subset. Optional-null normalization now returns a new native value and uses the schema checker for nullability decisions. Recursive plain-schema coercion is implemented as a separate stage. Full validation integration, schema builders, caching, validation errors and public validation entry points remain pending. No validation suite is marked complete.

See [native Bend decisions](../../docs/native-bend.md) and [upstream coverage](../../tests/UPSTREAM.md). Canonical libraries build without the bootstrap's libcurl/ICU adapters, using the explicit [compiler patches](../../patches/README.md).

`utils/validation-normalize.bend` preserves required/nullable/referenced null fields, removes optional non-nullable null fields and traverses declared properties and array item schemas. `validation.normalizeOptionalNulls` exposes this transformation as a typed result. Unsupported nullability checks report their schema and instance paths. The literal-false optional-null case is explicitly pending a user decision because upstream’s WeakMap cache cannot use a boolean schema as its key; it is not silently normalized or counted as parity. No WeakMap/object emulation is introduced. The normalization stage’s reference guard does not implement reference resolution for final validation.

`validation.coerceWithJsonSchema` applies ordered allOf transformations, checks original union values before trying independent coerced candidates, then applies scalar and nested object/array coercion. Additional properties receive their own schema when configured. Failed candidates leave both the original and later candidates unchanged. Union checks use the native schema loader/evaluator; unsupported constraints return typed errors. Literal-true union arms remain explicitly pending under the same boolean-key cache behavior decision. This stage does not perform final argument validation or replace the full public validation entry points.
