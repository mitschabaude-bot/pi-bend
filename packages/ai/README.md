# pi-ai library port

Reference: pi-mono `46c9de402`, `packages/ai`. This is a partial library port, separate from the bootstrap executable. Provider coverage, authentication, the model registry and complete schema validation remain incomplete.

## Modules

`types.bend` (pi's `types.ts`), `models.bend` (model metadata helpers). Provider side under `api/`: `openai-client` (SDK request side: headers, URL, API errors, status boundary), `openai-sse` (SDK stream dispatch), `openai-responses-shared` (request conversion shared by the Responses providers), `openai-responses-stream` (response-side processing), `openai-responses` (the provider lifecycle), `azure-openai-responses` (Azure configuration and request body over that lifecycle), `openai-prompt-cache`, `github-copilot-headers`, `simple-options` (response budgets and base request options), `constrained-sampling` (strict schemas), `transform-messages` (image downgrade, cross-model replay, tool-call id mapping), `transform-tool-results` (synthetic results for unanswered calls), `pi-messages` (pi's own message protocol, as the Radius gateway speaks it), `mistral-conversations` (Mistral Chat Completions over native fetch), `google-vertex` (Vertex AI over the Google client and stream loop shared with `google-generative-ai`) with `google-vertex-credentials` (authorized_user and service-account Application Default Credentials), `bedrock-converse-stream` (Amazon Bedrock ConverseStream: SigV4 or bearer auth, the AWS event-stream response) with `bedrock-credentials` (the AWS SDK default credential chain: environment keys, shared config/credentials profiles with role assumption, web identity, credential_process and SSO, then container and instance-metadata credentials) over `bedrock-credential-services` (the STS, SSO, SSO-OIDC, container and instance-metadata requests), and `provider-fetch` (the fetch Response surface of the providers that call fetch directly). Utilities under `utils/`: `event-stream`, `transcript`, `validation` with `validation-normalize` and `validation-errors`, `tool-declaration`, `schema-json`, `json` and `json-parse`, `estimate`, `cost`, `thinking-levels`, `model-api`, `headers`, `provider-env`, `provider-retry`, `error-body`, `diagnostics`, `hash`, `sanitize-unicode`, `text`.

Built-in providers live under `providers/` (Radius with `radius-config`, its OAuth flow in `auth/oauth/radius` and RFC 8628 polling in `auth/oauth/device-code`): one module per provider with its catalog generated into `<id>.models.bend` by `scripts/generate-model-catalog.py`, and `all` (pi's `builtinProviders`). `models.bend` `ProviderStreams` records how a provider streams: through the model api's implementation, or, for the Cloudflare providers, after `cloudflare-stream` materializes the `{CLOUDFLARE_ACCOUNT_ID}`/`{CLOUDFLARE_GATEWAY_ID}` endpoint placeholders from the resolved provider env; `cloudflare-auth` resolves their key, account and gateway ids (credential values first, then the environment) and the gateway's `cf-aig-authorization` headers. Upstream's `api/cloudflare-ai-binding.ts` (Workers AI binding fetch, not used by the CLI) is not ported.

Image generation (pi's `images*.ts`): `image-models.generated.bend` (the image catalog, generated by `scripts/generate-model-catalog.py --images`) with `image-models.bend` lookups, `images-models.bend` (`ImagesProvider`, `createImagesProvider` and the `ImagesModels` collection with auth resolution, refresh and generation), `images-api-registry.bend` (a registry value), `images.bend` (`generateImages` through the registry), `api/openrouter-images.bend` (OpenRouter image generation over the OpenAI SDK port), `providers/openrouter-images.bend` and `providers/images/register-builtins.bend`; `providers/all.bend` adds `builtinImagesProviders`/`builtinImagesModels`. `tests/openrouter_images_check.py` compares requests and results with upstream against a loopback server.

## History

`src/types.bend` defines content, usage/cost, calls/results, messages, contexts, models, provider options and the twelve assistant event variants. Numeric fields use binary64, optional fields use `Maybe`, and constructors carry the role/event discriminators. Generic arguments, diagnostic details and provider dependencies retain their typed interfaces. Library-owned data is immutable; callbacks and cancellation/stream state remain explicit resources.

`utils/event-stream.bend` implements buffered delivery, deferred final results, per-iterator request queues and the assistant stream specialization. Each iterator serializes its pending requests; separate iterators compete for the stream queue. Completion delivers its event to one waiter; explicit end wakes remaining waiters, and buffered events drain before termination. Assistant events and final messages are immutable snapshots. The generic stream can also transport caller-supplied resource handles without inspecting them.

All five upstream generic event-stream tests retain their names and assertions. `sh tests/event-stream.sh` also checks iterator serialization, completion/end separation, late result settlement, resource-handle transport and assistant event variants. Async-generator return/throw, recoverable extraction callback failures and complete concurrent producer scheduling remain open. Iterators, deferred tickets and streams currently require explicit disposal after their users retire.

`utils/transcript.bend` contains pure normalization, replay, system-message collapse, tool history/state calculation and transport anchoring. All nine upstream system-message-replay cases have native equivalents; run `sh tests/transcript.sh`. Tool declarations contain immutable schema values, so projection requires no cloning. Equality is structural: dictionary field order is ignored while list order and values matter. Reordering schema fields alone no longer signals a redefinition; this is an approved language adaptation.

`runtime/schema-value.bend` represents schema/argument data using null, boolean, number, text, list and dictionary variants. `utils/schema-json.bend` converts these to the explicit JSON codec domain. Sampling uses typed variants and optional grammar strings. There are no prototypes, reflective properties, callable schema hooks or stringify/parse copies.

`models.bend` and utility modules implement thinking metadata, API matching and pricing calculations. `calculateCost` returns a value without mutating usage. Its binary64 operation order and tier rules are checked against the upstream function, including the original request-wide pricing-tier test. The max-thinking and models-runtime upstream suites remain partial.

`utils/provider-retry.bend` is pi's retry policy and loop with strict native option/sleep validation and borrowed effect handles ([design](../../docs/provider-retry.md)); `utils/headers.bend` projects header records and provider overlays; `utils/provider-env.bend` resolves scoped environment values. Provider option projection preserves inherited fields and callback handles. Header values distinguish absent entries, explicit null and empty strings with typed values. Signals, fetch and telemetry are caller-typed dependencies, not completed transports. `tests/provider_option_types.py` verifies inherited field sets, projection and rejected type combinations.

`api/openai-responses.bend` is pi's OpenAI Responses provider: option extension, compatibility/cache policy, credential and header selection, request-parameter assembly, preparation, the retry/acquisition loop, SSE processing, message settlement and the asynchronous run owner (`stream`, `streamAt`, `streamSimple`, `borrow`, `wait`, `dispose`). `api/openai-responses-shared.bend` holds the shared message/tool conversion, text signatures and IDs from `openai-responses-shared.ts`; `api/openai-responses-stream.bend` holds its stream processor (`processResponsesStream`), output-item state, terminal handling and wire decoding. `api/openai-client.bend` replaces the SDK client: request headers and authentication policy, the Responses URL, the request envelope, typed `APIError` construction/formatting and one transport attempt with retry classification. `api/openai-sse.bend` is the SDK's SSE dispatch policy and the affine cursor over an acquired body. The native transport is `packages/runtime/src/fetch.bend`. `Config.security` explicitly supplies `http-exchange.NoTLS` or `WithTLS`; any authorizer factory is borrowed until the provider run and its consumers retire. `tls-trust.newSAN` creates an owned factory from explicit trust anchors and a path-search bound, sampling native wall time for each connection. The provider uses this policy for its own native fetch when no custom fetch is supplied. Input transcripts and output events both carry `schema-value.Value` tool arguments, so an assistant response can be retained for the next turn without rebuilding its argument representation; schema validation remains the agent/tool boundary.

The pricing hooks are pure templates and the processor iterates an affine caller-supplied state, so an unchanged usage means no tier pricing applied and every read, emission and close is a typed state transition. Language-driven adaptations are listed in [the provider document](../../docs/openai-responses.md). `tests/openai_responses_check.py` runs the provider end to end against a scripted loopback server and the pinned upstream wrapper; the differential harnesses under `tests/responses_*` and `tests/openai_sse_*` compare the pure stages with the SDK and pi.

`utils/validation.bend` implements schema type extraction, matching and primitive/type-union coercion on native data. Supplemental source-derived vectors cover that subset. Optional-null normalization now returns a new native value and uses the schema checker for nullability decisions. Recursive plain-schema coercion is implemented as a separate stage. The supported plain-schema path now composes those stages with final checking. Builder conversion, remaining vocabulary, recursive/external references, caching and complete public entry points remain pending. No validation suite is marked complete.

See [native Bend decisions](../../docs/native-bend.md) and [upstream coverage](../../tests/UPSTREAM.md). Canonical libraries build without the bootstrap's libcurl/ICU adapters, using the explicit [compiler patches](../../patches/README.md).

`utils/validation-normalize.bend` preserves required/nullable/referenced null fields, removes optional non-nullable null fields and traverses declared properties and array item schemas. `validation.normalizeOptionalNulls` exposes this transformation as a typed result. Unsupported nullability checks report their schema and instance paths. The literal-false optional-null case is explicitly pending a user decision because upstream’s WeakMap cache cannot use a boolean schema as its key; it is not silently normalized or counted as parity. No WeakMap/object emulation is introduced. The normalization stage’s reference guard does not itself resolve references; final validation now supports acyclic local references through the schema loader.

`validation.coerceWithJsonSchema` applies ordered allOf transformations, checks original union values before trying independent coerced candidates, then applies scalar and nested object/array coercion. Additional properties receive their own schema when configured. Failed candidates leave both the original and later candidates unchanged. Union checks use the native schema loader/evaluator; unsupported constraints return typed errors. Literal-true union arms remain explicitly pending under the same boolean-key cache behavior decision. This stage does not perform final argument validation or replace the full public validation entry points.

`validatePlainToolArguments` and `validatePlainToolCall` compose optional-null normalization, schema compilation, recursive plain-schema coercion and final checking. The latter selects the first matching declaration. `ToolValidationError` distinguishes lookup, schema, normalization, coercion and argument failures; argument failures preserve the original and converted values plus native typed issues. These helpers cover plain JSON declarations, not builder-specific conversion. Six original named plain-schema cases now pass through this path (24 assertions), keeping the upstream validation suite partial. A native preparation/execution fixture supplies this checker explicitly and checks that rejected arguments never reach the tool executor. The default agent uses the strict checking entry point described below. The fixture uses `formatToolValidationError` and verifies the complete native error message. That formatter handles missing-tool and invalid-argument errors; unsupported/internal failures retain their typed categories.

`utils/validation-errors.bend` formats typed instance/required-field locations and issue messages into pi’s validation-failure envelope, using two-space JSON for the original arguments. `json.stringifyPretty` shares the native scalar encoding with compact provider JSON. Fifty-four complete upstream failure messages are compared through native normalization, coercion, checking, issue collection and rendering on one/four threads, alongside isolated renderer tests, 42 paths and 47 indented values. Tool failures retain the pinned dependency’s eight-issue display limit. Numeric-looking dictionary keys retain the approved native insertion order.

Builder primitive conversion is now available in the runtime as an explicit typed policy, separate from plain-schema coercion. Native builder declarations, structured conversion and integration into public tool validation remain unfinished. Structural uniqueness is supported, with the approved rule that positive and negative zero are duplicates.


The wire-event decoding section of `api/openai-responses-stream.bend` maps every event discriminator consumed by the pinned Responses processor to the existing native event sum. It retains unknown-event ignoring, uses JSON `type` rather than the SSE event name, and ignores SDK-synthesized envelopes just as the original processor does. Its immutable name table classifies wire strings before typed dispatch; long literal string patterns currently cause excessive generated C (BEND-016). The expanded boundary test passes 1,146 cases on one/four threads. The processor's 74 actual-upstream comparisons now include large/sparse, fractional, negative and signed-zero provider keys; none allocate storage in proportion to index magnitude. Native HTTPS and provider integration are described below; broader protocol and provider coverage remain partial.

`tests/native-openai.bend` is an integration runner over this provider, with an explicit trust-bundle path, model, base URL and prompt. It reads `OPENAI_API_KEY` from the environment and prints only assistant text or fixed error categories. Its model metadata is a smoke fixture, not registry/pricing parity. `python3 tests/native_openai_check.py bun` checks authenticated HTTPS, the serialized request, SSE output and transport retirement against a local test server; `native-1` and `native-4` select native builds, with `--prefix` selecting the artifact. A native request to OpenAI returned the expected assistant text in 13.84 seconds (10.57 seconds user CPU). The modular two-turn agent/tool integration passes against a scripted HTTPS peer on Bun and native one/four threads. A real native `gpt-4.1-mini` run also called `echo` exactly once and returned its result in the final answer through `Loop.agentLoop`; the fast-arithmetic native build took 5.22 seconds (0.64 seconds user CPU), compared with 27.94 seconds (22.70 seconds user CPU) for the earlier build. Authenticated local HTTPS success and validation-rejection scenarios also pass with the fast build on one and four threads. This confirms provider/tool-loop integration, not coding-tool or completed CLI parity. Fast arithmetic meets the saved-chain median target at 7.790 ms versus OpenSSL 0.806 ms (9.67×); this is a benchmark of that chain, not a worst-case or all-algorithms guarantee.

`checkPlainToolArguments` is the strict execution boundary used by the default native agent validator. It retains optional-null normalization and typed schema/errors but does not call the explicit coercion stage. Thus a schema mismatch is rejected even when conversion could produce a matching value. `validatePlainToolArguments` remains the explicitly callable upstream-compatible coercing pipeline described above. The distinction is an intentional execution-policy adaptation, not a claim that upstream already rejects coercible values.
