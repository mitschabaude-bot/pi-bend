# pi-ai library port

Reference: `packages/ai` in pi-mono revision `46c9de402`. This is a partial library port. It is not wired into the bootstrap executable.

`src/types.bend` contains the field sets for content, usage/cost, tool calls, user/assistant/tool-result messages, deferred handles, image inputs/outputs, text signatures, tool declarations, system messages, raw/normalized contexts, models and compatibility/routing metadata, and all twelve assistant-message event variants. Numeric fields use binary64; optional fields use `Maybe`, preserving false and zero independently of absence. Literal role/type/version discriminators are supplied by constructors; codecs must emit the original upstream tags. The open `Api` and provider identifier types remain string aliases so custom providers are allowed. Known-literal catalogs and codecs remain pending.

Opaque arguments and diagnostic details use explicit type parameters, and `ToolResultMessage` retains its details parameter. This lets callers retain typed records and live handles rather than narrowing `any`/`unknown` fields to JSON. A common heterogeneous dynamic-value representation and enforcement of the upstream record/schema relationships are still required for full public API integration. Only fields explicitly declared `JsonValue` upstream use the recursive `JsonValue` type. Its object fields use the pure-Bend own-property `Record`, including JavaScript array-index enumeration order. `utils/json.bend` now serializes this explicit JSON domain; dynamic schema values remain a separate gap.

Assistant messages and their text/thinking/tool-call content objects use shared `Ref` handles when exposed through events. An event's `partial`, a terminal event's message, the final stream result and retained content handles therefore refer to live objects. `StreamDone` and `StreamError` avoid constructor collisions with Bend's base types; their wire tags remain `done` and `error`. Separate `DoneReason` and `ErrorReason` types preserve the upstream restricted stop-reason unions. `src/utils/diagnostics.bend` contains diagnostic records; its `diagnosticType` field maps to upstream `type`, a Bend keyword. Thrown-value extraction, formatting and append helpers remain pending.

Schema constraints, complete provider-option runtime contracts, provider implementations and library entry points remain unported. Model data fields and API-dependent compatibility are implemented; model registry and behavior integration remain open. Tool-declaration comparison/serialization now supports finite schema-data trees; full schema-object integration remains open. These declarations are not evidence of completed providers or core-type integration. `calculateCost` now has shared mutation/return identity and pricing tests; provider integration remains open.

## Event streams

`src/utils/event-stream.bend` ports the generic `EventStream<T, R>` state, FIFO buffers, injectable completion/extraction callbacks, final-result settlement and iterator request queues. `create` is the constructor equivalent, and `iterator` is the `Symbol.asyncIterator` equivalent. Type arguments are explicit; optional `end` results use `Maybe`. `Iteration.Yield`/`End` encode the iterator result's `done` discriminator without confusing an absent payload with termination. `next` returns a `Deferred` without waiting for an event, and `result` returns the stream's existing final-result `Deferred`. `nextValue` and `resultValue` are convenience equivalents of awaiting those results. Callback values are reusable typed runtime handles, not fixed provider logic.

Each iterator serializes its own pending `next` calls, while separate iterators compete for the shared stream queue. An idle iterator registers its first request before `next` returns. Drivers stop when their request queue is empty. Completion pushes retain the upstream distinction between settling the final result and ending all waiting consumers: the completing event goes to one waiter, and `end` wakes the remaining waiters. Buffered values drain before termination. Shared-reference payloads retain live identity.

All five cases from upstream `test/event-stream.test.ts` are ported, with four supplementary native cases for request serialization, completion/end separation, deferred explicit results, and shared payload identity. Run `sh tests/event-stream.sh`; it builds without foreign adapters and executes on one and four runtime threads.

The module remains partial despite this test coverage. Async-generator `return`/`throw`, recoverable callback exceptions, and equivalence to JavaScript microtask scheduling under reentrant/concurrent operations remain open. Callbacks currently accept IO; callers must sequence producer operations, and general concurrent `push`/`end` calls are not claimed to behave like JavaScript's synchronous methods. Iterator/result `Data` handles require explicit lifetime management until Bend supports automatic shared-object reclamation. Dispose returned `next` promises after observation; the stream owns the promise returned by `result`. Dispose iterators after requests finish, then the stream; callback handles remain owned by their creator. This library has not replaced the prototype's provider stream.

`AssistantMessageEventStream(Arguments, DiagnosticDetails)` specializes the generic stream with the canonical assistant event/message types; the upstream subclass adds only fixed completion/extraction callbacks, so the Bend representation is a type alias. `createAssistantMessageEventStream` constructs those callbacks, and `disposeAssistantMessageEventStream` also releases the callbacks it owns. Native tests cover every event variant, success/error result extraction, setup failure before start, ignored late pushes, and live message/content/tool-argument identity. They supplement the generic upstream suite and do not establish provider protocol conformance. The unexpected-extraction branch currently terminates through `IO.die`; recoverable exceptions remain part of the runtime gap.

## Transcript input and prompt rendering

`Tool<Parameters>` retains schema values with their caller-supplied type. `GrammarVariants`, grammar/JSON-schema sampling configurations and the absent/explicit-false/configured tool option remain distinct. The schema type constraint and validation machinery are not implemented yet; accepting a typed value alone does not establish TypeBox parity.

`SystemMessage` preserves content, sections, added/removed tools and timestamp. Tool and message objects use shared references, while collections currently use persistent values. `Message` retains its four upstream role variants. `Context` and nominally distinct `TranscriptContext` preserve the raw-versus-normalized provider boundary. Full mutable array/object alias behavior and the structural replay interface that accepts custom agent roles still need integration.

`utils/transcript.bend` implements `createInitialSystemMessage`, `normalizeContext`, `getInitialSystemMessage` and `withoutInitialSystemMessage`. Absent/empty shorthand inputs leave the list unchanged; a prompt or nonempty tool set adds a new system message with timestamp zero and retains the original message/tool references. Normalization does not merge or replay existing system messages. The newly allocated system handle currently needs explicit owner disposal; existing message/tool handles remain borrowed.

`utils/text.bend` implements content text extraction, complete prompt rendering and framed updates. Non-text blocks are filtered before joining; empty text blocks still contribute separators. Empty complete-prompt parts are omitted, but empty update values retain their framing. Sections use runtime `Record` enumeration, including numeric keys. The mixed-content input union preserves all four upstream content kinds; callers read shared content records before passing values. Default separator arguments have explicit convenience functions because Bend has no optional call arguments.

All nine upstream system-message-replay cases pass; the broader transcript/schema contracts remain partial. `sh tests/transcript.sh` runs those cases and supplemental text/tool-history tests. `python3 tests/record_vectors.py` compares both own-property records and insertion-ordered maps against JavaScript. Declaration comparison/serialization has a schema-data implementation described below; the full schema-type and dynamic-object adapters are still required.

Replay now includes `getCurrentTools`, `getDeclaredTools`, `getCurrentSystemMessage`, `getCurrentSystemPrompt`, `collapseSystemMessages` and `resolveTranscript`. It appends nonempty content, applies section replacements/removals, preserves the first system timestamp (including zero), and applies removals before additions. Tool maps preserve first insertion positions for replacements and move a removed/re-added key to the end, even for numeric names. Declared-tool history ignores removals and retains the latest definition at its first-declaration position.

`hasNonAdditiveToolChanges` detects removals or any repeated declaration name, including identical definitions. `resolveTranscriptTools` anchors additions only when the transport supports them and the history is additive; otherwise it returns the current tool set. No leading system message means an anchored request starts with no top-level tools. This is independent of `hasToolRedefinitions`, which compares same-name declarations through canonical JSON.

`getCurrentSystemMessage` and collapse produce a fresh system handle; callers currently own its explicit disposal. `getCurrentSystemPrompt` disposes its temporary internally. Original message/tool handles remain borrowed. General concurrent mutation/scheduler equivalence and custom-role structural replay inputs remain open.

## Canonical JSON values

`utils/json.bend` serializes the explicit upstream `JsonValue` union using the canonical binary64 formatter and property-ordering runtime. It retains array order and null/boolean distinctions, quotes strings and property names with JavaScript-compatible UTF-16 semantics, and emits compact JSON. The result is `Maybe<String>` so an internal numeric conversion failure cannot silently become a different value. An explicit work stack handles nested arrays/objects without a fixed depth limit. Its single `@unsafe` annotation records a checker limitation: expansion terminates on the finite acyclic JSON tree, but the structural checker cannot track that measure through a work stack.

`sh tests/json.sh` compares 892 string cases and 114 structured values with JavaScript, then checks 2,000 nested arrays and alternate UTF-16 representations of dictionary keys. This is serialization for `JsonValue`, not a port of the complete JavaScript `JSON` object. Decimal parsing, arbitrary dynamic values, undefined/function/symbol omission, cyclic-reference errors, schema metadata projection, replacers and indentation are not implemented by this module. Typed messages and tools still need their explicit wire codecs; this does not turn them into generic JSON.

`GrammarVariants` now stores ordered, unique format properties instead of a fixed two-field record. `utils/grammar-variants.bend` supplies enum-keyed set/get/remove operations; replacement keeps position, deletion/reinsertion moves a key, and own undefined remains distinct from absence. Direct constructors must preserve the uniqueness invariant. `ConstrainedSamplingConfig` adds explicit `SamplingPropertyOrder` metadata for the two required fields in each branch, preserving either insertion order. `utils/constrained-sampling-json.bend` serializes these typed configurations without reordering them. These are representation adaptations for upstream JSON-based declaration equality.

`python3 tests/constrained_sampling_vectors.py` checks 115 configurations and mutation histories against JavaScript, including both configuration/grammar orders, empty and undefined grammar values, replacement, deletion/reinsertion and escaped Unicode strings. This covers the declared configuration variants; arbitrary extra runtime properties and mutable aliasing still require the extension-object layer. Tool-declaration comparison and TypeBox integration remain incomplete.

`utils/schema-json.bend` converts a runtime schema-data snapshot into canonical `JsonValue`, retaining property order and distinguishing omitted roots, BigInt failures and unsupported hooks from JSON null. It reuses the existing JSON codec for numeric spelling and string escaping. A malformed internal snapshot reports `InvalidSnapshot`; it is not converted to an empty object. This is the serialization boundary for schema data, not a replacement for typed tool or message APIs.

`python3 tests/schema_value_vectors.py` now verifies both projected trees and their serialized output on 156 cases, including twelve fixtures produced by the actual TypeBox 1.3.27 builders. The test-only fixture loader downloads the pinned archive on first use and verifies its SHA-512 against pi-mono’s lockfile value before executing its JavaScript. Fixtures cover hidden/enumerable kind metadata, optional fields, nested schemas, numeric property names and overriding options. Native checks also cover 2,000-level nesting and explicit unsupported hooks. TypeBox builders, validators, static schema relationships, live-object behavior and full typed-tool integration remain pending in the Bend implementation.

`transcript.toToolDeclaration` and `transcript.declarationsEqual` now delegate to `utils/tool-declaration.bend` for tools carrying `schema-value.Value<Metadata>`. They preserve the upstream name/description/parameters/sampling output order, project schema data, retain the sampling configuration, and compare exact canonical JSON. They return `DeclarationResult<A>` instead of throwing: an omitted root and a visited BigInt have distinct errors; unsupported hooks and internal codec failures are also explicit. The left declaration is processed before the right, preserving error precedence.

`python3 tests/tool_declaration_vectors.py` checks 53 tool pairs against the actual pinned pi-mono TypeScript functions, including serialized declarations, configuration ordering, metadata omission, signed zero/non-finite numbers and errors. This is supplemental coverage: all nine upstream replay-suite cases now have separate native ports. The declaration entry points currently accept the schema-data representation; TypeBox static relationships, general extension-object projection, live objects, mutable configuration identity and full schema-aware replay integration remain open.

`transcript.getToolStateChanges` now returns typed `ToolStateChanges` for schema-data tools, preserving last-definition name lookup, duplicate entries and original list order. It completes the addition filter before projecting selected declarations, then computes removals, retaining upstream error precedence. The original changed-definition and identical-state assertions are included in the replay suite. `python3 tests/tool_state_vectors.py` adds 79 comparisons against upstream, covering duplicate names, numeric names, removals with unused invalid schemas and competing errors. Mutable tool-list/reference adapters and extended schema types remain pending.

`hasToolRedefinitions` now scans schema-data message histories through shared tool references. It ignores removals, keeps each latest reference, compares repeated names even when they point to the same object, and stops at the first changed definition or error. First declarations are not serialized. `python3 tests/tool_history_vectors.py` compares 61 histories against both upstream history predicates on one and four threads, including repeated invalid schemas, ignored non-system entries, removals/reintroductions and short-circuit behavior. The original combined history/redefinition case is part of the replay suite, whose fixtures now use the verified schema-data shape throughout. Custom-role structural inputs, general extension objects, live schema-object semantics and full schema relationships remain open.

The final replay case uses `agent.AgentTool` and its explicit `toTool` base projection, which replaces TypeScript’s implicit structural upcast. It preserves all original declaration-equality assertions and additionally verifies that preparation/execution callbacks are not invoked. This completes the named replay test suite, not the transcript module’s dynamic-object/schema contracts. Cross-package imports currently require the checked-in [Bend loader patch](../../patches/README.md).

`Model<SamplingValue>` and `ImagesModel<SamplingValue>` retain the upstream fields, including typed routing options, nullable thinking mappings, fallback pricing, sampling data and headers. `Model.api` uses a `ModelApi` discriminator; its `compat` field is dependent on that value. Responses APIs share `OpenAIResponsesCompat`, other supported families use their own exact records, and APIs with no compatibility contract use `Empty` so only an omitted compat is constructible. `utils/model-api.bend` maps all known and custom API identifiers to/from this representation. Provider identifier strings remain open.

`python3 tests/model_types.py` checks field names/optionality for eleven upstream interfaces, exercises all ten known APIs plus a custom API, and confirms the compiler rejects three incompatible API/configuration combinations. These are contract checks, not provider/model-registry parity tests. Thinking-map mutation helpers, model codecs/catalog loading, provider specialization and complete live-object integration still need implementation; leaf model utilities are described below. Ordered thinking-map properties must be unique; undefined, null and mapped strings remain distinct. Unknown sampling values keep their caller-supplied data type until dynamic-value integration.

`src/models.bend` now implements `getSupportedThinkingLevels`, `clampThinkingLevel`, the runtime `hasApi` predicate and `modelsAreEqual`. Disabled mappings differ from absent/undefined values, xhigh/max are opt-in, clamping prefers the next higher supported level before falling back, and a non-reasoning model exposes only off. Model equality compares only id/provider and rejects both null and missing models, using UTF-16 string equality. `hasApi` currently returns a boolean; a compile-time narrowing witness for provider specialization is still pending.

`python3 tests/model_metadata_vectors.py` executes the original leaf-function tail of pinned `models.ts` after type erasure, without loading unrelated provider dependencies. It checks 212 thinking configurations across all seven requested levels, 64 model identity pairs and 30 API predicates, including Unicode representation equivalence. Two original standalone `max-thinking.test.ts` cases have native ports; catalog-backed and provider-payload cases in that suite remain pending. No model-registry, cost or provider behavior is supplied by the test oracle.

`Usage.cost` is now `Ref<UsageCost>` so `models.calculateCost` mutates and returns the original cost object. The function accepts the complete model and usage records, selects the highest strictly exceeded threshold (first matching tier wins ties), and preserves binary64 operation order and the one-hour cache-write formula. It returns an IO action because shared-state access is explicit in Bend. Reading the reference produces a value snapshot; retaining the handle observes subsequent mutations. Owners currently dispose the nested cost reference after aliases retire, matching the runtime’s explicit lifetime policy.

`python3 tests/model_cost_vectors.py` compares all five charges with the original upstream function on 159 cases, including thresholds, unsorted/duplicate tiers, long writes, negative/non-finite values and extreme binary64 inputs. Each case checks mutation through the original handle and writes through the returned handle to verify shared identity, on one and four threads. The original request-wide pricing-tier case from `models-runtime.test.ts` is ported separately; the rest of that suite remains pending. Assistant-stream and transcript fixtures allocate and retire nested cost handles explicitly.

Canonical request declarations now include `ProviderRequestOptions`, `StreamOptions` and `SimpleStreamOptions`, retaining every inherited field and optionality from the pinned source. Explicit projections preserve the TypeScript structural upcasts without adding defaults or invoking callbacks. Cache/transport/tool-choice/deferred variants remain closed unions; simple-request reasoning excludes off, while an explicit false deferred option differs from absence. Deferred windows are nested in the configuration variant.

Provider environment/header maps and metadata/sampling maps retain shared handles. Null headers use `Nullable<String>` and remain distinct from empty strings or omitted keys. `ProviderResponse` preserves binary64 status and shared response headers. Payload/response callbacks use typed argument records and recoverable results; payload replacement distinguishes omitted return from a supplied value, including null when represented by the payload type. Fetch, telemetry and signal fields remain explicit caller-typed dependencies, not completed HTTP/telemetry runtime interfaces. Generic payload data is not narrowed to JSON.

`python3 tests/provider_option_types.py` compares three inherited field sets plus the response record directly with upstream and runs native one/four-thread checks for shared callback/header projection, callback non-invocation and null/empty/missing header distinctions. Negative compilation checks keep off out of provider reasoning and prevent a bare deferred window from replacing a deferred request. Provider invocation, option merging/defaults, dynamic extra properties, exact callback scheduling and HTTP transport remain unfinished; these declarations do not complete a provider or upstream behavior suite.

`Context.messages` and `TranscriptContext.messages` now hold shared message-array cells. Normalization without a nonempty legacy prompt/tool list retains that exact array; adding an initial system message allocates a new array while retaining existing message objects. `collapseSystemMessages` always allocates its filtered array, including empty/no-system inputs, and `resolveTranscript` with supported mid-conversation system messages retains the supplied array. Callers own newly allocated arrays and generated system-message objects; borrowed arrays and elements retain their original owners. Dense-list cells still do not implement sparse arrays or arbitrary array properties, and the legacy `tools` field remains a value list.

The original replay suite keeps its field/order assertions through explicit test-only snapshot adapters that invoke production functions and release their array cells. `transcript-array-identity.bend` additionally exercises nine prompt/tool combinations directly against production, checking shared-array mutation, copied-array independence, shared message mutation and collapse/resolve allocation. `tests/transcript.sh` runs both sets on one and four threads.

`AssistantMessage.content` now retains a shared array cell, in addition to its already shared text/thinking/tool-call objects. This lets shallow message copies observe later content additions or removals while a replacement of the original message's `content` field stays local to that message. Creators own content-array cells separately from messages and content objects. Existing assistant-stream and replay assertions now use this representation; complete sparse-array APIs and shared identities for other value-backed nested fields remain unfinished.

`AssistantMessage.usage` now holds a shared usage-record cell; `diagnostics` retains optional array identity and shared diagnostic entries. Mutations remain observable through retained message snapshots, while replacing those message fields leaves older snapshots unchanged. Ownership is separate for message, usage, cost, diagnostics array and entries. This does not yet migrate optional usage fields on tool/image results or all nested diagnostic/deferred records.
