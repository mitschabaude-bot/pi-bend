# pi-ai library port

Reference: `packages/ai` in pi-mono revision `46c9de402`. This is a partial library port. It is not wired into the bootstrap executable.

`src/types.bend` currently contains the complete field sets for `TextContent`, `ThinkingContent`, `ImageContent`, `Usage`, `ModelCostRates`, `ModelCostTier` and `ModelCost`, plus all `StopReason` variants. Their source names and field names are preserved. `UsageCost` names the anonymous upstream `Usage.cost` record. Content constructors encode the literal type discriminator; serializers must emit the original string tags. Optional fields use `Maybe` so an absent breakdown remains distinct from a reported zero, and absent redaction remains distinct from false. Numeric fields use the pure-Bend binary64 type.

The remainder of `types.ts`, schema-dependent generic relationships, the full model interface, messages, stream protocols, providers and library entry points remain unported. No provider implementation or core-type completion is implied by these initial records. In particular, `calculateCost` still needs its original model input, mutation/return semantics and upstream tests; an alternate helper taking only rates would not complete that API.

## Event streams

`src/utils/event-stream.bend` ports the generic `EventStream<T, R>` state, FIFO buffers, injectable completion/extraction callbacks, final-result settlement and iterator request queues. `create` is the constructor equivalent, and `iterator` is the `Symbol.asyncIterator` equivalent. Type arguments are explicit; optional `end` results use `Maybe`. `Iteration.Yield`/`End` encode the iterator result's `done` discriminator without confusing an absent payload with termination. `next` returns a `Deferred` without waiting for an event, and `result` returns the stream's existing final-result `Deferred`. `nextValue` and `resultValue` are convenience equivalents of awaiting those results. Callback values are reusable typed runtime handles, not fixed provider logic.

Each iterator serializes its own pending `next` calls, while separate iterators compete for the shared stream queue. An idle iterator registers its first request before `next` returns. Drivers stop when their request queue is empty. Completion pushes retain the upstream distinction between settling the final result and ending all waiting consumers: the completing event goes to one waiter, and `end` wakes the remaining waiters. Buffered values drain before termination. Shared-reference payloads retain live identity.

All five cases from upstream `test/event-stream.test.ts` are ported, with four supplementary native cases for request serialization, completion/end separation, deferred explicit results, and shared payload identity. Run `sh tests/event-stream.sh`; it builds without foreign adapters and executes on one and four runtime threads.

The module remains partial despite this test coverage. `AssistantMessageEventStream` and its factory await the complete assistant-message/event types. Async-generator `return`/`throw`, recoverable callback exceptions, and equivalence to JavaScript microtask scheduling under reentrant/concurrent operations remain open. Callbacks currently accept IO; callers must sequence producer operations, and general concurrent `push`/`end` calls are not claimed to behave like JavaScript's synchronous methods. Iterator/result `Data` handles require explicit lifetime management until Bend supports automatic shared-object reclamation. Dispose returned `next` promises after observation; the stream owns the promise returned by `result`. Dispose iterators after requests finish, then the stream; callback handles remain owned by their creator. This library has not replaced the prototype's provider stream.
