# Native schema evaluation

`src/schema.bend` evaluates immutable `Schema` values against immutable `schema-value.Value` inputs. This supplies the checking dependency needed by pi's union coercion and optional-null normalization. The companion loader compiles a supported subset of JSON-schema values. This is not yet a complete TypeBox replacement.

`JsonKind` enforces a JSON type, including finite number/integer checks. `TypeUnion` preserves an ordered array of allowed types as one constraint, so a mismatch yields one aggregate type diagnostic instead of child-schema/anyOf failures. `Constant` and `Enumeration` use structural equality: dictionary field order is irrelevant and list order matters. `All`, `Any`, `One` and `Not` compose schemas. `Object` checks declared properties, required keys and each additional property. `Array` checks a prefix of position-specific schemas and applies its item schema to the remainder. Object/array constraints apply only to matching instance kinds; combine them with `JsonKind` when the instance type must also be enforced. Use `Accept` for unrestricted additional properties/items and `Reject` to disallow them.

`Minimum` and `Maximum` carry a numeric limit and an inclusive/exclusive flag. `ItemCount` and `PropertyCount` use `CountBounds` with a compact arbitrary-precision nonnegative minimum and optional maximum. Counts and limits use the existing pure-Bend `BigNat`, so large declared limits do not overflow or allocate unary successor chains. `Contains` counts matching item schemas and applies its explicit bounds; the ordinary JSON-schema default is minimum one with no maximum. These keyword constraints leave instances of unrelated types alone, matching JSON Schema applicability rules. Contradictory bounds reject applicable instances.

The evaluator uses explicit immutable child tests, with no generated source, callback resources or object mutation. Ordinary dictionaries supply property lookup; names such as `__proto__` and `constructor` have no special behavior. Required fields distinguish an absent key from an explicit null value.

Still pending: the remaining JSON-schema loader vocabulary, multipleOf, string-length and pattern/format handling, recursive/external/anchored references, conditional/dependent schemas, remaining vocabulary and diagnostics for those extensions. String limits need the pinned TypeBox grapheme-counting behavior, not code-point or byte length. The loader reports unsupported keywords explicitly instead of dropping constraints.

Run `python3 tests/schema_check.py` for TypeBox comparisons and native-specific checks. This supplements the partially ported upstream validation suite.

`UniqueItems` uses native structural equality, including numeric equality for `0` and `-0`. The user explicitly approved treating `[0, -0]` as non-unique, including nested occurrences. This differs from TypeBox 1.3.27’s bit-sensitive hashing and is recorded as an adaptation rather than a parity pass. Lists remain ordered values; dictionaries compare by fields independently of insertion order. Non-array values are unaffected by the keyword. The loader accepts only a boolean `uniqueItems` flag.

`src/schema-load.bend` exposes `compile(schema-value.Value) -> Result<Error, Schema>`. It loads boolean schemas, primitive/type-array declarations, const/enum, allOf/anyOf/oneOf/not, properties/required/additionalProperties, items/additionalItems, numeric bounds, collection counts and contains/minContains/maxContains. Common annotation fields are accepted as annotations. Each error carries ordered schema-path segments and either an unsupported keyword or an expected input shape. Unknown constraints fail even inside an alternative that would otherwise accept the instance. Cross-keyword rules consult the whole declaration, so field order does not affect their meaning. Count bounds must be nonnegative finite integers. Binary64 declarations convert exactly to compact integers, including limits above the machine-word range. Acyclic local root/pointer references and `$defs`/`definitions` containers are supported; recursive references, anchors, resource IDs, external references, dialect selection and other vocabulary remain pending.

`python3 tests/schema_check.py --loaded` runs the native loader through the applicable TypeBox fixtures, verifies unsupported-keyword rejections for the rest, and checks malformed/nested schema paths and immutable dictionary behavior. The default command runs typed, loaded and diagnostic modes.

`src/schema-errors.bend` exposes `errors(Schema, Value) -> List<Issue>`. Each issue retains ordered instance-path segments and a typed reason, including missing/additional fields, numeric bounds, exact collection/match counts and union ambiguity. Successful unions suppress unsuccessful branch diagnostics; a union with no successful branch retains child issues before its parent issue. Negation and contains do not leak internal check failures. Collection is immutable and covers the complete current executable schema vocabulary. `python3 tests/schema_check.py --diagnostics` checks issue presence against all 3,150 TypeBox acceptance results on one/four threads, plus native content/path/order fixtures. The loader preserves type arrays versus anyOf, diagnostic keyword order and native declared-property order. The loader retains separate contains/minContains/maxContains constraints so each failed keyword produces its own issue. `AdditionalItems` retains the tuple offset and stops diagnostic traversal at the first invalid extra item, while ordinary array items collect all failures. Native tool validation now collects these issues and the AI library renders them; diagnostics for unimplemented schema vocabulary remain pending.

The loader orders constraint checks by pi’s diagnostic keyword order, independent of input schema field order. It preserves the declaration order within `properties`, including numeric-looking names; JavaScript key enumeration is deliberately excluded. This ordering affects diagnostic presentation only, not schema validity.

`errorsLimited(Schema, Value, Nat)` stops collection at an explicit issue budget; `errors` remains uncapped. Pi’s tool-validation boundary requests eight issues to match the pinned dependency’s default. The AI formatter also caps its rendered issues, independent of runtime collection policy.

`json-pointer.bend` reads immutable dictionaries and lists using decoded path segments; `uri-component.bend` supplies strict percent/UTF-8 decoding for local fragments. Empty names, tilde/slash escapes, percent-encoded Unicode and canonical array indices are preserved. Numeric-looking dictionary fields remain ordinary keys and arrays expose only their elements. Array lookup walks the existing list rather than allocating a unary integer from an arbitrary index string.

The loader resolves acyclic local references against its original root while compiling, without rewriting declarations used by normalization/coercion. References can chain and include sibling constraints. Unresolved local pointers compile to rejection, matching the pinned checker. Active canonical pointer paths detect cycles, including differently percent-encoded spellings; these return `UnsupportedReferenceCycle` until recursive graph evaluation is implemented. Named anchors, malformed/unsupported fragments and external references return `UnsupportedReference`; `$id` remains unsupported, so resource scopes are not silently flattened. Unreferenced definitions are inert; referenced targets are checked by the regular loader.

`schema-convert.bend` implements typed builder primitive conversion separately from plain-JSON coercion: booleans accept case-insensitive words and `0`/`1` strings, numbers accept numeric/boolean text and safe decimal bigint-literal strings, integers truncate toward zero, strings render null as `"null"`, and null conversion accepts its builder-specific spellings. `f64.truncate` preserves signed zero and special-value bits. All 1,067 comparisons against TypeBox builder conversion pass on one/four threads, including exact binary64 results. Native declaration builders, container/union conversion and public builder validation are still pending. Object conversion’s literal-field/additional-property behavior awaits the user’s decision about the observed TypeBox bugs.
