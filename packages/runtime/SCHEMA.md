# Native schema evaluation

`src/schema.bend` evaluates immutable `Schema` values against immutable `schema-value.Value` inputs. This supplies the checking dependency needed by pi's union coercion and optional-null normalization. The companion loader compiles a supported subset of JSON-schema values. This is not yet a complete TypeBox replacement.

`JsonKind` enforces a JSON type, including finite number/integer checks. `Constant` and `Enumeration` use structural equality: dictionary field order is irrelevant and list order matters. `All`, `Any`, `One` and `Not` compose schemas. `Object` checks declared properties, required keys and each additional property. `Array` checks a prefix of position-specific schemas and applies its item schema to the remainder. Object/array constraints apply only to matching instance kinds; combine them with `JsonKind` when the instance type must also be enforced. Use `Accept` for unrestricted additional properties/items and `Reject` to disallow them.

`Minimum` and `Maximum` carry a numeric limit and an inclusive/exclusive flag. `ItemCount` and `PropertyCount` use `CountBounds` with a compact arbitrary-precision nonnegative minimum and optional maximum. Counts and limits use the existing pure-Bend `BigNat`, so large declared limits do not overflow or allocate unary successor chains. `Contains` counts matching item schemas and applies its explicit bounds; the ordinary JSON-schema default is minimum one with no maximum. These keyword constraints leave instances of unrelated types alone, matching JSON Schema applicability rules. Contradictory bounds reject applicable instances.

The evaluator uses explicit immutable child tests, with no generated source, callback resources or object mutation. Ordinary dictionaries supply property lookup; names such as `__proto__` and `constructor` have no special behavior. Required fields distinguish an absent key from an explicit null value.

Still pending: the remaining JSON-schema loader vocabulary, uniqueItems, multipleOf, string-length and pattern/format handling, references and recursion, conditional/dependent schemas, remaining vocabulary, source-keyword diagnostic metadata and diagnostic integration with tool validation. String limits need the pinned TypeBox grapheme-counting behavior, not code-point or byte length. The loader reports unsupported keywords explicitly instead of dropping constraints.

Run `python3 tests/schema_check.py` for TypeBox comparisons and native-specific checks. This supplements the still-pending upstream validation suite.

A uniqueness decision is pending: TypeBox 1.3.27 accepts `[0, -0]` under `uniqueItems` because its hashing distinguishes their bit patterns; native numeric equality regards them as duplicates. No uniqueness node is enabled until that behavior is resolved with the user.

`src/schema-load.bend` exposes `compile(schema-value.Value) -> Result<Error, Schema>`. It loads boolean schemas, primitive/type-array declarations, const/enum, allOf/anyOf/oneOf/not, properties/required/additionalProperties, items/additionalItems, numeric bounds, collection counts and contains/minContains/maxContains. Common annotation fields are accepted as annotations. Each error carries ordered schema-path segments and either an unsupported keyword or an expected input shape. Unknown constraints fail even inside an alternative that would otherwise accept the instance. Cross-keyword rules consult the whole declaration, so field order does not affect their meaning. Count bounds must be nonnegative finite integers. Binary64 declarations convert exactly to compact integers, including limits above the machine-word range. References, dialect selection and the other remaining vocabulary are still pending.

`python3 tests/schema_check.py --loaded` runs the native loader through the applicable TypeBox fixtures, verifies unsupported-keyword rejections for the rest, and checks malformed/nested schema paths and immutable dictionary behavior. The default command runs typed, loaded and diagnostic modes.

`src/schema-errors.bend` exposes `errors(Schema, Value) -> List<Issue>`. Each issue retains ordered instance-path segments and a typed reason, including missing/additional fields, numeric bounds, exact collection/match counts and union ambiguity. Successful unions suppress unsuccessful branch diagnostics; a union with no successful branch retains child issues before its parent issue. Negation and contains do not leak internal check failures. Collection is immutable and covers the complete current executable schema vocabulary. `python3 tests/schema_check.py --diagnostics` checks issue presence against all 3,150 TypeBox acceptance results on one/four threads, plus native content/path/order fixtures. This is not exact TypeBox diagnostic parity: the loader still needs to preserve keyword distinctions (for example type arrays versus anyOf), keyword ordering and separate count bounds before tool-error rendering can use these issues.
