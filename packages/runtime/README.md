# Native runtime foundations

Pure Bend primitives for the canonical libraries. Compiler changes are documented in [patches](../../patches/README.md).

`src/line-decoder.bend` provides immutable `LineDecoder` state with byte/text/optional-chunk decoding and explicit `flush`. It preserves OpenAI SDK 6.40.0's CR, LF, CRLF and deferred-CR emission timing, including UTF-8 replacement and initial-BOM removal independently for each line. Pending bytes are kept in reversed lists and decoded only when a line completes; each arriving chunk avoids copying or rescanning the accumulated buffer. `findDoubleNewlineIndex` returns `Maybe<Nat>` for CRCR, LFLF and CRLFCRLF boundaries. Run `python3 tests/line_decoder_vectors.py`: 11,940 direct SDK comparisons pass on one/four native threads. These dependency checks do not establish provider SSE or HTTP integration.

`src/utf8.bend` implements replacement-mode UTF-8 encoding and decoding over Base's byte-list convention (`List<&2, U32>`, each element in 0..255). Incremental decoding returns immutable decoder state and the text available from that chunk; `finish` emits a replacement for an unfinished sequence and resets state. One initial BOM is removed, while later BOMs survive. Complete-buffer decoding matches the non-streaming `TextDecoder` used by the pinned OpenAI SDK. Encoding combines explicit UTF-16 surrogate pairs and replaces unmatched surrogates. It adds no foreign effects or compiler patches. Run `python3 tests/utf8_vectors.py` for 80,002 comparisons on one/four native threads: complete buffers/encoding against Node and Bun, incremental output against Bun. The test sends inputs to one compiled runner rather than generating a larger program per vector. This codec is a transport foundation; HTTP/TLS and provider wire integration remain pending.

`ref.bend`, `deferred.bend` and `callback.bend` provide explicit synchronized state, first-settlement results and reusable callback resources. Their handle identity is resource identity, not an object model. Ordinary pi records, lists and event payloads do not allocate reference cells.

`abort.bend` uses a deferred typed reason: supplied reasons or a `DefaultAbort` variant. The first abort wins; observations may be removed independently and late observations receive the settled reason. `throwIfAborted` returns a typed result. No DOM event dispatch, event-handler properties or inherited object APIs are involved. Combined/timeout signals and integration with the complete agent remain pending.

`src/clock.bend` reads exact monotonic nanoseconds through the new `IO.monotonicNanoseconds` compiler primitive. The primitive returns high/low U32 words; its native effect reads the existing OS monotonic clock and its JS-backend effect uses `process.hrtime.bigint`. Clock origin handling and numeric conversion are pure Bend. A `Clock` captures one origin, and copies keep it; initialize it once before runtime callbacks start. `elapsed` subtracts unsigned 64-bit ticks before converting the interval to binary64 and dividing by one million, matching the evaluation order in [Node's PerformanceNowImpl](https://github.com/nodejs/node/blob/v24.18.0/src/node_perf.cc#L284). Raw epochs are unspecified, and subtraction follows the counter's modulo-2^64 representation.

`python3 tests/clock_vectors.py` checks 276 exact-bit interval vectors against Node numeric arithmetic, including nanosecond intervals at epochs beyond binary64 integer precision, conversion ties, word carries and counter wrap. Native one/four-thread and Bun-hosted JS-backend tests check monotonic ordering, timer liveness, cross-task epoch consistency and elapsed-time readings. The JS host is Bun because the existing sleep effect uses bun:ffi; Node supplies the independent numeric oracle. They do not compare absolute clock origins across processes or establish real-time scheduling guarantees. The compiler patch is explicit under `patches/`; native clock policy uses no host floating-point or library adapter.

`Deferred.observe` returns an affine `Observation` containing a single-use `Ticket<Maybe<A>>` and a copyable `Cancellation<A>` handle. `cancel` atomically removes the pending waiter; its true result identifies the cancellation winner. Cancellation delivers `None`, whereas settlement delivers `Some(value)`, including `Some(None)` when the actual value is optional. Exactly one side owns delivery, and duplicate or post-settlement cancellation returns false. Arbitrary-precision registration keys prevent stale handles from matching later observations after integer wraparound. The original `subscribe`/`result` API remains available for required observations. Native tests verify removal, neighboring required/removable waiters, late observation, stale handles across a 64-bit counter carry, optional results, 64 simultaneous cancellation attempts with exactly one winner, and 128 settlement races. Cancellation handles must retire before their source is disposed.

`src/callback.bend` provides reusable first-class callback handles despite Bend's affine closures. Construction supplies closed callback code and a typed runtime capture environment; libraries subsequently accept and store the resulting runtime `Callback<Input, Output>` value. Each call obtains a fresh affine closure and releases the factory before invoking user code, allowing concurrent async calls. Inputs and outputs may themselves be affine. The factory uses one explicitly documented guarded `@unsafe` corecursion: construction returns a closure, and each invocation constructs one successor. There is no background actor or artificial invocation limit.

These shared primitives currently require owner-directed disposal after aliases and observers retire. The current Bend channel runtime does not reclaim live channel rows merely because handles are dropped. Automatic resource reclamation remains a language/runtime prerequisite for removing manual disposal. These primitives do not establish completion of pi's event-stream or subscription semantics. The generic stream has separate upstream tests in `packages/ai/test/event-stream.bend`.

`src/u64.bend` implements unsigned fixed-width arithmetic modulo 2^64, bit operations, logical shifts, rotations, comparison, and quotient/remainder division. Values use two U32 limbs, ordered high then low. Division by zero returns `None`; shifts of at least 64 bits produce zero; rotations reduce their count modulo 64. `multiplyWords` exposes the exact 32-by-32-bit product needed by wider arithmetic.

`src/u128.bend` provides exact 64-by-64-bit multiplication and wide intermediates with sticky-bit shifting. It is used to retain the full product before binary64 rounding.

`src/f64.bend` represents every IEEE-754 binary64 bit pattern and implements addition, subtraction, multiplication and division with round-to-nearest, ties-to-even. It retains signed zeros and subnormal results. Arithmetic NaNs become a canonical quiet NaN; payload preservation is not an API guarantee. Comparisons return `None` for unordered NaN operands and treat signed zeros as equal. Unsigned integer conversion rounds directly from the 64-bit integer. Alignment retains guard, round and sticky bits; cancellation and underflow are normalized before the final rounding. Operations never pass through F32. Decimal parsing and remaining numeric operations are still required before full integration with pi's number APIs; base-10 formatting is implemented separately in `f64-decimal.bend`.

Run the independent vector tests from the repository root:

```sh
python3 tests/u64_vectors.py
python3 tests/f64_vectors.py
sh tests/runtime-concurrency.sh
```

Python generates expected results from arbitrary-precision integers and host binary64 arithmetic. It writes constant input/output vectors, then compiles and executes Bend assertions. Python supplies no behavior to the implementation or native executable. The tests currently cover 272 unsigned/wide arithmetic vectors and 1,077 floating-point vectors, each checking all four operations, comparison and integer conversion. These tests supplement, rather than replace, the future port of pi's numeric and model-cost tests.

Concurrency tests check retained reference identity, 1,000 competing updates, affine ownership, result fan-out, ignored duplicate settlements, repeated callback invocation, and overlapping async callback calls. Gates and explicit registrations coordinate the tests; no sleeps are used to guess scheduling order.

`src/fifo.bend` supplies the persistent two-list FIFO used by the event stream and per-iterator request queues. Enqueue/dequeue are amortized constant time along a queue history; transferring incoming values reverses the list only when the outgoing side empties. Stream tests cover buffered and waiting-consumer ordering across transfers.

`src/record.bend` is a persistent string-keyed dictionary with insertion-order traversal. Updating a value preserves its position; removing and re-adding a key appends it. Numeric-looking strings have no special ordering. `tests/record_vectors.py` checks this native contract against an independent insertion-ordered dictionary model.

`src/ordered-map.bend` supplies persistent insertion-ordered tool maps. Numeric-looking keys are ordinary strings; updates preserve position and remove/reinsert appends. Operations currently scan lists.

`src/big-nat.bend` implements exact unsigned arbitrary-precision integers for decimal/binary64 conversion. Values have canonical little-endian 16-bit limbs; zero has no limbs. Addition, comparison, nonnegative subtraction, multiplication, left shift, powers and quotient/remainder division use only Bend U32 arithmetic. Subtraction returns `None` for a negative result; division returns `None` for a zero divisor. `divideSmall` additionally requires a divisor of at most 65535; general division has no such restriction. Decimal integer parsing rejects signs, whitespace, fractions and exponents, accepts leading zeros, and normalizes zero. Decimal output uses an input-size-derived digit bound, not fixed precision. No host arithmetic or string formatting supplies production results.

`python3 tests/big_nat_vectors.py` checks 179 independent Python-integer vectors, plus power/construction/input cases. Coverage includes limb boundaries, carries/borrows, zero divisors, out-of-range small divisors, 2048-bit operands, 2^1074 and 5^1074, and exact decimal round trips. The native executable does not invoke Python.

`src/f64-decimal.bend` implements shortest base-10 binary64 spelling using exact integer rounding intervals. It tests both adjacent decimal candidates at each precision, respects inclusive/exclusive binary midpoints (including the asymmetric lower interval at normal powers of two), and chooses the closest admissible decimal with ties to an even coefficient. It emits ordinary or scientific notation according to [ECMAScript Number::toString](https://tc39.es/ecma262/multipage/ecmascript-data-types-and-values.html#sec-numeric-types-number-tostring). Both signed zeros become `0`; non-finite number strings remain `NaN` and signed `Infinity`.

`toDecimal` returns `Maybe<String>`: an impossible denominator or exhausted format-derived bound remains an explicit failure instead of producing an approximate value. Normalization is bounded by binary64's denominator bit count; digit selection checks up to seventeen significant places. These are format guarantees, not user-input precision caps. `toJsonNumber` additionally maps non-finite values to `null`, matching [JSON numeric serialization](https://tc39.es/ecma262/multipage/structured-data.html#sec-serializejsonproperty).

`python3 tests/f64_decimal_vectors.py` compares 1,092 bit patterns against JavaScript's actual number spelling, with additional JSON numeric checks. Coverage includes signs, dense small subnormals, the subnormal/normal boundary, maximum finite values, powers of two and ten with adjacent bit patterns, ordinary/scientific cutovers, explicit decimal midpoint ties in both directions, and seeded random patterns. JavaScript supplies expected test strings only. This is an exact reference implementation, not a performance-tuned conversion algorithm; whole-provider serialization performance still needs evaluation.

Serialization of the explicit pi-ai `JsonValue` union is implemented separately. The bootstrap JSON encoder's preserved decimal tokens still cannot replace the canonical codec or establish correct tool-declaration comparison.

`src/utf16.bend` canonicalizes string representation by merging valid adjacent surrogate pairs into scalar characters, retaining unpaired units. It does not perform Unicode spelling normalization. Dictionary keys use native string equality. `src/json-string.bend` quotes that representation, escaping controls and unpaired surrogates while preserving ordinary Unicode. The canonical `JsonValue` codec uses these helpers. JavaScript differential tests and native codec tests run through `sh tests/json.sh`; existing record/Map ordering tests remain separate.

`src/schema-value.bend` holds immutable schema/argument data: null, booleans, numbers, text, lists and dictionaries. Equality compares dictionary fields without regard to order and preserves list order. There is no dynamic JavaScript object model, callable schema metadata, property inspection, JSON cloning, or prototype machinery. See `packages/ai/test/native-schema.bend`.


`src/date.bend` implements `Date.now` over exact signed Unix milliseconds from the explicit compiler primitive. It remains separate from `Clock.now`, whose epoch is an elapsed-time origin. Integer words are converted to binary64 entirely in Bend, including pre-epoch negative values; no F32 conversion is involved. This is not the Date constructor, parsing, formatting, timezone or full Date API. `python3 tests/date_vectors.py` checks 146 signed conversion bit patterns and live native/JS-backend readings against host wall-clock call bounds. System-clock adjustments remain observable; the wall clock is not guaranteed to be monotonic.

`F64.isInteger` classifies the stored binary64 value without decimal conversion or F32 rounding. Signed zeros are integers; subnormal fractions, NaNs and infinities are not. For finite values, restoring the significand after removing fractional bits must reproduce it exactly. The validation predicate differential tests cover this operation across exponent boundaries and random bit patterns (`python3 tests/validation_primitives_vectors.py`).

`src/f64-ratio.bend` converts an arbitrary-size unsigned numerator/denominator pair and explicit sign to binary64 with exact round-to-nearest, ties-to-even. A zero denominator returns `None`; zero numerators retain the supplied sign. It searches monotone positive encodings using integer comparisons in units of the smallest subnormal, then compares the exact midpoint of adjacent values. A virtual `2^1024` endpoint supplies the correct overflow midpoint. Sixty-three bisections cover the encoding interval; this is a proof-derived bound, not a precision or input-size cap. Numerator and denominator are never independently rounded or converted to host numbers.

`python3 tests/f64_ratio_vectors.py` checks 226 cases against Python's independent exact-rational conversion on one/four threads. Cases include both signs of zero, zero denominators, ties and close neighbors, subnormal/normal boundaries, odd/even significands, overflow, random large ratios, and 1,000-digit operands whose ratio remains near one. This reference-quality conversion is the rounding dependency for numeric parsing; numeric-string grammar, parsing and validation coercion are not implemented by this module. Throughput optimization remains open.


`python3 tests/number_string_vectors.py` compares 365 inputs against JavaScript's actual `Number` conversion on one/four threads, preserving negative-zero bits and checking NaNs explicitly. Coverage includes all accepted whitespace code points and rejected lookalikes, surrogate inputs, malformed syntax, three radix forms, exact rounding midpoints, subnormal/overflow boundaries, long mantissas and exponents, and seeded decimal cases. Runtime conversion is pure Bend; Node supplies expected test values only. This is a reference-quality parser; integration into schema coercion and provider codecs and performance tuning remain pending.

`src/json-parse.bend` decodes strict JSON directly into immutable `schema-value.Value` arrays/records and native binary64 numbers. It validates numeric grammar before decimal conversion, normalizes surrogate-pair representation, retains lone units, and uses explicit container frames rather than a recursion-depth limit. Duplicate JSON keys replace the previous value; keys remain ordinary native record keys, including `__proto__`. Failures are typed parse errors rather than host-engine exception text. `tests/json_parse_check.py` checks 498 acceptance/value cases against JSON.parse, exact top-level numeric bits (including negative zero and overflow), and a 2,000-level nested container on one/four threads. Partial JSON and repair are not part of this decoder.

`src/sse-chunks.bend` ports the pinned SDK's byte-level SSE framing. It retains bytes until CRCR, LFLF or CRLFCRLF, yields every completed frame in order and yields a remaining nonempty fragment at EOF. `ChunkDecoder` is immutable, with a delimiter-prefix state and reversed byte buffer; it avoids the SDK's repeated buffer copying/rescanning. `python3 tests/sse_chunks_vectors.py` passes 10,297 comparisons on one/four native threads, checking exact bytes and which input read emits each frame. Event-field decoding is provided by `sse-decoder.bend`; provider integration remains pending.

`src/sse-decoder.bend` provides immutable `SSEDecoder` state and `ServerSentEvent` values. It implements the pinned SDK's field and blank-line rules, preserving absent versus empty event names and exact data joins. The approved diagnostic policy clears comment/unknown-field history at each empty block; it does not clear an explicitly empty event name. `python3 tests/sse_decoder_vectors.py` checks 3,306 sequences on one/four native threads against the actual SDK and the isolated diagnostic-only adaptation. This line-to-event layer does not yet compose the complete async wire iterator.

`src/sse-stream.bend` composes byte framing, UTF-8 line decoding and SSE field decoding into immutable `StreamDecoder` transitions. Each decode call returns the events made available by that input chunk, in order. `finish` consumes the state, flushes pending bytes and the final line, and returns only events with an actual blank-line separator; it does not force an incomplete event to emit. `python3 tests/sse_stream_vectors.py` passes 3,819 comparisons against the SDK's full `_iterSSEMessages` iterator on one/four native threads, including exact input-read emission timing. The oracle checks original event names/data/timing and the approved diagnostic-only adaptation separately. Pulling and early-close behavior are provided by `sse-reader.bend`; request cancellation, JSON event decoding and provider integration remain unfinished.

`src/sse-reader.bend` supplies an affine pull cursor over borrowed input callbacks. Each `next` or `close` returns a successor cursor; event buffering and decoder state are ordinary immutable values, not reference cells. Pending events are delivered before another input read. Fresh, active, input-exhausted and closed states distinguish when an early close must call the underlying iterator's return callback. Read failure closes the cursor without calling return; return failure is surfaced once and leaves the successor closed. The owner must retire callback handles after cursor use; the reader does not dispose borrowed callbacks. `python3 tests/sse_reader_check.py` verifies 806 complete next/return traces against the actual SDK generator on one/four native threads, and rejects a cursor-duplication fixture at type checking. This reader models an acquired input iterator; HTTP-body acquisition, request cancellation and the outer JSON/provider stream remain separate unfinished work.

`json-decode.bend` provides typed field/object/list decoding over immutable JSON values. Required fields distinguish absence from wrong types; nullable optional fields use `Maybe`. Failures carry literal field/index path segments, so nested diagnostics require no dotted-key parsing. Decoders compose with Base's `Result` monad and short-circuit on the first failure. Static element decoders support native list traversal without effectful callback handles. The Responses wire test exercises these helpers through nested item, usage and error decoding.

`serial-resource.bend` coordinates asynchronous operations on one affine value. A duplicable handle queues access through a one-slot channel; an affine owner controls retirement. Each operation receives the resource and returns its successor alongside its result, so typed failures also release the next queued operation. This is distinct from `Ref.modify`'s pure atomic update. An operation must not await re-entry on its own handle. Join outstanding operations and retire all handle aliases before retiring the owner; retirement returns the resource for caller-directed cleanup. Native one/four-thread tests cover an awaited operation failing before a queued successor, state preservation, ordering and rejected owner duplication.


## Unicode normalization

`src/unicode-normalization.bend` provides `nfc(tables, text)` and `nfd(tables, text)` for scalar strings. Construct `src/unicode-17-normalization.bend`'s `tables()` once and share the immutable value across calls. Normalization decomposes canonical mappings, handles Hangul algorithmically, stably orders combining segments and performs blocked canonical composition. It does not case-fold or implement IDNA validation.

The generated Unicode 17 data is covered by `src/unicode-LICENSE.txt`. Regenerate with `python3 scripts/generate-unicode-normalization.py`; `--check` verifies reproducibility. The generator verifies pinned hashes of official Unicode inputs cached under `build/unicode-17`; downloaded source files are not production dependencies. `u32-table.bend` stores balanced immutable lookup data with generated height bounds, and `stable-sort.bend` avoids non-tail list traversal for long combining segments.


## IDNA input preparation

`src/idna-mapping.bend` maps scalar strings using Unicode 17 UTS #46 data, in transitional or nontransitional mode. Disallowed code points return a typed error containing the first offending code point. Construct `unicode-17-idna-mapping.table()` once and reuse it. `idna-prepare.bend` composes mapping with NFC through an immutable context containing both tables. This is preparation only: label validity, ACE decoding, contextual/bidirectional rules and URL host restrictions still need to run before using a result as a hostname.

`scripts/generate-idna-mapping.py --check` verifies the generated ranges against pinned official data. The mapping checker compares range boundaries and mixed strings exactly and checks every Unicode code point in both modes through ordered block checksums. The preparation checker exercises mapping plus NFC on the official IDNA test inputs; it does not claim full IDNA conformance. Both run on native one/four threads and Bun through native-cleanup.


`src/idna-bidi.bend` implements the RFC 5893 label rule over `unicode-bidi-class.Class` values, either incrementally or through `analyze`. Its result preserves both rule validity and whether the label contains R/AL/AN. The domain processor must check every label if any label contains those classes; checking only right-to-left labels would be incorrect. Full domain integration remains unfinished.


`src/idna-contextj.bend` validates contextual joiners incrementally. Feed each scalar's code point, `unicode-joining-type.JoiningType` and canonical combining class to `push`, then call `finish` to reject any unresolved right context. Transparent characters preserve joining context but do not preserve immediate virama adjacency. These rules operate on prepared label characters, after any transitional mapping has removed join controls. The property-backed label analyzer described below feeds these transitions.


`src/unicode-17-idna-properties.bend` now supplies an immutable table for Bidi_Class, Joining_Type, canonical combining class and mark classification, including Unicode's script-specific defaults. `idna-label-context.analyze(table, text)` connects property lookup to the contextual rules and leading-mark inspection in one traversal. Its input is a prepared, decoded label; it does not perform mapping, NFC or ACE decoding. Regenerate the pinned data with `python3 scripts/generate-idna-properties.py`.


`src/idna-ace.bend` supplies strict decoding of already-mapped `xn--` labels, returning the decoded text and whether ACE encoding was used. It rejects non-ASCII encodings, malformed Punycode and empty/ASCII-only decoded results. It deliberately preserves decoded characters for later validation; they must not be mapped again. Transitional capital sharp S is handled separately by the mapper as required by UTS #46, rather than relying solely on the data-table replacement.


`src/idna-label-rules.bend` checks prepared-label syntax and mapping status with explicit `checkHyphens`, `useSTD3` and processing-mode options. It returns typed failures and never repairs text. ACE-decoded labels must use nontransitional mode. These checks are one part of validation: NFC, leading marks, ContextJ, domain-wide Bidi applicability and DNS lengths must also be handled before treating text as a valid hostname.


`src/idna-label.bend` composes strict ACE decoding, NFC verification, syntax/status checks and Unicode context analysis. Construct an immutable `Context` from the mapping, normalization and property tables and reuse it across calls. `process` accepts a label after domain-wide mapping/NFC and splitting; decoded ACE text is checked without repair and uses nontransitional status rules automatically. Options explicitly select hyphen, STD3 and joiner checks. Results preserve the decoded text, emptiness and Bidi facts, so the domain processor can apply Bidi requirements to every nonempty label when needed. DNS lengths and full domain orchestration remain separate work.


`src/idna-domain-policy.bend` aggregates label Bidi facts across an entire domain and checks strict UTS #46 DNS lengths after ASCII conversion. Bidi validity applies to every nonempty label if any label contains RTL characters; a late RTL label therefore affects earlier labels too. DNS checks require ASCII labels of 1–63 characters and a domain of at most 253 characters, rejecting empty labels including a final root label in strict `VerifyDnsLength` mode. URL-host processing may disable that strict length policy. Counters saturate above the limits rather than wrapping on oversized input.


`src/idna-domain.bend` now provides strict `toASCII(context, options, input)`: domain-wide mapping/NFC, dot splitting, ACE decoding and label validation, Punycode encoding, domain-wide Bidi and optional strict DNS lengths. It reuses `idna-label.Context` and requires explicit label/Bidi/length options; no URL policy defaults are chosen. Typed failures distinguish preparation, indexed label/encoding errors and domain policy failures. Successful output preserves label order and empty separators when strict DNS lengths are disabled. This is ToASCII, not tolerant ToUnicode display conversion or a complete URL host parser; forbidden-host-character and numeric-host handling still belong to the URL layer.
