# Native runtime foundations

Pure Bend primitives for the canonical libraries. Compiler changes are documented in [patches](../../patches/README.md).

`src/line-decoder.bend` provides immutable `LineDecoder` state with byte/text/optional-chunk decoding and explicit `flush`. It preserves OpenAI SDK 6.40.0's CR, LF, CRLF and deferred-CR emission timing, including UTF-8 replacement and initial-BOM removal independently for each line. Pending bytes are kept in reversed lists and decoded only when a line completes; each arriving chunk avoids copying or rescanning the accumulated buffer. `findDoubleNewlineIndex` returns `Maybe<Nat>` for CRCR, LFLF and CRLFCRLF boundaries. Run `python3 tests/line_decoder_vectors.py`: 11,940 direct SDK comparisons pass on one/four native threads. These dependency checks do not establish provider SSE or HTTP integration.

`src/utf8.bend` implements replacement-mode UTF-8 encoding and decoding over Base's byte-list convention (`List<&2, U32>`, each element in 0..255). Incremental decoding returns immutable decoder state and the text available from that chunk; `finish` emits a replacement for an unfinished sequence and resets state. One initial BOM is removed, while later BOMs survive. Complete-buffer decoding matches the non-streaming `TextDecoder` used by the pinned OpenAI SDK. Encoding combines explicit UTF-16 surrogate pairs and replaces unmatched surrogates. It adds no foreign effects or compiler patches. Run `python3 tests/utf8_vectors.py` for 80,002 comparisons on one/four native threads: complete buffers/encoding against Node and Bun, incremental output against Bun. The test sends inputs to one compiled runner rather than generating a larger program per vector. This codec is a transport foundation; HTTP/TLS and provider wire integration remain pending.

`ref.bend`, `deferred.bend` and `callback.bend` provide explicit synchronized state, first-settlement results and reusable callback resources. Their handle identity is resource identity, not an object model. Ordinary pi records, lists and event payloads do not allocate reference cells.

`abort.bend` uses a deferred typed reason: supplied reasons or a `DefaultAbort` variant. The first abort wins; observations may be removed independently and late observations receive the settled reason. `throwIfAborted` returns a typed result. No DOM event dispatch, event-handler properties or inherited object APIs are involved. Combined/timeout signals and integration with the complete agent remain pending.

`src/clock.bend` reads exact monotonic nanoseconds through the new `IO.monotonicNanoseconds` compiler primitive. The primitive returns high/low U32 words; its native effect reads the existing OS monotonic clock and its JS-backend effect uses `process.hrtime.bigint`. Clock origin handling and numeric conversion are pure Bend. A `Clock` captures one origin, and copies keep it; initialize it once before runtime callbacks start. `elapsed` subtracts unsigned 64-bit ticks before converting the interval to binary64 and dividing by one million, matching the evaluation order in [Node's PerformanceNowImpl](https://github.com/nodejs/node/blob/v24.18.0/src/node_perf.cc#L284). Raw epochs are unspecified, and subtraction follows the counter's modulo-2^64 representation.

`python3 tests/clock_vectors.py` checks 276 exact-bit interval vectors against Node numeric arithmetic, including nanosecond intervals at epochs beyond binary64 integer precision, conversion ties, word carries and counter wrap. Native one/four-thread and Bun-hosted JS-backend tests check monotonic ordering, timer liveness, cross-task epoch consistency and elapsed-time readings. The JS host is Bun because the existing sleep effect uses bun:ffi; Node supplies the independent numeric oracle. They do not compare absolute clock origins across processes or establish real-time scheduling guarantees. The compiler patch is explicit under `patches/`; native clock policy uses no host floating-point or library adapter.

`Deferred.observe` returns an affine `Observation` containing a single-use `Ticket<Maybe<A>>` and a copyable `Cancellation<A>` handle. `cancel` atomically removes the pending waiter; its true result identifies the cancellation winner. Cancellation delivers `None`, whereas settlement delivers `Some(value)`, including `Some(None)` when the actual value is optional. Exactly one side owns delivery, and duplicate or post-settlement cancellation returns false. Arbitrary-precision registration keys prevent stale handles from matching later observations after integer wraparound. The original `subscribe`/`result` API remains available for required observations. Native tests verify removal, neighboring required/removable waiters, late observation, stale handles across a 64-bit counter carry, optional results, 64 simultaneous cancellation attempts with exactly one winner, and 128 settlement races. Cancellation handles must retire before their source is disposed.

`src/callback.bend` provides reusable first-class callback handles despite Bend's affine closures. Construction supplies closed callback code and a typed runtime capture environment; libraries subsequently accept and store the resulting runtime `Callback<Input, Output>` value. Each call obtains a fresh affine closure and releases the factory before invoking user code, allowing concurrent async calls. Inputs and outputs may themselves be affine. The factory uses one explicitly documented guarded `@unsafe` corecursion: construction returns a closure, and each invocation constructs one successor. There is no background actor or artificial invocation limit.

These shared primitives currently require owner-directed disposal after aliases and observers retire. The current Bend channel runtime does not reclaim live channel rows merely because handles are dropped. Automatic resource reclamation remains a language/runtime prerequisite for removing manual disposal. These primitives do not establish completion of pi's event-stream or subscription semantics. The generic stream has separate upstream tests in `packages/ai/test/event-stream.bend`.

`src/u64.bend` implements unsigned fixed-width arithmetic modulo 2^64, bit operations, logical shifts, rotations, comparison, and quotient/remainder division. Values use two U32 limbs, ordered high then low. Division by zero returns `None`; shifts of at least 64 bits produce zero; rotations reduce their count modulo 64. `multiplyWords` exposes the exact 32-by-32-bit product needed by wider arithmetic.

`src/u128.bend` provides exact 64-by-64-bit multiplication and wide intermediates with sticky-bit shifting. It is used to retain the full product before binary64 rounding.

`src/f64.bend` represents every IEEE-754 binary64 bit pattern and implements addition, subtraction, multiplication and division with round-to-nearest, ties-to-even. It retains signed zeros and subnormal results. Arithmetic NaNs become a canonical quiet NaN; payload preservation is not an API guarantee. Comparisons return `None` for unordered NaN operands and treat signed zeros as equal. Unsigned integer conversion rounds directly from the 64-bit integer. Alignment retains guard, round and sticky bits; cancellation and underflow are normalized before the final rounding. Operations never pass through F32. Decimal parsing and remaining numeric operations are still required before full integration with pi's number APIs; base-10 formatting is implemented separately in `f64-decimal.bend`.

Run the independent vector tests from the repository root:

```sh
python3 tests/u64_vectors.py
python3 tests/f64_vectors.py
sh tests/runtime-concurrency.sh
```

Python generates expected results from arbitrary-precision integers and host binary64 arithmetic. It writes constant input/output vectors, then compiles and executes Bend assertions. Python supplies no behavior to the implementation or native executable. The tests currently cover 272 unsigned/wide arithmetic vectors and 1,077 floating-point vectors, each checking all four operations, comparison and integer conversion. These tests supplement, rather than replace, the future port of pi's numeric and model-cost tests.

Concurrency tests check retained reference identity, 1,000 competing updates, affine ownership, result fan-out, ignored duplicate settlements, repeated callback invocation, and overlapping async callback calls. Gates and explicit registrations coordinate the tests; no sleeps are used to guess scheduling order.

`src/fifo.bend` supplies the persistent two-list FIFO used by the event stream and per-iterator request queues. Enqueue/dequeue are amortized constant time along a queue history; transferring incoming values reverses the list only when the outgoing side empties. Stream tests cover buffered and waiting-consumer ordering across transfers.

`src/record.bend` is a persistent string-keyed dictionary with insertion-order traversal. Updating a value preserves its position; removing and re-adding a key appends it. Numeric-looking strings have no special ordering. `tests/record_vectors.py` checks this native contract against an independent insertion-ordered dictionary model.

`src/ordered-map.bend` supplies persistent insertion-ordered tool maps. Numeric-looking keys are ordinary strings; updates preserve position and remove/reinsert appends. Operations currently scan lists.

`src/big-nat.bend` implements exact unsigned arbitrary-precision integers for decimal/binary64 conversion. Values have canonical little-endian 16-bit limbs; zero has no limbs. Addition, comparison, nonnegative subtraction, multiplication, left shift, powers and quotient/remainder division use only Bend U32 arithmetic. Subtraction returns `None` for a negative result; division returns `None` for a zero divisor. `divideSmall` additionally requires a divisor of at most 65535; general division has no such restriction. Decimal integer parsing rejects signs, whitespace, fractions and exponents, accepts leading zeros, and normalizes zero. Decimal output uses an input-size-derived digit bound, not fixed precision. No host arithmetic or string formatting supplies production results.

`python3 tests/big_nat_vectors.py` checks 179 independent Python-integer vectors, plus power/construction/input cases. Coverage includes limb boundaries, carries/borrows, zero divisors, out-of-range small divisors, 2048-bit operands, 2^1074 and 5^1074, and exact decimal round trips. The native executable does not invoke Python.

`src/f64-decimal.bend` implements shortest base-10 binary64 spelling using exact integer rounding intervals. It tests both adjacent decimal candidates at each precision, respects inclusive/exclusive binary midpoints (including the asymmetric lower interval at normal powers of two), and chooses the closest admissible decimal with ties to an even coefficient. It emits ordinary or scientific notation according to [ECMAScript Number::toString](https://tc39.es/ecma262/multipage/ecmascript-data-types-and-values.html#sec-numeric-types-number-tostring). Both signed zeros become `0`; non-finite number strings remain `NaN` and signed `Infinity`.

`toDecimal` returns `Maybe<String>`: an impossible denominator or exhausted format-derived bound remains an explicit failure instead of producing an approximate value. Normalization is bounded by binary64's denominator bit count; digit selection checks up to seventeen significant places. These are format guarantees, not user-input precision caps. `toJsonNumber` additionally maps non-finite values to `null`, matching [JSON numeric serialization](https://tc39.es/ecma262/multipage/structured-data.html#sec-serializejsonproperty).

`python3 tests/f64_decimal_vectors.py` compares 1,092 bit patterns against JavaScript's actual number spelling, with additional JSON numeric checks. Coverage includes signs, dense small subnormals, the subnormal/normal boundary, maximum finite values, powers of two and ten with adjacent bit patterns, ordinary/scientific cutovers, explicit decimal midpoint ties in both directions, and seeded random patterns. JavaScript supplies expected test strings only. This is an exact reference implementation, not a performance-tuned conversion algorithm; whole-provider serialization performance still needs evaluation.

Serialization of the explicit pi-ai `JsonValue` union is implemented separately. The bootstrap JSON encoder's preserved decimal tokens still cannot replace the canonical codec or establish correct tool-declaration comparison.

`src/utf16.bend` canonicalizes string representation by merging valid adjacent surrogate pairs into scalar characters, retaining unpaired units. It does not perform Unicode spelling normalization. Dictionary keys use native string equality. `src/json-string.bend` quotes that representation, escaping controls and unpaired surrogates while preserving ordinary Unicode. The canonical `JsonValue` codec uses these helpers. JavaScript differential tests and native codec tests run through `sh tests/json.sh`; existing record/Map ordering tests remain separate.

`src/schema-value.bend` holds immutable schema/argument data: null, booleans, numbers, text, lists and dictionaries. Equality compares dictionary fields without regard to order and preserves list order. There is no dynamic JavaScript object model, callable schema metadata, property inspection, JSON cloning, or prototype machinery. See `packages/ai/test/native-schema.bend`.


`src/date.bend` implements `Date.now` over exact signed Unix milliseconds from the explicit compiler primitive. It remains separate from `Clock.now`, whose epoch is an elapsed-time origin. Integer words are converted to binary64 entirely in Bend, including pre-epoch negative values; no F32 conversion is involved. This is not the Date constructor, parsing, formatting, timezone or full Date API. `python3 tests/date_vectors.py` checks 146 signed conversion bit patterns and live native/JS-backend readings against host wall-clock call bounds. System-clock adjustments remain observable; the wall clock is not guaranteed to be monotonic.

`F64.isInteger` classifies the stored binary64 value without decimal conversion or F32 rounding. Signed zeros are integers; subnormal fractions, NaNs and infinities are not. For finite values, restoring the significand after removing fractional bits must reproduce it exactly. The validation predicate differential tests cover this operation across exponent boundaries and random bit patterns (`python3 tests/validation_primitives_vectors.py`).

`src/f64-ratio.bend` converts an arbitrary-size unsigned numerator/denominator pair and explicit sign to binary64 with exact round-to-nearest, ties-to-even. A zero denominator returns `None`; zero numerators retain the supplied sign. It searches monotone positive encodings using integer comparisons in units of the smallest subnormal, then compares the exact midpoint of adjacent values. A virtual `2^1024` endpoint supplies the correct overflow midpoint. Sixty-three bisections cover the encoding interval; this is a proof-derived bound, not a precision or input-size cap. Numerator and denominator are never independently rounded or converted to host numbers.

`python3 tests/f64_ratio_vectors.py` checks 226 cases against Python's independent exact-rational conversion on one/four threads. Cases include both signs of zero, zero denominators, ties and close neighbors, subnormal/normal boundaries, odd/even significands, overflow, random large ratios, and 1,000-digit operands whose ratio remains near one. This reference-quality conversion is the rounding dependency for numeric parsing; numeric-string grammar, parsing and validation coercion are not implemented by this module. Throughput optimization remains open.


`python3 tests/number_string_vectors.py` compares 365 inputs against JavaScript's actual `Number` conversion on one/four threads, preserving negative-zero bits and checking NaNs explicitly. Coverage includes all accepted whitespace code points and rejected lookalikes, surrogate inputs, malformed syntax, three radix forms, exact rounding midpoints, subnormal/overflow boundaries, long mantissas and exponents, and seeded decimal cases. Runtime conversion is pure Bend; Node supplies expected test values only. This is a reference-quality parser; integration into schema coercion and provider codecs and performance tuning remain pending.

`src/json-parse.bend` decodes strict JSON directly into immutable `schema-value.Value` arrays/records and native binary64 numbers. It validates numeric grammar before decimal conversion, normalizes surrogate-pair representation, retains lone units, and uses explicit container frames rather than a recursion-depth limit. Duplicate JSON keys replace the previous value; keys remain ordinary native record keys, including `__proto__`. Failures are typed parse errors rather than host-engine exception text. `tests/json_parse_check.py` checks 498 acceptance/value cases against JSON.parse, exact top-level numeric bits (including negative zero and overflow), and a 2,000-level nested container on one/four threads. Partial JSON and repair are not part of this decoder.

`src/sse-chunks.bend` ports the pinned SDK's byte-level SSE framing. It retains bytes until CRCR, LFLF or CRLFCRLF, yields every completed frame in order and yields a remaining nonempty fragment at EOF. `ChunkDecoder` is immutable, with a delimiter-prefix state and reversed byte buffer; it avoids the SDK's repeated buffer copying/rescanning. `python3 tests/sse_chunks_vectors.py` passes 10,297 comparisons on one/four native threads, checking exact bytes and which input read emits each frame. Event-field decoding is provided by `sse-decoder.bend`; provider integration remains pending.

`src/sse-decoder.bend` provides immutable `SSEDecoder` state and `ServerSentEvent` values. It implements the pinned SDK's field and blank-line rules, preserving absent versus empty event names and exact data joins. The approved diagnostic policy clears comment/unknown-field history at each empty block; it does not clear an explicitly empty event name. `python3 tests/sse_decoder_vectors.py` checks 3,306 sequences on one/four native threads against the actual SDK and the isolated diagnostic-only adaptation. This line-to-event layer does not yet compose the complete async wire iterator.

`src/sse-stream.bend` composes byte framing, UTF-8 line decoding and SSE field decoding into immutable `StreamDecoder` transitions. Each decode call returns the events made available by that input chunk, in order. `finish` consumes the state, flushes pending bytes and the final line, and returns only events with an actual blank-line separator; it does not force an incomplete event to emit. `python3 tests/sse_stream_vectors.py` passes 3,819 comparisons against the SDK's full `_iterSSEMessages` iterator on one/four native threads, including exact input-read emission timing. The oracle checks original event names/data/timing and the approved diagnostic-only adaptation separately. Pulling and early-close behavior are provided by `sse-reader.bend`; request cancellation, JSON event decoding and provider integration remain unfinished.

`src/sse-reader.bend` supplies an affine pull cursor over borrowed input callbacks. Each `next` or `close` returns a successor cursor; event buffering and decoder state are ordinary immutable values, not reference cells. Pending events are delivered before another input read. Fresh, active, input-exhausted and closed states distinguish when an early close must call the underlying iterator's return callback. Read failure closes the cursor without calling return; return failure is surfaced once and leaves the successor closed. The owner must retire callback handles after cursor use; the reader does not dispose borrowed callbacks. `python3 tests/sse_reader_check.py` verifies 806 complete next/return traces against the actual SDK generator on one/four native threads, and rejects a cursor-duplication fixture at type checking. This reader models an acquired input iterator; HTTP-body acquisition, request cancellation and the outer JSON/provider stream remain separate unfinished work.

`json-decode.bend` provides typed field/object/list decoding over immutable JSON values. Required fields distinguish absence from wrong types; nullable optional fields use `Maybe`. Failures carry literal field/index path segments, so nested diagnostics require no dotted-key parsing. Decoders compose with Base's `Result` monad and short-circuit on the first failure. Static element decoders support native list traversal without effectful callback handles. The Responses wire test exercises these helpers through nested item, usage and error decoding.

`serial-resource.bend` coordinates asynchronous operations on one affine value. A duplicable handle queues access through a one-slot channel; an affine owner controls retirement. Each operation receives the resource and returns its successor alongside its result, so typed failures also release the next queued operation. This is distinct from `Ref.modify`'s pure atomic update. An operation must not await re-entry on its own handle. Join outstanding operations and retire all handle aliases before retiring the owner; retirement returns the resource for caller-directed cleanup. Native one/four-thread tests cover an awaited operation failing before a queued successor, state preservation, ordering and rejected owner duplication.


## Unicode normalization

`src/unicode-normalization.bend` provides `nfc(tables, text)` and `nfd(tables, text)` for scalar strings. Construct `src/unicode-17-normalization.bend`'s `tables()` once and share the immutable value across calls. Normalization decomposes canonical mappings, handles Hangul algorithmically, stably orders combining segments and performs blocked canonical composition. It does not case-fold or implement IDNA validation.

The generated Unicode 17 data is covered by `src/unicode-LICENSE.txt`. Regenerate with `python3 scripts/generate-unicode-normalization.py`; `--check` verifies reproducibility. The generator verifies pinned hashes of official Unicode inputs cached under `build/unicode-17`; downloaded source files are not production dependencies. `u32-table.bend` stores balanced immutable lookup data with generated height bounds, and `stable-sort.bend` avoids non-tail list traversal for long combining segments.


## IDNA input preparation

`src/idna-mapping.bend` maps scalar strings using Unicode 17 UTS #46 data, in transitional or nontransitional mode. Disallowed code points return a typed error containing the first offending code point. Construct `unicode-17-idna-mapping.table()` once and reuse it. `idna-prepare.bend` composes mapping with NFC through an immutable context containing both tables. This is preparation only: label validity, ACE decoding, contextual/bidirectional rules and URL host restrictions still need to run before using a result as a hostname.

`scripts/generate-idna-mapping.py --check` verifies the generated ranges against pinned official data. The mapping checker compares range boundaries and mixed strings exactly and checks every Unicode code point in both modes through ordered block checksums. The preparation checker exercises mapping plus NFC on the official IDNA test inputs; it does not claim full IDNA conformance. Both run on native one/four threads and Bun through native-cleanup.


`src/idna-bidi.bend` implements the RFC 5893 label rule over `unicode-bidi-class.Class` values, either incrementally or through `analyze`. Its result preserves both rule validity and whether the label contains R/AL/AN. The domain processor must check every label if any label contains those classes; checking only right-to-left labels would be incorrect. Full domain integration remains unfinished.


`src/idna-contextj.bend` validates contextual joiners incrementally. Feed each scalar's code point, `unicode-joining-type.JoiningType` and canonical combining class to `push`, then call `finish` to reject any unresolved right context. Transparent characters preserve joining context but do not preserve immediate virama adjacency. These rules operate on prepared label characters, after any transitional mapping has removed join controls. The property-backed label analyzer described below feeds these transitions.


`src/unicode-17-idna-properties.bend` now supplies an immutable table for Bidi_Class, Joining_Type, canonical combining class and mark classification, including Unicode's script-specific defaults. `idna-label-context.analyze(table, text)` connects property lookup to the contextual rules and leading-mark inspection in one traversal. Its input is a prepared, decoded label; it does not perform mapping, NFC or ACE decoding. Regenerate the pinned data with `python3 scripts/generate-idna-properties.py`.


`src/idna-ace.bend` supplies strict decoding of already-mapped `xn--` labels, returning the decoded text and whether ACE encoding was used. It rejects non-ASCII encodings, malformed Punycode and empty/ASCII-only decoded results. It deliberately preserves decoded characters for later validation; they must not be mapped again. Transitional capital sharp S is handled separately by the mapper as required by UTS #46, rather than relying solely on the data-table replacement.


`src/idna-label-rules.bend` checks prepared-label syntax and mapping status with explicit `checkHyphens`, `useSTD3` and processing-mode options. It returns typed failures and never repairs text. ACE-decoded labels must use nontransitional mode. These checks are one part of validation: NFC, leading marks, ContextJ, domain-wide Bidi applicability and DNS lengths must also be handled before treating text as a valid hostname.


`src/idna-label.bend` composes strict ACE decoding, NFC verification, syntax/status checks and Unicode context analysis. Construct an immutable `Context` from the mapping, normalization and property tables and reuse it across calls. `process` accepts a label after domain-wide mapping/NFC and splitting; decoded ACE text is checked without repair and uses nontransitional status rules automatically. Options explicitly select hyphen, STD3 and joiner checks. Results preserve the decoded text, emptiness and Bidi facts, so the domain processor can apply Bidi requirements to every nonempty label when needed. DNS lengths and full domain orchestration remain separate work.


`src/idna-domain-policy.bend` aggregates label Bidi facts across an entire domain and checks strict UTS #46 DNS lengths after ASCII conversion. Bidi validity applies to every nonempty label if any label contains RTL characters; a late RTL label therefore affects earlier labels too. DNS checks require ASCII labels of 1–63 characters and a domain of at most 253 characters, rejecting empty labels including a final root label in strict `VerifyDnsLength` mode. URL-host processing may disable that strict length policy. Counters saturate above the limits rather than wrapping on oversized input.


`src/idna-domain.bend` now provides strict `toASCII(context, options, input)`: domain-wide mapping/NFC, dot splitting, ACE decoding and label validation, Punycode encoding, domain-wide Bidi and optional strict DNS lengths. It reuses `idna-label.Context` and requires explicit label/Bidi/length options; no URL policy defaults are chosen. Typed failures distinguish preparation, indexed label/encoding errors and domain policy failures. Successful output preserves label order and empty separators when strict DNS lengths are disabled. This is ToASCII, not tolerant ToUnicode display conversion or a complete URL host parser; forbidden-host-character and numeric-host handling still belong to the URL layer.


`src/url-host.bend` represents domains, opaque hosts, IPv4, IPv6 and empty hosts with native variants and a common serializer. `classifyDomain` checks a previously processed ASCII domain and dispatches numeric suffixes to IPv4 parsing. `parseOpaque` preserves case/percent escapes, applies C0 UTF-8 escaping and dispatches leading brackets to IPv6 before ordinary opaque-host checks. `bracketed` accepts the text after an opening bracket. This layer does not perform special-host percent decoding or IDNA policy selection. Nonfatal URL validation warnings are not exposed.


`src/url-host-input.bend` prepares raw special-host tokens. It dispatches literal leading brackets to IPv6 before decoding, rejects an empty input token, and otherwise returns domain text after one percent-decoding pass and replacement-mode UTF-8 decoding with BOM preservation. Plus signs remain literal. The result distinguishes a completed IP literal from domain text that still requires IDNA policy and host classification. Percent-encoded brackets therefore never become IP-literal syntax.


`url-scheme.bend` represents the six special schemes explicitly and retains normalized names for other schemes. Its token parser accepts ASCII scheme syntax, lowercases ASCII letters, and exposes special-scheme and default-port queries. `url-port.bend` parses a delimited decimal port into an optional bounded number, omitting empty and scheme-default ports. Overflow never enters the accumulator. URL input preprocessing, delimiters, relative resolution, file authority restrictions, and setter prefix semantics belong to the enclosing parser; these modules do not implement them. Both are pure Bend.


`url-authority.bend` reads a non-file authority prefix and returns the unconsumed path/query/fragment delimiter. Special schemes additionally stop at backslash. Its immutable tokens retain optional credentials and an optional raw port, distinguishing absent syntax from explicitly empty syntax. The last at-sign separates credentials from host; the first credential colon separates username/password, and the shared UTF-8 percent encoder escapes both. Host/port splitting respects IPv6 brackets. These lexical tokens still require host parsing, port validation and scheme-specific empty-host checks; file authority handling is separate.


`url-path.bend` parses hierarchical path segments with immutable accumulators, resolves literal and percent-encoded dot segments, preserves repeated separators, and handles special-scheme backslashes and file-drive roots. `start` accepts the remainder after authority scanning; `parse` enters the path state with normalized base segments after the caller has performed relative-path shortening or reset. Results preserve absent versus empty query/fragment values and encode them with their respective UTF-8 sets. Input preprocessing, opaque paths, setter overrides and full relative-URL resolution are separate work.


`url-record.bend` defines the immutable internal URL value: typed scheme/host, optional port, encoded credentials, hierarchical or opaque path, and optional query/fragment. Absent host and an explicitly empty host are distinct. `url-serialize.bend` serializes this normalized record or its path, optionally excluding the fragment. It preserves encoded text, omits empty credentials, and protects hostless paths beginning with two slashes from being interpreted as an authority. Reversed accumulators bound machine-stack use for long components and many segments. Parsers must establish record invariants; serialization does not validate or normalize arbitrary field combinations.


`url-input.bend` prepares constructor inputs by trimming edge C0 controls/space and removing ASCII tabs, line feeds and carriage returns. `removeTabsAndNewlines` exposes only the latter operation for parser entries that must retain edge characters. `prefix` separates a syntactically valid, lowercased scheme from its unconsumed remainder, or returns the complete preprocessed relative reference unchanged. A detected scheme is not proof of URL validity; base resolution and the remaining parser states follow. All scans are tail-recursive.


`url-opaque-path.bend` handles the opaque-path state used by data, mailto and other non-hierarchical URLs. It preserves literal slashes, dot segments and percent escapes, encodes C0/non-ASCII bytes, and handles the final literal space before a query/fragment delimiter. `url-query.bend` provides shared UTF-8 query/fragment parsing for both opaque and hierarchical paths, with scheme-dependent query escaping. Opaque-path entry selection and constructor preprocessing remain the responsibility of the enclosing URL parser.


`url-special-host.bend` composes raw host preparation, Unicode domain-to-ASCII conversion and final domain/IPv4 classification. Literal bracketed IPv6 bypasses percent/IDNA processing, while percent-encoded brackets do not. The API returns typed preparation, domain or classification failures and borrows reusable immutable Unicode tables through its context argument. IDNA options are required explicitly: the pending Node-versus-Unicode domain-validation decision has not been made into a public URL default.


`url-absolute.bend` composes constructor preprocessing, scheme dispatch, authority validation, host/port parsing, hierarchical/opaque path parsing and immutable URL records. It handles all absolute schemes, including file authorities, raw Windows-drive host tokens and localhost normalization. Missing schemes and invalid authorities/hosts/ports return typed errors. Its context requires explicit IDNA options and reusable Unicode tables; relative references with a base are a separate unfinished entry point. `url-authority.raw` exposes the shared authority boundary scanner for file parsing without applying non-file credential/port rules.

`dns-address-lookup.lookupRandom` performs A/AAAA lookups against a caller-selected numeric recursive server using a fresh OS-random ID for each question, retaining it across server attempts and reset recovery. `lookupWith` accepts a static source function and borrowed environment for deterministic or application-owned sources; `lookup` retains the fixed-ID API. `dns-id.bend` converts two entropy octets without modulo bias and preserves source failures. Alias responses trigger follow-ups under one shared deadline, with immutable alias history across packets. The current random entry point requires the isolated entropy/socket/connection/timer candidate; Linux entropy is implemented, while Darwin entropy and OS resolver configuration remain work in progress.

`resolver-address.bend` parses numeric server tokens independently from URL host policy: libc-style IPv4 numbers and IPv6 addresses with optional unresolved zone text. `resolver-config.bend` builds an immutable syntax tree for nameserver, domain, search, options and sortlist directives. It preserves order, unknown directives and invalid server tokens for the policy/diagnostic layer. Parsing does not apply defaults, environment overrides, interface resolution or resolver options; these remain explicit integration work.

`resolver-settings.configure` folds configuration entries with typed, already-decoded overrides. It preserves valid server order and duplicates, defaults an empty server list to IPv4 loopback, and selects search domains from an explicit override, the final file directive, or the hostname suffix in that order. Invalid server tokens and unknown lines remain diagnostics. Option and sort-list tokens are collected in order for subsequent interpretation; the result is not yet a runnable resolver configuration.

`resolver-options.bend` represents resolver settings with native numeric fields and a set of typed features. `defaults` and `apply` operate on valid options; `parseStrict`/`interpretStrict` recognize whole flag names and unsigned decimal numbers with documented caps, reporting malformed/unknown tokens separately. The strict parser is an explicit candidate policy. Handling its diagnostics and compatibility with permissive libc token parsing remain an open user decision; no network entry point consumes unresolved reports.

`dns-presentation.bend` converts textual DNS names into binary labels plus an explicit absolute/relative flag. It supports escaped characters and three-digit decimal octet escapes, preserves case and arbitrary escaped bytes, and enforces wire-name/label limits. Text enters through the existing UTF-8 encoder; IDNA and hostname/search policy remain separate. Raw NUL and out-of-range input octets return typed errors instead of truncating a Bend value. The UTF-16 representation normalizer now collects output through a reversed character accumulator, avoiding Base's non-tail `String.join` on long inputs.

`dns-search.bend` is an immutable cursor over direct-name and search-suffix candidates. Its explicit policy controls the ndots threshold, default-name/search flags and no-TLD behavior. Caller-supplied dot count and absolute status keep text policy separate from binary label data. Each yielded candidate validates the full composed wire name. `stopSearch` skips remaining suffixes while retaining any permitted final bare-name attempt; only previously yielded root suffixes suppress that attempt. Response classification and network execution remain separate work.

`dns-search-response.bend` handles failed search candidates with immutable error history. It separates resolver error classes from transport/answer causes, keeps the initial direct-name failure for final precedence, and distinguishes continuing suffix search, skipping to the final bare name, and immediate termination. Success finishes in the enclosing driver. Cancellation, entropy failure and cleanup errors are not DNS search causes and must retain their separate typed failure paths; the network adapter remains to be connected.

`dns-search-run.bend` executes the cursor and failure policy through an injected asynchronous Bend request function. Successful values return immediately; typed non-DNS failures halt without being masked by earlier resolver errors. Invalid candidates follow the failure policy without calling the request function. The borrowed environment remains caller-owned. The generic driver is tested with suspended scripted requests; `dns-address-search` below connects it to actual DNS exchanges. Server retry and OS integration remain implementation work.

`dns-address-lookup.exchangeWith` borrows an existing deadline signal for a name and all its alias follow-ups. It validates the record type/read size before invoking the ID source, returns the typed lookup result, and leaves the scope and source environment caller-owned. Search can reuse that deadline across candidates instead of resetting the timeout for each name. `lookupWith` remains the convenience entry point that creates and closes its own scope.

`dns-address-search.searchWith` now executes a candidate cursor against one numeric TCP resolver, using a borrowed injectable ID source and one owned deadline across candidates and alias follow-ups. `searchRandom` supplies OS entropy. NXDOMAIN, SERVFAIL, other nonzero DNS codes and empty selections feed the search response policy; successful selections return intact. Connection refusal, other socket failures, EOF and incomplete frames now enter search policy as explicit transport causes; cancellation, entropy, cleanup, validation and other unclassified failures retain their typed terminal details. This composes the existing network and search layers, but OS resolver integration, socket setup/connect error distinctions and UDP remain unfinished. The current search entry points require the additional isolated [connection-refusal primitive](../../patches/experimental/socket-refused/README.md).

`dns-tcp-servers.bend` provides an ordered, single-pass driver over numeric TCP servers. Each closed exchange either returns a reply, permits the next server, or stops with its typed report. It retains the final failed report on exhaustion and borrows one deadline throughout. This driver is now wired into address lookup; the single-server search API inherits its reset recovery through that lookup layer. `dns-tcp-recover` now reconnects once after a reset while reading the frame length, including a partially received length, but never after a payload or write reset. Transport errors retain the operation explicitly. The retry reuses the query and deadline, and cleanup failure suppresses it. Socket setup/connect stage distinctions and higher-level integration remain pending.

`dns-address-lookup.lookupServersWith` and `lookupServersRandom` accept a supplied ordered server list; `exchangeServersWith` borrows an existing deadline. All share the same alias-selection implementation as the preserved single-server entry points. Empty lists return `NoServers` before entropy or scope creation. Each alias question restarts the supplied order and draws one new ID; every retry of that question retains its ID. The final transport or cleanup report remains typed. Socket setup/connect error distinctions, OS resolver configuration and UDP are still pending.

`dns-address-search.searchServersWith` and `searchServersRandom` now execute a candidate cursor over a supplied server list. One deadline spans suffix candidates, alias questions, failover and permitted reset recovery. Server order restarts for each question; IDs change for new questions and remain stable across retries. Existing single-server search entry points wrap singleton lists. Empty server lists fail before creating a deadline or drawing entropy. This is explicit-configured TCP search, not yet an OS-backed resolver.

`dns-server-rotation.bend` supplies a pure generic rotation state. `choose` returns the selected server order and next immutable state; disabling rotation returns the original order without advancing the retained position. Duplicates and empty/singleton lists are preserved. Enabled steps use tail-recursive list operations, tested with 16,384 entries. The caller owns initialization. `dns-server-source.bend` now serializes its pure transitions through an owned `Ref`, with borrowed fixed or rotating selectors. Lookup and search accept these selectors through `exchangeSourceWith`, `lookupSourceWith`/`lookupSourceRandom` and `searchSourceWith`/`searchSourceRandom`. Each question selects once after successful ID generation and a cancellation check; failover and reset recovery retain that selected order. Alias and search follow-ups select again. Existing list APIs wrap fixed selectors. All borrowed uses must finish before the selector owner closes. OS configuration loading and automatic reload remain pending; the explicit TCP owner is described below.

`dns-server-rotation.startAt` and `dns-server-source.createAt` preserve the configured order while initializing a different next rotation position. Offsets wrap by list length; initialization uses linear, tail-recursive traversals. These are explicit seeded constructors. OS-random initialization is supplied by `dns-server-initialize`; an explicit configuration owner is provided by `dns-tcp-resolver` below.

`random-index.bend` samples an index below a supplied bound using four OS entropy bytes and pure rejection sampling. Bounds range from 1 through 2^32; invalid bounds fail before entropy, and bound 1 returns zero without a draw. Byte decoding validates exact length and octet range. Rejected words draw again; source errors propagate unchanged. The static source/environment API supports caller-owned generators and deterministic tests. Injected effects must return promptly; this initialization API does not impose a deadline.

`dns-server-initialize.random` creates an owned server selector with a uniform initial position, while `createWith` accepts an injected word source. Empty and singleton lists skip entropy. Owner allocation follows successful sampling; failure returns without creating selector resources. This uses the existing isolated [entropy primitive](../../patches/experimental/entropy/README.md), with no new compiler effects or installation changes. Borrowed selector use and teardown follow `dns-server-source`'s ownership contract. These constructors are not yet wired into OS configuration loading/reload.

`dns-tcp-resolver.bend` owns an explicit TCP configuration and its server selector across calls. `Config` carries numeric endpoints, parsed search domains, search policy, timeout, read limit and the rotation flag. `createWith` injects initial-position entropy; `create` uses OS entropy. Disabled rotation skips seeding. `borrow` returns an immutable configuration view with a borrowed selector; `lookupWith` injects question IDs and `lookup` uses OS IDs. Every lookup creates one deadline for its complete search, while rotation survives between calls.

Finish all borrowed operations before `replaceWith`/`replace` or `close`. Replacement constructs a new owner before retiring the old one. `Unchanged` returns the previous owner on initialization failure; `Updated` returns the new owner after closing the old selector. This is explicit replacement, not automatic reload. OS configuration loading, interface-name resolution, option interpretation, hosts files, UDP, family ordering and HTTP integration remain separate work.

`file-fold.bend` supplies a generic owned byte reader over the existing file primitives. A pure static consumer receives each nonempty chunk and returns `Continue` or `Stop` with its next state. State may be affine. `Outcome` returns that state on EOF, early stop, open failure, read failure or invalid read size. The reader closes its file before returning from every path that opened one; zero read size fails before opening. Short nonempty reads are data, not EOF. The consumer controls buffering and text-decoding policy. This API has no cancellation/deadline, and the existing `File.close` primitive does not report close errors.

`resolver-file.bend` connects owned file input to configuration parsing and settings precedence. `readWith` accepts a decoder, path, chunk size and source-byte limit, returning syntax entries only after complete read/decode success. `loadWith` additionally applies typed `Settings.Overrides`. Open/read failures, size overflow and decoder failures are distinct; no partial configuration is applied. Exactly the byte limit is allowed, including comments and newlines; overflow stops and closes the file. The decoder remains explicit, so this layer imposes no BOM or malformed-byte policy. Environment and OS hostname capture are composed below; Linux missing-file fallback is composed below; option diagnostic policy, scope resolution and conversion into the live resolver remain implementation work.

`resolver-environment.bend` captures `LOCALDOMAIN` and `RES_OPTIONS` once each, preserving unset versus present-empty values. Current Linux/JS `get_env` absence (`ENOENT`) becomes `None`; other failures retain the variable, code and message. An injected getter uses the same path. `LOCALDOMAIN` stops at newline and preserves an initial empty root suffix; space/tab-separated option tokens remain uninterpreted. `overrides` combines these values with an explicitly supplied hostname.

`resolver-load.loadWith` combines that environment capture with bounded file reading, caller-selected decoding and settings precedence. Capture failure stops before opening the file; file/decoder failures remain separate. `captured` accepts an already captured or injected environment result. OS hostname discovery is supplied by `resolver-system` below; Linux missing-file fallback is provided below; option diagnostic policy, IPv6 scope resolution and conversion into a live resolver remain work in progress. Environment reads are sequential, not an atomic snapshot.

`resolver-hostname.bend` checks whether environment or file directives already supply a search list before invoking a hostname source. A failed source leaves hostname fallback absent and retains a diagnostic; otherwise valid settings survive. `resolver-system.loadWith` now combines environment capture, bounded file loading and this lazy hostname step. It returns settings plus any hostname failure, while file/environment failures remain typed terminal errors. `capturedWith` accepts injected environment and hostname sources. Decoder and missing-file policy remain explicit; this still requires option/scope conversion before constructing a live resolver.

The system loader uses the isolated [OS hostname primitive](../../patches/experimental/hostname/README.md), extending the DNS candidate. The addition changes no compiler or existing effects and is not installed. Its native backend calls the OS directly; resolver policy remains pure Bend.

`resolver-system-linux.loadWith` supplies the Linux system-file fallback policy over the strict loader. Open failures with EPERM, ENOENT, EACCES, ENOTDIR, EISDIR or ELOOP use default file settings, retaining the error code/message in `Report.unavailable`; successful reads retain `None`. Environment overrides and lazy hostname discovery still apply. Other open errors, every read error, invalid read size, byte-limit overflow and decoding errors propagate. In particular, opening a directory successfully and then failing to read it is a fatal read error. `parsedWith` and `capturedWith` expose the same policy for injected file results and environment/hostname sources. Linux errno values are isolated in this module; this is not a portable errno mapping or automatic reload.

`ipv6-scope.bend` resolves IPv6 zone text with an injected interface-index source. Interface lookup is permitted only for link-local unicast (`fe80::/10`) and node/link-local multicast; it runs before decimal fallback, even for numeric-looking interface names. Other addresses skip lookup. Numeric indices require a complete nonempty ASCII decimal in 0..2^32−1; leading zeroes are accepted without overflow. A zero interface result is unavailable, while textual zero is a valid scope. Failed lookups fall back to numeric parsing; otherwise `InvalidScope` retains the original text and any source error.

`resolver-scope.resolveWith` converts parsed resolver addresses into the existing connection address type. IPv4 and unzoned IPv6 skip lookup. An invalid zone retains its IPv6 address with scope zero and a diagnostic, matching libc's configuration behavior. These modules implement policy in pure Bend; the OS adapter is provided below, while whole-settings/live-resolver construction remains to be implemented. The combined test fixture uses the isolated connection-capable compiler candidate because its output type imports the connection API.

`network-interface.index` now looks up an actual OS interface index through the isolated [interface-index primitive](../../patches/experimental/interface-index/README.md). Its typed error record keeps errno and message; embedded NUL is rejected before lookup. `resolver-interface.resolve` supplies this source to `resolver-scope.resolveWith`, making named scopes usable in connection addresses without introducing OS effects into the scope parser. The native effect calls POSIX `if_nametoindex`; the Bun effect binds the same OS function on Linux/glibc. Other Bun platforms currently return ENOSYS. This candidate extends `build/bend-hostname-candidate` and is not installed. Whole-settings/live-resolver construction and automatic reload remain unfinished.

`resolver-servers.resolveWith` resolves a complete validated nameserver list in order, returning the existing TCP server values on standard DNS port 53. It preserves duplicates, retains failed scopes as scope-zero endpoints, and reports each failure with its zero-based position in the validated list. Invalid source tokens remain in `Settings.diagnostics` and do not occupy those positions. Empty input returns an empty report; default loopback insertion belongs to settings configuration. This conversion imposes no server-count limit or retry policy.

`resolver-servers.prepareWith` also retains the complete original `Settings` value alongside resolved endpoints. `resolver-interface.resolveAll` and `prepare` supply the OS interface-index source. `resolver-system-servers.loadWith` now composes Linux system-file loading and preparation, preserving file-unavailability and hostname diagnostics as well as all settings and scope diagnostics. It accepts an explicit decoder and read limits. The result still requires search-domain and option interpretation before constructing a live resolver; it does not silently use partially parsed options or trigger network queries. These OS APIs require the isolated interface-index candidate, which remains uninstalled.

`resolver-domains.prepare` converts configured search strings into ordered `dns-search.Domain` values plus positional presentation diagnostics. It normalizes one leading dot, so empty text and `.` represent root while `..` remains invalid. Invalid entries occupy their original positions as `Invalid` values; duplicates are retained. `dns-search.startDomains` uses those values directly. An invalid candidate produces a typed failure when reached, allowing the existing response policy to stop suffix searching and still try the bare name where appropriate. Valid domains are checked again after joining the query base to enforce the complete wire-name length.

`dns-search.start` still accepts a list of wire names. The owned TCP resolver's `Config.domains` and borrowed `Resolver.domains` now use `List<&2, Search.Domain>` so prepared configuration can retain invalid entries faithfully; callers constructing these records from wire names can use `Search.wrapDomains(names, Nil{})` or explicit `Search.Valid` values. Domain preparation does not select option diagnostics policy, add IDNA processing or impose hostname validity rules on DNS label bytes. Whole-settings option conversion remains unfinished.

`resolver-search.prepare` combines explicitly selected option values with typed domain preparation. `Configuration` retains all options and domain diagnostics; search policy is derived when starting a cursor, so there is no separately stored policy that can disagree with those values. Normal system search enables default-name and search-list handling and takes `ndots` and `no-tld-query` from the selected options. Transport/retry/response/reload flags are retained for their respective layers.

`prepareStrict` and `fromSettingsStrict` are explicit strict entry points: any malformed or unknown option returns the complete ordered diagnostic list, without constructing a search configuration from partial values. Strictness applies to options, not unrelated file diagnostics or invalid suffixes (which retain their existing typed candidate behavior). These APIs do not choose the application's OS compatibility policy for malformed options. Successful settings conversion preserves file/environment precedence and existing option caps, and `start` creates the normal immutable search cursor. Transport scheduling, option-driven live resolver construction and application integration remain unfinished.

`dns-edns.bend` encodes EDNS(0) query OPT records and complete single-question messages in pure Bend. `Query` supplies the advertised UDP payload size, DNSSEC-OK bit and ordered opaque `Option` values. Unknown codes, duplicate options, zero-length data and arbitrary octets are preserved. Payload size and option codes must fit U16; option bytes must be octets; aggregate option RDATA must fit U16. `query` additionally checks the complete DNS message's 65,535-byte limit and uses the existing question/ID/flags validation. `encode` returns an OPT record alone, so its RDATA limit is distinct from the complete-message bound.

OPT encoding uses the root owner, type 41, version zero, zero extended RCODE and reserved flags, and ARCOUNT one in a complete query. Advertised payload sizes are serialized verbatim; payload selection and responder interpretation belong to resolver policy. Tail-recursive accumulation avoids a recursive append proportional to large option data. EDNS session transmission, response-option interpretation, negotiation/fallback and option-driven resolver wiring remain unfinished.
