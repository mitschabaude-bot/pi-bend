# Bend runtime foundations

This package supplies primitives missing from Bend 2.0.5 that the faithful pi library port requires. Implementations are pure Bend. The compiler's native backend is used without prototype C effects, host numeric callbacks or JavaScript runtime support. Required compiler changes are explicit in [patches](../../patches/README.md), including opaque channel identity.

`src/ref.bend` provides shared identity and atomic updates over Bend channels. `Ref<A>` is a copyable handle even when A is affine. `modify` owns the value exclusively and takes a pure state transformation; only `Data` values can be copied out by `read`. This lets stream events retain the same live response reference rather than a stale snapshot.

`Ref.same` and `Callback.same` compare identity without observing the stored value or invoking a callback. They use the compiler's `Chan.same` primitive, whose implementation compares its existing opaque handles. Two references containing equal values and two callbacks created with identical code/captures remain distinct. `python3 tests/runtime_identity.py` checks native and JS compiler lowering, runtime aliases, channel slot reuse and type rejection. JS compilation here is only a compiler regression target, not an adapter for native libraries.

`src/deferred.bend` provides first-settlement results and repeated observations. `subscribe` registers an observation before returning its single-use ticket; `wait` consumes that ticket. Waiting, late and repeated observers receive the original result. `result` combines registration and waiting. `peek` reads settlement without waiting and preserves the distinction between pending and a supplied value. Resolving a shared reference preserves its identity.

`src/abort.bend` implements the abort-state foundation: typed `AbortController`/`AbortSignal` handles, first-reason settlement, `aborted`, `reason`, and `throwIfAborted`. The last function returns a recoverable `Result` in Bend. Omitted reasons allocate a shared default error with Node's name/message/code; supplied reasons, including false, zero and explicit null representations, retain their identity. Repeated aborts leave the original reason intact. These are a subset of the [DOM abort contracts](https://dom.spec.whatwg.org/#aborting-ongoing-activities), not a complete AbortSignal implementation.

Native abort `observe` returns a removable deferred observation; it is not an EventTarget listener. Cancellation unlinks that observation without aborting the signal. The receiving owner must consume its ticket even after cancellation to release the reply channel. Dependent/combined signals, timeout signals, full DOMException behavior, complete listener options and automatic lifetime reclamation remain pending. Native observations may wake before synchronous abort callbacks finish; they are not JavaScript Promise reactions and cannot substitute for the pi abort-race utility. The model store and pi abort utilities remain unported, including promise-reaction scheduling and abandoned-rejection handling. Abort tests cover preflight results, falsy reasons, early/late observations, shared reason identity, caller ownership, 100 concurrent abort attempts and 1,000 cancellations on a never-aborted signal, on one and four threads.

Abort signals now compose the shared EventTarget dispatcher. `AbortController<Reason, Error>` and `AbortSignal<Reason, Error>` separate abort reasons from listener failures; constructor calls receive the runtime's shared clock and reporting queue explicitly. Function listeners receive the complete signal as `this` and `event.target`, including its settled reason. Only the atomic abort winner creates and synchronously dispatches one trusted, noncancelable `abort` event. Repeated/reentrant aborts preserve the first reason and do not dispatch again. The signal owns that event until disposal so retained callback references remain usable after dispatch. All event/signal aliases and dispatches must retire before owner disposal; supplied reasons, callbacks and reporting queues remain caller-owned.

Signals expose `addEventListener`, `removeEventListener` and `dispatchEvent` through the same machinery as ordinary targets. Explicitly dispatching an untrusted event named `abort` does not set `aborted` or `reason`. `python3 tests/abort_event_vectors.py` compares 24 Node 24.18.0 traces covering trusted versus explicit dispatch, callback state/identity, once/passive options, removals, reentrant/repeated aborts, late registration, retained events and listener errors, on one and four threads. A native check verifies that 100 competing abort calls dispatch exactly once even with a reentrant listener. These host-runtime prerequisite tests do not mark a pi-mono suite complete; next-tick error delivery and Promise scheduling remain open.

`src/event-handler.bend` implements a shared on-event property slot for callable/null values. The first assignment registers one stable callback wrapper, including when the assigned value is null. Replacements retain its listener position; null clears the current callback without removing the wrapper. Dispatch reads the current callback when that wrapper is reached, preserving mutations made by earlier listeners. The getter returns the original callback identity. Registering that callback separately remains a separate listener, and removing it does not remove the property's wrapper. Callback failures propagate to the enclosing EventTarget reporting queue. The slot owns its wrapper and shared cell, but not user callbacks.

AbortSignal exposes this slot through `onabort` and `setOnabort`, explicit Bend adaptations of the property getter/setter. Abort construction now takes compile-time reason/error type arguments (`A.new(~Reason, ~Error, clock, reports)`) so Bend can specialize its reusable wrapper factory. `python3 tests/onabort_vectors.py` compares 32 Node traces on one/four threads for first-null assignment, replacement/clearing, interleaved listeners, mutation during dispatch, independent registrations/removal, callback identity, actual aborts and failure payload/order. Dynamic non-callable assigned values, property descriptors and Node listener-count hooks remain unimplemented; this is not a claim of complete event-handler property semantics.

`src/listener-registry.bend` implements the internal listener collection and live traversal needed by EventTarget. Registrations match by normalized event type, exact callback identity and capture; duplicate adds preserve their original once/passive flags. Registration keys encode live next-links. Each step caches the next link and removes a once listener before the dispatcher invokes user code. Removed nodes keep their old links while any walk remains active, so removal and re-addition do not revive old registrations. Closing the final walk releases retired nodes; an early exit must consume its cursor with `close`. Callbacks remain caller-owned and are never invoked while registry state is locked.

`nextWith` lets the EventTarget layer decide whether to call, skip or stop before once removal. The decision is pure and can inspect the current registration, including a retired node. Skipping preserves once; stopping closes the walk immediately. The composed dispatcher and basic abort integration are described below and above; complete signal options, object listeners and automatic listener error reporting remain required work. This internal collection is not the complete EventTarget API.

`python3 tests/listener_vectors.py` compares native traversal with 36 actual Node 24.18.0 EventTarget traces on one and four threads: twelve explicit cases and 24 seeded mutation sequences. Adding from the only listener waits until the next dispatch; adding while another original listener remains can run in the same dispatch. Nested dispatch and removed-node chains are included. Native concurrency/lifetime tests additionally check 64 competing duplicate registrations, once claims and removals, UTF-16-equivalent names, preserved options, skip/stop decisions and early-cursor cleanup. Lookup and mutation currently scan persistent lists; links preserve source behavior but large-list performance still needs evaluation. Retired-node reclamation is coarse at the final active walk, and general shared-object reclamation remains open.

`src/event.bend` implements the shared state and typed property/method operations for Node Event. It preserves cancellation and propagation flags across redispatch and legacy `initEvent`, masks default prevention when cancelable is false, suppresses cancellation in passive listeners, and retains shared target identity. Dispatcher hooks distinguish successful callback return from a throw: the Node reference clears its dispatch flag only after a successful listener return, so later listeners can observe phase NONE and null currentTarget. The final exit hook clears the flag in either case. Recursive dispatch produces a recoverable typed error with Node's name/code/message; full error-object/stack behavior remains pending.

Two source names need explicit Bend adaptations: `WebEvent` avoids Base's existing window-input `Event`, and `eventType` replaces the reserved keyword `type` in the record and getter. `Properties` is an internal snapshot for inspection, not a replacement wire format or mutable event object. Other property/method names are retained. Target nullability uses `Maybe`, and targets remain caller-owned after event disposal.

`createAt` remains an internal factory taking an explicit binary64 timestamp and trust flag. `new` now obtains its timestamp from a supplied runtime `Clock` and always creates an untrusted event. Passing the shared clock explicitly is the Bend adaptation of Node's implicit process clock. Canonical runtime startup still needs to create and share that origin; this does not claim that independently created clocks share Node's process-start timestamp. The typed EventTarget dispatcher is described below; Web IDL conversion at dynamic boundaries, object/property-descriptor behavior, automatic exception reporting and managed lifetimes remain open. No complete Event/EventTarget API is claimed from this state layer.

`python3 tests/event_vectors.py` compares 17 actual Node 24.18.0 traces with 147 property checkpoints on one and four threads. It covers all constructor-flag combinations, passive cancellation, both stop methods, legacy setters/init, recursive-dispatch errors, callback-phase changes and the throw cleanup path. The fixture drives state hooks using the observed host lifecycle; it does not implement or test a native EventTarget dispatcher or error reporter. Native tests separately verify event/target aliases, live target mutations, redispatch, target ownership and exact binary64 timestamp retention.

`src/event-target.bend` composes the event state and live listener registry into `Dispatcher<Host, Error>`. Ordinary `EventTarget<Error>` wraps this machinery while retaining its public methods; derived targets supply their actual receiver type. This is the typed Bend adaptation of inherited EventTarget behavior, not a detached base target substituted for a signal. The current synchronous-listener interface receives an affine pair of the actual target (`this`) and shared event, and returns a recoverable `Result` for listener failure. `addEventListener` and `removeEventListener` retain callback identity/capture matching. Null listeners are ignored for registration/removal, but Node's add-listener warning is not implemented yet. Their current options are resolved capture/once/passive flags. `dispatchEvent` returns the cancellation result or a recursive-dispatch error, preserves Node's callback/phase behavior, and closes every completed/stopped traversal. Listener failures do not stop subsequent listeners and preserve the distinct throw cleanup path.

Targets share a caller-owned `ReportQueue<Error>`. Dispatch appends failures in order without invoking user error handlers. `takeReportedError` is an internal runtime/test observation boundary; automatic next-tick delivery, callback-turn scheduling and process error policy are still unimplemented. This queue must not be drained early as a replacement for Node's next-tick scheduling. Targets do not dispose their shared queue or callbacks, and owners must consume pending reports before disposing the queue. Promise/thenable return observation, object listeners with dynamic handleEvent, signal options, internal resistant listeners, null-listener/count warnings, dynamic argument conversion and managed lifetimes remain pending. This is a partial EventTarget implementation, not a completed cancellation runtime.

`python3 tests/listener_vectors.py --event-target` now runs all 36 reference traversal cases through the production dispatcher, including reentrant once handlers, live additions and callback this identity. `python3 tests/event_target_vectors.py` compares ten additional Node traces for passive/default cancellation, both stop methods, callback phases, recursive dispatch, repeated dispatch and FIFO listener errors. Both run on one and four threads. A native shared-queue check also preserves cross-target error order after disposing the first target. The error comparison consumes the queue after dispatch and verifies payload/order; it does not claim automatic error delivery or returned-promise handling.

`src/clock.bend` reads exact monotonic nanoseconds through the new `IO.monotonicNanoseconds` compiler primitive. The primitive returns high/low U32 words; its native effect reads the existing OS monotonic clock and its JS-backend effect uses `process.hrtime.bigint`. Clock origin handling and numeric conversion are pure Bend. A `Clock` captures one origin, and copies keep it; initialize it once before runtime callbacks start. `elapsed` subtracts unsigned 64-bit ticks before converting the interval to binary64 and dividing by one million, matching the evaluation order in [Node's PerformanceNowImpl](https://github.com/nodejs/node/blob/v24.18.0/src/node_perf.cc#L284). Raw epochs are unspecified, and subtraction follows the counter's modulo-2^64 representation.

`python3 tests/clock_vectors.py` checks 276 exact-bit interval vectors against Node numeric arithmetic, including nanosecond intervals at epochs beyond binary64 integer precision, conversion ties, word carries and counter wrap. Native one/four-thread and Bun-hosted JS-backend tests check monotonic ordering, timer liveness, cross-task epoch consistency and clock-backed Event construction. The JS host is Bun because the existing sleep effect uses bun:ffi; Node supplies the independent numeric oracle. They do not compare absolute clock origins across processes or establish real-time scheduling guarantees. The compiler patch is explicit under `patches/`; native clock policy uses no host floating-point or library adapter.

`Deferred.observe` returns an affine `Observation` containing a single-use `Ticket<Maybe<A>>` and a copyable `Cancellation<A>` handle. `cancel` atomically removes the pending waiter; its true result identifies the cancellation winner. Cancellation delivers `None`, whereas settlement delivers `Some(value)`, including `Some(None)` when the actual value is optional. Exactly one side owns delivery, and duplicate or post-settlement cancellation returns false. Arbitrary-precision registration keys prevent stale handles from matching later observations after integer wraparound. The original `subscribe`/`result` API remains available for required observations. Native tests verify removal, neighboring required/removable waiters, late observation, stale handles across a 64-bit counter carry, optional results, 64 simultaneous cancellation attempts with exactly one winner, and 128 settlement races. Cancellation handles must retire before their source is disposed.

`src/callback.bend` provides reusable first-class callback handles despite Bend's affine closures. Construction supplies closed callback code and a typed runtime capture environment; libraries subsequently accept and store the resulting runtime `Callback<Input, Output>` value. Each call obtains a fresh affine closure and releases the factory before invoking user code, allowing concurrent async calls. Inputs and outputs may themselves be affine. The factory uses one explicitly documented guarded `@unsafe` corecursion: construction returns a closure, and each invocation constructs one successor. There is no background actor or artificial invocation limit.

These shared primitives currently require owner-directed disposal after aliases and observers retire. The current Bend channel runtime does not reclaim live channel rows merely because handles are dropped. Automatic shared-object reclamation therefore remains a language/runtime prerequisite for JavaScript-equivalent object lifetimes. These primitives do not establish completion of pi's event-stream or subscription semantics. The generic stream has separate upstream tests in `packages/ai/test/event-stream.bend`.

`src/u64.bend` implements unsigned fixed-width arithmetic modulo 2^64, bit operations, logical shifts, rotations, comparison, and quotient/remainder division. Values use two U32 limbs, ordered high then low. Division by zero returns `None`; shifts of at least 64 bits produce zero; rotations reduce their count modulo 64. `multiplyWords` exposes the exact 32-by-32-bit product needed by wider arithmetic.

`src/u128.bend` provides exact 64-by-64-bit multiplication and wide intermediates with sticky-bit shifting. It is used to retain the full product before binary64 rounding.

`src/f64.bend` represents every IEEE-754 binary64 bit pattern and implements addition, subtraction, multiplication and division with round-to-nearest, ties-to-even. It retains signed zeros and subnormal results. Arithmetic NaNs become a canonical quiet NaN; payload preservation is not an API guarantee. Comparisons return `None` for unordered NaN operands and treat signed zeros as equal. Unsigned integer conversion rounds directly from the 64-bit integer. Alignment retains guard, round and sticky bits; cancellation and underflow are normalized before the final rounding. Operations never pass through F32. Decimal parsing and remaining numeric operations are still required before full integration with pi's number APIs; base-10 formatting is implemented separately in `f64-decimal.bend`.

Run the independent vector tests from the repository root:

```sh
python3 tests/u64_vectors.py
python3 tests/f64_vectors.py
sh tests/runtime-concurrency.sh
```

Python generates expected results from arbitrary-precision integers and host binary64 arithmetic. It writes constant input/output vectors, then compiles and executes Bend assertions. Python supplies no behavior to the implementation or native executable. The tests currently cover 272 unsigned/wide arithmetic vectors and 1,077 floating-point vectors, each checking all four operations, comparison and integer conversion. These tests supplement, rather than replace, the future port of pi's numeric and model-cost tests.

Concurrency tests check retained reference identity, 1,000 competing updates, affine ownership, result fan-out, ignored duplicate settlements, repeated callback invocation, and overlapping async callback calls. Gates and explicit registrations coordinate the tests; no sleeps are used to guess scheduling order.

`src/fifo.bend` supplies the persistent two-list FIFO used by the event stream and per-iterator request queues. Enqueue/dequeue are amortized constant time along a queue history; transferring incoming values reverses the list only when the outgoing side empties. Stream tests cover buffered and waiting-consumer ordering across transfers.

`src/record.bend` represents own enumerable string data properties, with replacement/deletion and JavaScript object key enumeration: canonical array indices below 2^32-1 are numeric, and other keys retain insertion order. It is distinct from JavaScript Map ordering and does not implement prototypes, accessors or symbol properties. Operations currently scan persistent property lists, suitable for small metadata/section records; large dynamic-object integration may need a different storage implementation. `python3 tests/record_vectors.py` checks 50 deterministic mutation sequences against actual JavaScript own-property enumeration, including index boundaries, leading zeros, Unicode names and deletion/reinsertion. JavaScript is a test oracle only.

`src/ordered-map.bend` provides the distinct insertion ordering required by JavaScript Map for string keys. Numeric-looking keys retain insertion order, replacement keeps the old position, and remove/reinsert appends. Tool replay uses this map rather than object-property order. The shared differential runner now checks 50 mutation sequences against actual JavaScript Map as well as 50 against own-property records. Both persistent list implementations have linear operations; large-scale storage optimization remains separate from their ordering contracts.

`src/big-nat.bend` implements exact unsigned arbitrary-precision integers for decimal/binary64 conversion. Values have canonical little-endian 16-bit limbs; zero has no limbs. Addition, comparison, nonnegative subtraction, multiplication, left shift, powers and quotient/remainder division use only Bend U32 arithmetic. Subtraction returns `None` for a negative result; division returns `None` for a zero divisor. `divideSmall` additionally requires a divisor of at most 65535; general division has no such restriction. Decimal integer parsing rejects signs, whitespace, fractions and exponents, accepts leading zeros, and normalizes zero. Decimal output uses an input-size-derived digit bound, not fixed precision. No host arithmetic or string formatting supplies production results.

`python3 tests/big_nat_vectors.py` checks 179 independent Python-integer vectors, plus power/construction/input cases. Coverage includes limb boundaries, carries/borrows, zero divisors, out-of-range small divisors, 2048-bit operands, 2^1074 and 5^1074, and exact decimal round trips. The native executable does not invoke Python.

`src/f64-decimal.bend` implements shortest base-10 binary64 spelling using exact integer rounding intervals. It tests both adjacent decimal candidates at each precision, respects inclusive/exclusive binary midpoints (including the asymmetric lower interval at normal powers of two), and chooses the closest admissible decimal with ties to an even coefficient. It emits ordinary or scientific notation according to [ECMAScript Number::toString](https://tc39.es/ecma262/multipage/ecmascript-data-types-and-values.html#sec-numeric-types-number-tostring). Both signed zeros become `0`; non-finite number strings remain `NaN` and signed `Infinity`.

`toDecimal` returns `Maybe<String>`: an impossible denominator or exhausted format-derived bound remains an explicit failure instead of producing an approximate value. Normalization is bounded by binary64's denominator bit count; digit selection checks up to seventeen significant places. These are format guarantees, not user-input precision caps. `toJsonNumber` additionally maps non-finite values to `null`, matching [JSON numeric serialization](https://tc39.es/ecma262/multipage/structured-data.html#sec-serializejsonproperty).

`python3 tests/f64_decimal_vectors.py` compares 1,092 bit patterns against JavaScript's actual number spelling, with additional JSON numeric checks. Coverage includes signs, dense small subnormals, the subnormal/normal boundary, maximum finite values, powers of two and ten with adjacent bit patterns, ordinary/scientific cutovers, explicit decimal midpoint ties in both directions, and seeded random patterns. JavaScript supplies expected test strings only. This is an exact reference implementation, not a performance-tuned conversion algorithm; whole-provider serialization performance still needs evaluation.

Decimal-to-binary64 parsing and full live-object JSON serialization remain pending; serialization of the explicit pi-ai `JsonValue` union is implemented separately. The bootstrap JSON encoder's preserved decimal tokens still cannot replace the canonical codec or establish correct tool-declaration comparison.

`src/utf16.bend` canonicalizes string representation by merging valid adjacent surrogate pairs into scalar characters, retaining unpaired units. It does not perform Unicode spelling normalization. Record and ordered-map key insertion, lookup and removal use this representation so scalar and surrogate-pair spellings identify the same JavaScript string key. `src/json-string.bend` quotes that representation, escaping controls and unpaired surrogates while preserving ordinary Unicode. The canonical `JsonValue` codec uses these helpers. JavaScript differential tests and native map-identity tests run through `sh tests/json.sh`; existing record/Map ordering tests remain separate.

`src/schema-value.bend` represents finite schema data trees with explicitly typed opaque symbol/callable metadata, string-property enumerability and symbol-keyed properties. `snapshot` projects JSON-visible data: omitted object fields are removed, omitted array values become null, non-finite numbers become null, and negative zero becomes positive zero. A root omission stays distinct from null; callers emulating `JSON.parse(JSON.stringify(root))` must reject it. Visited BigInts produce an explicit error; ignored properties are not visited. A callable own `toJSON` produces `UnsupportedToJSON`, including when non-enumerable, so it cannot silently change behavior by being dropped.

`python3 tests/schema_value_vectors.py` compares 156 inputs against actual JavaScript JSON round trips and canonical pi-ai serialization, including twelve fixtures from the pinned TypeBox builders and checks explicit hook failures and 2,000-level nesting. This data-only projection does not implement live object identity, cycles, prototypes, accessors or hook invocation. It is a prerequisite for schema snapshots, not the TypeBox builder/validator API or completed tool-declaration comparison.

`src/date.bend` implements `Date.now` over exact signed Unix milliseconds from the explicit compiler primitive. It remains separate from `Clock.now`, whose epoch is an elapsed-time origin. Integer words are converted to binary64 entirely in Bend, including pre-epoch negative values; no F32 conversion is involved. This is not the Date constructor, parsing, formatting, timezone or full Date API. `python3 tests/date_vectors.py` checks 146 signed conversion bit patterns and live native/JS-backend readings against host wall-clock call bounds. System-clock adjustments remain observable; the wall clock is not guaranteed to be monotonic.

`F64.isInteger` classifies the stored binary64 value without decimal conversion or F32 rounding. Signed zeros are integers; subnormal fractions, NaNs and infinities are not. For finite values, restoring the significand after removing fractional bits must reproduce it exactly. The validation predicate differential tests cover this operation across exponent boundaries and random bit patterns (`python3 tests/validation_primitives_vectors.py`).

`src/f64-ratio.bend` converts an arbitrary-size unsigned numerator/denominator pair and explicit sign to binary64 with exact round-to-nearest, ties-to-even. A zero denominator returns `None`; zero numerators retain the supplied sign. It searches monotone positive encodings using integer comparisons in units of the smallest subnormal, then compares the exact midpoint of adjacent values. A virtual `2^1024` endpoint supplies the correct overflow midpoint. Sixty-three bisections cover the encoding interval; this is a proof-derived bound, not a precision or input-size cap. Numerator and denominator are never independently rounded or converted to host numbers.

`python3 tests/f64_ratio_vectors.py` checks 226 cases against Python's independent exact-rational conversion on one/four threads. Cases include both signs of zero, zero denominators, ties and close neighbors, subnormal/normal boundaries, odd/even significands, overflow, random large ratios, and 1,000-digit operands whose ratio remains near one. This reference-quality conversion is the rounding dependency for numeric parsing; numeric-string grammar, parsing and validation coercion are not implemented by this module. Throughput optimization remains open.

`src/number-string.bend` implements the string domain of ECMAScript `Number`: trimming the specified whitespace/line terminators, empty-string zero, signed decimal/exponent forms, signed infinity, and unsigned binary/octal/hexadecimal forms. Invalid trailing text, signed radix prefixes, numeric separators and BigInt suffixes produce NaN. It follows the [StringNumericLiteral grammar](https://tc39.es/ecma262/multipage/abstract-operations.html#sec-stringtonumber); it is not `parseFloat` and does not perform arbitrary-object coercion. Decimal/radix mantissas accumulate in exact `BigNat` values and use `f64-ratio` for the final rounding. Exponent saturation depends on mantissa length plus a binary64 range bound, so enormous exponents produce the correct zero/infinity without an arbitrary digit limit or exponent-sized allocation. Zero retains its sign even with enormous exponents.

`python3 tests/number_string_vectors.py` compares 365 inputs against JavaScript's actual `Number` conversion on one/four threads, preserving negative-zero bits and checking NaNs explicitly. Coverage includes all accepted whitespace code points and rejected lookalikes, surrogate inputs, malformed syntax, three radix forms, exact rounding midpoints, subnormal/overflow boundaries, long mantissas and exponents, and seeded decimal cases. Runtime conversion is pure Bend; Node supplies expected test values only. This is a reference-quality parser; integration into schema coercion and provider codecs and performance tuning remain pending.

## Shared runtime values

`src/value.bend` adds a shared graph representation alongside the existing finite schema trees. Scalars retain undefined/null, binary64, strings, BigInts and typed opaque symbol/function identities. Objects and arrays hold shared storage cells; repeated references and cycles therefore retain identity. Object storage has ordered string properties, symbol descriptors, an explicit prototype edge and extensibility. Data/accessor descriptors retain their flags and typed getter/setter metadata. Array storage separates length and length writability from indexed descriptors, preserving the distinction between a missing index and a present `undefined` value.

`newObject` and `newArray` allocate distinct cells. Their prototype argument is explicit: `None` means a null prototype; standard realm prototypes are not implicitly fabricated. `strictEqual` compares aggregate storage identities without reading graph contents, compares strings as UTF-16 sequences, preserves NaN/signed-zero rules, and delegates symbol/function identity to a supplied pure metadata comparator. `typeOf` preserves source language tags, including `object` for null and arrays.

`python3 tests/runtime_value_vectors.py` checks 676 scalar equality pairs and 26 scalar type tags against JavaScript, plus native aggregate type/identity checks and graph tests on one/four threads. Fixtures distinguish equal-content objects, retain self/shared/prototype edges through mutation, preserve sparse indices and explicitly retire cycle edges before releasing owned cells. This is storage and identity infrastructure: descriptor operations, prototype lookup, array-length invariants, getter invocation, built-in/exotic objects, structured cloning, garbage collection and schema-coercion integration remain unfinished. Raw storage construction is not a replacement for those operations. The existing schema-tree API remains in use until its consumers are migrated.

`src/object.bend` adds `ownKeys` and `getOwnPropertyDescriptor` for ordinary object and array storage. Inspection includes non-enumerable and symbol properties, excludes prototypes, retains descriptor flags/getter/setter identities and never invokes accessors. String keys follow array-index/insertion ordering; symbols follow string keys in insertion order. Array `length` is synthesized as a non-enumerable/non-configurable descriptor with its current value/writability and appears after indices but before user string keys. Each operation reads the current shared cell; previously returned key lists stay independent of later mutations. Array storage must obey the documented index/length invariants.

`python3 tests/object_inspection_vectors.py` compares 24 key orders and 384 descriptors against actual `Reflect` operations on one/four threads, including maximum array indices, hidden/accessor/symbol properties, UTF-16 keys, readonly lengths and inherited-property exclusion. It also checks live mutation, independent prior key lists and explicit error outcomes. Non-object inputs return `NotObject`; callable-object reflection returns a distinct `UnsupportedCallableObject` until function storage is implemented. This is typed internal reflection, not a JavaScript host bridge; primitive boxing, proxies/exotics, property writes/lookup and cloning remain unfinished. These tests require the explicit static-layout compiler patch documented in `patches/README.md`.

`object.deleteProperty` adds Reflect-style deletion for ordinary objects and arrays. Missing/inherited-only keys succeed without touching the prototype. Non-configurable data/accessor properties return false; writable/enumerable/extensible flags do not independently prevent deletion. Successful deletion preserves the order of surviving string/symbol keys. Array element deletion leaves a hole and retains length/writability; deleting `length` returns false. Descriptor lookup and mutation occur within one pure `Ref.modify` transaction. Getters/setters are never invoked, and existing aliases see the updated storage. Strict-language callers must translate a false result into their required exception; this primitive retains Reflect's boolean result.

`python3 tests/object_delete_vectors.py` compares 16 sequences and 384 successive mutation results with actual `Reflect.deleteProperty` on one/four threads. Every step checks success, remaining key order, the queried descriptor and array length. It covers repeated deletion, configurable/non-configurable accessors, hidden/symbol/UTF-16 keys, readonly lengths, non-extensible objects and inherited-property exclusion, with explicit prototype/extensibility preservation checks. Reflection regression tests also check deletion's non-object and unsupported-callable errors. Property definition, assignment, getter/prototype lookup, cloning and schema-coercion integration remain pending.
