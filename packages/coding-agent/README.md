# Coding agent

Canonical port of `pi-mono/packages/coding-agent`. This package is under construction; the executable in the repository's `src/` remains the earlier bootstrap prototype.

`src/core/tools/truncate.bend` implements shared head/tail output truncation, grep line truncation and byte-size formatting. It preserves Pi's result fields, default limits, trailing-newline counting, line-limit precedence and UTF-8 suffix boundaries. Limits are natural numbers, with explicit optional overrides. `truncateLine` retains the UTF-16 budget but preserves whole native characters instead of producing an isolated surrogate at a split supplementary character. Native characters cannot contain isolated surrogates.

`python3 tests/tool_truncate_check.py` compares the implementation directly with the pinned TypeScript module, including both limits, zero budgets, default boundaries, terminal newlines, multibyte text and BOM retention. The whole-character grep policy is the only expected-output adaptation. All 1,152 comparisons pass on Bun and native one/four threads. The proved `fitting_text_is_preserved` law establishes exact preservation, including metadata, for every text and either direction whenever both limits are satisfied. Bounds and idempotence for truncated output still lack general proofs; the differential checks do not substitute for those proofs or establish that the read/bash/grep tools themselves are ported. Tool execution, extensions, session management and terminal integration remain unfinished.

`src/core/tools/file-mutation-queue.bend` serializes operations by canonical filesystem path, including symlink aliases, while independent paths proceed concurrently. Registration is ordered through a shared queue owner supplied to the tool bundle; operations return typed results and retain their reservation until they settle. Missing paths use their normalized absolute spelling, matching upstream. `tests/file_mutation_queue_check.py` exercises the first three upstream queue contracts on Bun and native one/four threads, plus error recovery, aliases and resource retirement. The four complete public write/edit integration scenarios remain pending; the write execution core already has separate in-flight cancellation coverage.

`src/core/tools/write.bend` supplies `createWriteTool`, its schema and sampling metadata, exact success text, unit details, input decoding, and injectable filesystem operations. Callers supply the shared mutation queue and a path environment; `borrowTool` returns the executable `AgentTool`, and `disposeTool` retires its callback and any default operations it owns. Injected operations remain caller-owned. Cancellation is checked before mkdir, after mkdir and after write, retaining the reservation until in-flight IO settles and preserving an operation failure over a simultaneous abort. `tests/write_public_check.py` and `tests/write_tool_check.py` pass on Bun and native one/four threads for public results, actual bytes/overwrites, parent creation, path handling and cancellation. Extension `ToolDefinition`/context overrides, prompt metadata and terminal renderers remain unfinished.

`src/utils/paths.bend` implements POSIX `normalizePath`, `resolvePath` and `resolveToCwd`: optional trimming, Unicode-space normalization, `@` stripping, tilde expansion and local file URLs through the existing URL parser. `Environment` carries explicit cwd/home/URL policy; `loadEnvironment` obtains process directories through the byte-preserving OS primitives. `tests/coding_paths_check.py` runs 291 comparisons against the pinned Pi source under Node on Bun and native one/four threads, including relative home overrides and rejected URI encodings. Node supplies the reference builtins; its unused Windows process dependency is guarded by a test-only import hook that throws if called. Windows shell paths and read-specific macOS filename variants remain pending.

`tests/native-write-agent.bend` connects the canonical write tool to the same modular model loop used by `tests/native-agent.bend`. Its HTTPS integration checks real file creation before the next model request, exact replayed tool arguments/results, schema rejection without filesystem changes, and a nonzero exit for terminal provider failure after cleanup. All three cases pass on Bun and native one/four threads. Native validation used the captured `4691266` integration source and an isolated compiler candidate with the existing layout cap; that compiler candidate is not globally installed. The individual write tool also passes native tests as described above. This runner is an integration entry point, not the complete coding-agent CLI.

`src/core/tools/read.bend` implements the pure text result: offset/limit selection, end-of-file errors, truncation details and continuation notices. `tests/read_text_check.py` compares 450 cases with the extracted, otherwise unchanged text branch of pinned `read.ts` on Bun and native one/four threads. One intentional rendering improvement quotes the filename and adds `--` in the oversized-line shell fallback; the harness also checks that shell tokenization preserves the exact filename. Natural offset/limit values include zero, matching upstream's first-line/empty-selection behavior. Fractional and negative counts cannot reach this operation; the eventual public decoder must reject them. Read IO, cancellation, injectable operations and public tool metadata are now implemented (see `tests/read-tool.md`); default image processing and terminal rendering remain pending, so this is not yet a complete read tool. No general read law is claimed from these concrete comparisons.

A real OpenAI call through the native loop and canonical write tool generated the reusable `Strings.quoteShell` helper, now used by read fallback instructions. Two follow-up model calls supplied compiler feedback before the helper compiled; the host then integrated it and reran the 450 read comparisons on all three backends, including shell-tokenization checks. This exercises native model-driven file writing and revision. Only the write tool was supplied in that run; autonomous read/edit/bash development and the complete CLI are still unfinished.

`src/utils/image-convert.bend` connects native format decoding, EXIF orientation and PNG encoding. `convertImageBytesToPng` returns optional encoded bytes; `convertToPng` preserves PNG-labelled input and otherwise converts decoded Base64 into a PNG result. A bounded entry point exposes pixel and output-byte limits. PNG and BMP are integrated; GIF, JPEG and WebP dispatch remain pending. Unsupported/malformed conversion returns `None`; non-PNG Base64 is parsed strictly rather than accepting Node’s permissive malformed input. Compression bytes can differ from Photon while preserving pixels. `tests/image_convert_check.py --photon PATH` checks 72 conversion pixel results against pinned Photon and 60 budget/pass-through/error cases on Bun and native one/four threads. This does not establish full image-processing, read-image or terminal parity.
