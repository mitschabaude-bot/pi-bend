# Reviewed upstream source coverage

The [review records](source-coverage-reviews.json) name upstream modules whose Bend coverage has actually been checked. Each record gives a state (`partial`, `ported`, `missing` or `excluded`), a concise finding and the source hash reviewed. A same-path Bend target is inferred only for validation; relocated targets are listed explicitly. This is a small set of reviewed findings, not a complete port roadmap or a completion percentage.

The concrete use is to retain findings such as the missing `/thinking` selector: its upstream source is `packages/coding-agent/src/modes/interactive/components/thinking-selector.ts`, while the persisted thinking setting and model cycling live elsewhere. When that selector is ported, review its behavior, change this record and add the relevant terminal parity scenario. The [test inventory](../tests/upstream-inventory.json) separately tracks upstream test suites; it does not establish source-level completeness. Most upstream modules have no source review yet.

`python3 scripts/test-inventory.py` checks both records against the pinned pi checkout. For source reviews it checks the upstream revision and reviewed file hashes, verifies that named Bend targets exist, and rejects a `ported` record without a target or a `missing` record with one. New upstream files and unreviewed modules are not silently classified by filename. To find work, inspect the relevant upstream package and its tests directly; add a review record when there is a meaningful coverage finding.
