# Responses streaming error rendering

`openai-responses-stream-error` renders the typed reader and processor failures without participating in retry decisions or changing the stored cause. Callback failures delegate to the supplied renderer. Content and terminal failures retain their existing provider diagnostics. Native protocol errors identify literal field names with JSON-quoted brackets and distinguish array indices from numeric field names. Invalid SSE JSON uses the existing native parser's cause vocabulary; it does not imitate engine-specific `SyntaxError` wording or repeat the diagnostic block in the primary message.

Streaming API errors reuse the native HTTP error message-field policy but have no status prefix: an SSE error delivered over HTTP 200 is not an HTTP status failure. The implementation preserves present numeric and boolean message values under the existing explicit-value policy. If a diagnostic cannot be serialized, the formatter returns a typed `NonJsonBody` failure instead of silently inventing an explanation.

Eight generic laws cover independence from SSE debug context and preservation of transport, diagnostic callback, read, emit, service-tier, pricing and terminal messages. The laws check with the existing isolated compiler; no experimental IO-conversion patch is required. They remain outside the active root gate. Three type-correct mutations that erase read, diagnostic or terminal causes are rejected; the [proof record](proof-validation/2026-09-21-stream-error-standalone.json) retains the checked statements, compiler hashes and mutation results.

The native one/four-thread and Bun fixture compares twelve API payloads with OpenAI SDK 6.40.0 and the pinned pi error formatter, including nested values, Unicode and a 4,500-character message. It separately checks the existing false/zero-message adaptation and native protocol paths containing punctuation, quotes and emoji. The [runtime record](runtime-validation/2026-09-21-stream-error.json) contains 45 successful processes and 51 checked diagnostics. This is a rendering component, not the completed system-provider renderer: native transport/configuration, acquisition and compound cleanup errors still need their full boundary assembly.
