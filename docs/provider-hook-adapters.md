# Typed provider hook adapters

`provider-hook-map` adapts caller-owned payload/response callbacks into a provider's error type. It preserves the hook inputs and successful values, embedding only failure causes with the supplied function. An absent payload replacement stays absent; an explicit null remains a supplied payload value. The adapters own their callback handles and borrow the original callbacks until disposal.

The affine `Owner` lends a reusable `Hooks` record. Disposal retires payload and response adapters in order and leaves the original callbacks usable. Creating an absent hook does not allocate an adapter; retiring one performs no effects. The provider must retain the owner through all request-hook invocations and dispose it after acquisition has stopped using the hooks.

Seven generic laws cover successful output preservation, failure embedding, owner borrowing, absent/present retirement and ordered retirement of both adapters. The [completed full gate](proof-validation/2026-09-21-provider-hook-map.json) checks 455 public laws and 67 supporting lemmas and rejects 246 typed mutations, including lost borrowed hooks and skipped adapter retirement. The [runtime record](runtime-validation/2026-09-21-provider-hook-map.json) contains 120 cases across plain/audited native one/four threads and Bun. It checks every presence combination, payload/model/response forwarding, absent replacement versus explicit null, hook failures, exact call counts and use of the original callbacks after adapter disposal. All audited channel/IO counters finish at zero.

`provider-hook-options.create` now installs these adapters into canonical request options and returns the owner alongside those options. Two additional generic laws prove exact hook installation and preservation of every non-hook field across error types. Their standalone proofs pass; they are not yet registered in the root. Another [120 runtime cases](runtime-validation/2026-09-21-provider-hook-options.json) exercise the same hook outcomes and lifetimes through this options bridge, across all six backend/audit combinations.

The public Responses provider still needs to transfer the returned owner into session cleanup. These modules alone do not complete that integration or promote an upstream suite. Developing the fixture also exposed the separately documented [nested-pattern loading cliff](bend-issues.md#bend-025--nested-string-patterns-amplify-fallback-bodies-during-loading); the final assertions use explicit string equality and retain the same input/result checks.
