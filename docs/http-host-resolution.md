# Typed HTTP host resolution

`http-url.Endpoint` already retains `url-host.Host`. `http-host-route` consumes that value directly: an IPv4 or IPv6 variant yields the exact shared connection address, and a nonempty domain yields its unchanged name for lookup. Empty and opaque host variants fail as invalid HTTP hosts. URL IPv6 values have scope zero; scoped numeric destination strings use the separate numeric scope API. This layer does not serialize, reinterpret, normalize or parse host text again. Existing URL parsing determines the typed value, including its URL-specific numeric normalization.

The generic effectful dispatcher calls its injected name resolver only for a domain plan and wraps its entire report without flattening failures or metadata. `http-host-resolver` supplies the concrete paired hosts/DNS adapter using a borrowed persistent resolver, parent abort signal, explicit merge priority and already loaded hosts result. Numeric variants bypass that callback even if the hosts snapshot is a failure. Domain variants retain source errors, local rows, invalid-name results and complete paired network reports with their existing provenance.

The pure route and generic dispatcher require no resolver owner. The concrete adapter accepts one already borrowed by its caller; lazy resolver/configuration loading belongs to the higher HTTP client owner. Port, TLS/plaintext choice, HTTP authority and request target remain in the existing endpoint rather than being inferred from resolution results.

Six generic laws establish numeric routing with exact address retention, domain spelling retention and invalid-host boundaries. They describe the routing plan, not OS scheduling or DNS correctness. Live integration checks supply the latter composition evidence while reusing the existing native DNS tests. Address extraction/selection from named reports, connection attempts, TLS, proxy policy and attachment to the full HTTP request driver remain pending. This is a typed resolution layer, not a completed HTTP client or pi port.

All 312 live routing cases pass over IPv4/IPv6 transport and both explicit priorities on native one/four threads and Bun. They cover existing hosts/DNS behavior, repeated owner use, and numeric/invalid host variants paired with failed hosts snapshots. Numeric and invalid variants produce no query traffic, identifier draws or rotation. Resource audits return to zero, including Bun explicit channel closure; native socket inspection is bounded to descriptors 0–4095. The proof gate checks 164 public laws and 55 supporting lemmas, rejecting all 110 typed mutations. Source and compiler hashes are archived. The existing isolated compiler candidate remains required and uninstalled; no compiler/runtime patch or unsafe annotation was added.

## Connection candidate projection

`http-addresses.prepare` projects a completed resolution into `connection-addresses.Plan`, retaining the complete original result in both available and unavailable outcomes. Numeric results supply one address. Hosts rows supply one ordered sequence without removing duplicate occurrences. Successful paired DNS results supply separate IPv4/IPv6 candidate lists, preserving each family's answer order; only selections classified as usable answers contribute addresses. A failed or halted search supplies no candidates, even when its retained report contains a successful sibling.

The projection adds no family preference, sorting, deduplication, mapped-address conversion or socket activity. Each unscoped hosts/DNS IPv6 address receives scope zero. TTLs, canonical names, aliases, negative sibling reports and deadline diagnostics remain in the retained original value rather than being invented on connection addresses. Address conversion uses the existing native address values directly.

Ordered candidates are nonempty; the paired constructor returns an unavailable plan when both lists are empty. The connection scheduler must still choose how to order/interleave the family lists and handle connection failures before the HTTP exchange can start. Those decisions are independent of DNS error-merge priority.

The candidate core has inductive concatenation and count-preservation laws for hosts and DNS lists, exact address-conversion laws for arbitrary canonical/alias/TTL metadata, and generic report/list-retention laws for ordered, paired and empty plans. Count preservation matters independently: an always-empty conversion can satisfy the concatenation equation but cannot preserve nonempty input counts. Deliberate address-erasure mutations check that invariant directly. Runtime integration checks preserve the old resolution output beside the new projection, making lost diagnostics or changed canonical/TTL values observable.

All 312 live projection cases pass on native one/four threads and Bun. Every case checks both the retained resolution output and projected candidate lists, including duplicates, partial success, independent alias names, numeric literals and unavailable/terminal outcomes. Resource audits return to zero. Thirteen new laws bring the proof gate to 177 public laws and 55 supporting lemmas; all 115 typed mutations are rejected, including erased host/DNS lists checked by the count laws. Source hashes match the archived evidence. Builds and proofs use the existing isolated compiler candidate; no compiler/runtime patch or unsafe annotation was added.

[Connection ordering](connection-scheduling.md) now consumes these candidate groups, preserving first occurrence within each family and alternating families. Ordered inputs use their first family's preference; paired inputs still require an explicit choice. The finite driver and HTTP TCP composition below now consume this order; HTTP exchange integration remains pending.

## HTTP TCP establishment

`http-connect` now composes typed host resolution, candidate projection, stable family ordering and the finite native connection driver. `resolveWith` injects ID generation and the connection adapter independently; `openWith` supplies the native connection driver, and `open` supplies the native random ID source as well. DNS failure priority, connection-family preference, destination port and attempt duration are explicit inputs. Ordered hosts results still choose their first family's order; a preference is needed for paired DNS results.

The result distinguishes `Unresolved`, which retains the full original resolution without invoking the connector, from `Attempted`, which retains both that resolution and the complete driver report, including typed failure, attempt history or an affine socket. Projection and ordering affect attempts only: duplicate hosts rows, DNS metadata and negative/deadline diagnostics remain in the resolution report. Connector results transfer without flattening or replacing their diagnostics. Numeric URL hosts continue bypassing failed hosts snapshots and name lookup.

The resolver and parent signal remain caller-owned. The native adapter uses the same parent for resolution and connection, allowing a caller-owned overall deadline to span both phases. It does not create or select such an overall budget itself. Each DNS scope retires before connection driving begins; the final connection attempt has no family-selection timer. A successful result is a TCP socket, including when the intended application protocol is HTTPS: TLS must complete before HTTP application data is sent. Lazy system configuration/owner creation, TLS/proxy transport, request exchange integration and migration of pi's consumers remain pending.

The generic effect boundary lives in `connection-plan`. Its new law quantifies over arbitrary connector/context/resolution values, reason types and affine result types, proving that an unavailable plan equals an immediate pure return of the full resolution and cannot invoke its connector. This is a general IO-program equality, not an example-specific assertion. The proof gate checks 196 public laws and 57 supporting lemmas and rejects all 124 typed mutations, including a well-typed mutation that invokes the connector for an unavailable plan. Existing unsafe-declaration audits remain unchanged; no new unsafe annotation or compiler patch was added.

All 312 live resolution/dispatch cases pass on native one/four threads and Bun. A deliberately injected connector checks exact deduplicated/interleaved addresses and transfers an owned channel; every retained resolution output remains unchanged. Its requested family preference is deliberately opposite DNS error priority. Failure/invalid-host plans never call it, and numeric hosts bypass failed hosts snapshots without DNS activity. These synthetic destination addresses are never contacted.

All 144 real native-adapter cases also pass across those backends, in unmodified and audited programs. Numeric/hosts paths trap any DNS ID draw. Separate loopback DNS cases answer both A and AAAA before the native connector proceeds to first-address success, refusal fallback, timeout fallback or exhaustion, in both requested family orders. Real accepted peers observe EOF after the caller closes the returned socket. Hosts duplicates remain in the resolution and are removed only for attempts. Failed hosts snapshots and invalid hosts return unresolved without connecting.

Exact allocation audits require zero timers for single numeric attempts/unresolved results, one for hosts fallback, and four for the DNS path: one search deadline, two concurrent UDP-query deadlines and one non-final connection timer. A response barrier makes both query deadlines coexist, with peak three; no final connection timer is created. All inspected resources retire, including native UDP operation owners, connection/timer owners, channels, parked IO and sockets within descriptors 0–4095; Bun checks timer/connection owners, waiters, explicit channel closure and live/waiting IO. These are finite integration checks, not a universal concurrency proof. Runtime, proof and compiler identities are archived with matching source hashes. The existing isolated candidate remains uninstalled.

## Resolved cleartext request exchange

`http-resolved-exchange.startWith` now takes a fully prepared URL request, resolves its typed endpoint, selects/connects addresses, then transfers the owned socket into the existing upload/response-stream exchange. `start` supplies the native random ID source. The URL's prepared authority and origin-form target remain in the request rather than being replaced by the selected numeric address. The same caller-owned abort signal spans resolution, connection, socket adoption, upload and response reads; socket adoption rechecks a retained abort before request IO. The caller must consume or close a successful exchange before disposing that signal.

The result distinguishes preflight rejection, unresolved host reports and attempted connections. Attempted results preserve the complete resolution and ordered connection history alongside either the owned exchange or a typed connection/exchange-start failure. Read, parser and disposal errors remain in the existing exchange stream API. `http-exchange-plan` rejects zero read size and TLS endpoints before resolution/connection; this adapter implements cleartext HTTP and must not send application data over an unupgraded HTTPS socket. Two generic guard laws cover arbitrary endpoint/request values, bringing the proof gate to 198 public laws and 57 supporting lemmas; all 126 typed mutations are rejected.

All 204 integration cases pass on native one/four threads and Bun, with unmodified and audited programs. Loopback peers check the exact POST target, the URL-derived Host overriding an incorrect supplied field, the framed body and eventual EOF. Numeric, hosts and actual paired-DNS paths cover success, refusal/timeout fallback and exhaustion in both family orders. Additional cases cover failed host sources, TLS/zero-read rejection, pre-abort and cancellation after a final response head while the body is withheld. The retained cancellation reason and resource retirement are checked; these are finite IO cases, not a universal scheduling proof.

This validation used a clean checkout of `cd8da50` plus the new files because earlier uncommitted form-body drafts remain in the working tree. Evidence verifies all existing dependencies against that pinned base and new files against their final contents; the drafts were neither included nor discarded. The combined program needed a 12 GiB build guard after two 8 GiB failures with the same isolated compiler; the compiler investigation records that unresolved limitation. No compiler patch or unsafe annotation was added. TLS, proxy transport, redirects, decompression, connection pooling, higher-level fetch ownership and migration of pi's consumers remain pending.

## Response metadata

`http-response-metadata` exposes status, decoded status text, success classification, body presence and the received `Headers` view while retaining the complete original response head. Header values follow received-field handling rather than caller-input normalization; ordered raw fields remain available for framing diagnostics. Body presence comes from the response policy, so HEAD and null-body status handling remain separate from transport ownership. This immutable record does not acquire, consume or close a body.

This is the response surface used by the reference `packages/ai/src/api/openai-codex-responses.ts` at `46c9de402`: status/headers feed hooks, retry decisions and error extraction before the provider acquires a body reader. The [response owner](http-response-ownership.md) now connects metadata/body handoff to the native exchange; the acquired byte-source adapter for provider readers remains pending.

Eight generic laws establish field-fold partitioning and its empty/single-field boundaries, exact original-head and public-header retention, status and exposure retention, and the 200-inclusive/300-exclusive success range. The proof gate passes 206 public laws and 57 supporting lemmas and rejects 129 well-typed mutations. The laws do not establish body ownership or scheduler behavior.

The differential fixture projects actual streaming-parser final heads and compares them with 39 real loopback Node Fetch responses. Every two-chunk split, intervening empty chunks and byte-by-byte input produce 2,826 cases per backend; all pass on native one/four threads and Bun. Cases cover HEAD, boundary/nonstandard statuses, malformed UTF-8 reason bytes, duplicate fields, separate Set-Cookie values, cookie joining, trailing header whitespace, informational heads, chunked trailers and EOF framing. These are received-metadata checks, not native socket or body-owner integration tests. The fixture's import closure excludes the pending form drafts.
