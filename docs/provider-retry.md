# Provider retry

`packages/ai/src/utils/provider-retry.bend` is pi's `provider-retry.ts` in one module: the SDK-mirroring retry policy (retryable statuses, `x-should-retry`, `retry-after-ms`/`retry-after` seconds or HTTP dates, capped server delays, jittered backoff), the request loop, option validation, error rendering and the native effects the loop consumes. The loop abstracts over Bend's value quantity: `retryProviderRequest` returns copyable data and `retryProviderRequestOwned` transfers an affine owner (a response body, stream or socket) exactly once; failures stay copyable descriptions and every failed attempt retires its own resources. A success returns immediately even if the signal was already aborted, as in pi, whose request callback honors its own signal; a failed request checks abortion before exhaustion, and only typed provider failures enter the policy.

Language-driven changes, each explicit rather than emulated:

- **Effects are borrowed callbacks.** Entropy, `Date.parse` of Retry-After dates, the clock and timer sleeps are `Effects` handles. `Runtime.new` assembles the production handles (OS entropy, the native HTTP-date parser, real timers); virtual-time tests supply their own without a second loop.
- **Strict numeric options.** `resolve` validates `maxRetries` (a nonnegative exact integer within the native natural range) and `maxRetryDelayMs` (finite, nonnegative; zero disables the cap) once, at the provider boundary, into typed `OptionsError`s instead of upstream's `NaN` arithmetic. Absent values keep the defaults.
- **Strict sleep durations.** Sleeps accept finite binary64 milliseconds in `[0, 2^32)`, flooring fractions into the native timer; negative, nonfinite and overflowing values are typed `InvalidSleepDuration` failures before any timer exists, where upstream passes `Math.max(0, ms)` to `setTimeout`.
- **Rendering.** Only errors the helper introduces (abort, rejected delays, out-of-range sleeps) get names and messages here; original request errors keep the provider's rendering.

`laws/provider-retry.bend` states the loop's control-flow contracts (success bypasses effects, abort stops a failed request, exhaustion keeps the failure, application failures are never retried, sleep outcomes), option validation (field preservation, error precedence, independence from the selected signal) and the no-timer-effect guarantee for invalid durations. `tests/provider_retry_*` compare traces with the pinned helper, including the five named upstream retry tests under a test-only virtual clock, real-socket owned retries and audited timer allocation; `tests/provider_retry_options_check.py` and `tests/json_finite_growth_check.py` supply independent numeric boundaries.
