# Runtime formatting context and default session ownership

The Responses driver now accepts an immutable runtime rendering environment alongside its closed formatting function. This lets the public provider capture settings such as the selected provider name without allocating another callback channel. The existing static-renderer entry points delegate through a unit environment. Driver ordering, typed causes, primary-failure preservation and stream settlement use the same implementation.

`Session.startWithContextAndCleanup` passes the environment to the producer and retains the existing finalizer boundary. `Native.startWithContextAndCleanup` additionally owns its selected cancellation signal/query and an explicit dependency finalizer. It retires its own signal/query first and then runs dependency cleanup before `wait` returns. Existing native callers continue to borrow their dependencies through the original entry point.

The [driver evidence](runtime-validation/2026-09-21-renderer-context.json) covers 126 executions: seven outcomes with three runtime names across plain/audited native one/four threads and Bun. It checks acquisition, processing, cleanup, start-delivery and terminal-delivery failures, preserved primary errors and final settlement. The [session evidence](runtime-validation/2026-09-21-session-renderer-context.json) adds 72 executions with a gated dependency finalizer, repeated joins/disposal and checks of the rendered final message. All audited counters finish at zero. The [existing cleanup regression](runtime-validation/2026-09-21-renderer-cleanup-regression.json) also passes and rejects a producer that omits cleanup.

`openai-responses-default-session.startPrepared` now assembles default pricing ownership with native acquisition/session processing. The model ID selects pricing policy, and grammar mappings come from the same prepared request as the payload. The producer disposes the pricing owner before the supplied dependency finalizer. The [completed full gate](proof-validation/2026-09-21-default-session.json) checks 448 public laws and 67 supporting lemmas and rejects 243 typed mutations, including grammar loss, missing pricing and omitted dependency retirement. All 34 integration cases pass across plain/audited native one/four threads and Bun: [204 executions](runtime-validation/2026-09-21-default-session.json), including requested/response tier precedence and the special model multiplier. Audited resource counters finish at zero. The evidence records the two formatting-only source changes after emission. The [subsequent gate](proof-validation/2026-09-21-provider-hook-map.json) also passes with seven additional hook-adapter laws (455 public laws, 67 supporting lemmas and 246 rejected typed mutations).

This remains a prepared-request boundary with explicit transport dependencies. It does not yet supply the final public request-preparation entry point, complete error normalization, default resolver/fetch ownership, TLS or authentication lifecycle. The runtime tests above prove finite executions, not universal IO scheduling or resource retirement. No compiler patch or new unsafe definition was introduced.
