# Native Responses cleartext callback

`api/openai-responses-cleartext-fetch.bend` implements the canonical Responses fetch callback over the native resolver, connection driver, buffered HTTP exchange and affine response reader. Its caller-owned context contains a borrowed resolver, a typed hosts snapshot and explicit transport options. It frames the already-serialized payload as UTF-8, derives Host from the URL, resolves/connects using the fetch scope's child signal, uploads the request and waits for final response headers. The returned body remains unread and owns the exchange until consumption or close. Caller-owned callbacks and the resolver must outlive all active calls and returned responses.

Preparation, plan rejection, resolution, exchange and header-acquisition errors remain distinct typed variants. Connection and header failures retain the resolution report and connection-attempt history. Header acquisition uses the existing response adapter, which closes the exchange before reporting failure; the enclosing fetch scope can then safely retire its signal. Successful responses retain their status and headers, including non-2xx statuses. Provider HTTP status interpretation, bounded diagnostic consumption and retries belong above this transport boundary.

This callback is explicitly cleartext. HTTPS returns the existing `TLSRequired` plan error before opening a connection or sending HTTP bytes. It is a native building block for HTTP endpoints and loopback provider tests, not a completed HTTPS client. Native TLS, content decoding, redirect/pooling policy, authentication refresh, provider retry/status/session assembly and the full agent/TUI remain unfinished.

Five generic laws cover successful response transfer, preservation of header-error trace/cause, and effect-free propagation at the header-acquisition boundary for rejected plans, unresolved requests and failed exchanges. They do not prove network liveness. Importing the concrete transport adds six existing effect-loop declarations to the full proof root's explicit unsafe audit: `dns-address-lookup.drive`, `dns-tcp-connection.drive`, `dns-tcp-query.read`, `dns-udp-query.read`, `http-response-reader.drive` and `random-index.retry`. The first five depend on external IO/cancellation progress; the last performs rejection sampling. These are existing implementation annotations, not new unsafe proofs or declarations. The exact audit now contains 19 names, matching the full root's reported count; the concrete native module alone reports 13 annotations. No blanket allowance replaced the named audit.

The loopback fixture uses the real callback through `openai-responses-fetch.run`, then consumes or closes the returned scoped response. It checks numeric IPv4/IPv6 and hosts routes, logical Host overriding a supplied wrong Host, target/query preservation with fragment exclusion, exact UTF-8 payload/content length, informational/fixed/chunked responses, body reads beyond the original fetch deadline, early close, caller cancellation, malformed/truncated responses, fetch expiry and TLS rejection. The new boundary currently tests numeric/hosts routing; real DNS exchange is covered by the existing resolved-exchange fixture rather than claimed as executed here. Resource instrumentation is test-only; production complex dependencies remain Bend.

Reproduce with `python3 tests/openai_responses_cleartext_fetch_check.py build/bend-profiles/dns-transport-teles/bend2` and the full `scripts/check-proofs.py` gate. The full gate passes 384 public laws and 65 supporting lemmas, rejecting 214 type-correct mutations, open obligations and a missing proof. All 144 loopback checks pass: 72 unmodified and 72 resource-audited executions across native one/four threads and Bun. Exact timer counts and peaks are one for numeric/TLS-rejected requests and two for the hosts cases (fetch deadline plus a non-final connection-attempt timer). Native audits require zero live timers, waiters, channels, connection owners/descriptors, UDP operation owners, parked IO and socket descriptors within 0–4095; Bun audits timers, connection owners and channels/IO. [Proof evidence](proof-validation/2026-09-21-openai-responses-cleartext-fetch.json), [runtime evidence](runtime-validation/2026-09-21-openai-responses-cleartext-fetch.json) and [compiler evidence](bend-issues/2026-09-21-openai-responses-cleartext-fetch-compiler.json) pin the validated sources and limitations. Reusing compiled programs requires matching source and program hashes; the test harness itself can change to add assertions. No upstream pi suite status is changed by this transport milestone.
