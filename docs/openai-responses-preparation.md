# Responses request preparation

`api/openai-responses-options.bend` ports the complete Responses options record: all nineteen inherited `StreamOptions` fields plus reasoning effort, reasoning summary, service tier and tool choice. Conversion to/from the base record retains borrowed callbacks, fetch, signal and telemetry handles. Summary and service tier are native variants with explicit optional/null states. Tool choice remains a caller-supplied typed value with its wire encoder, matching the existing request-builder boundary; a concrete SDK-wide choice type is still pending.

`api/openai-responses-prepare.bend` composes the existing provider modules in upstream order: select Responses compatibility, normalize the transcript, validate credentials, resolve cache retention, compute grammar declarations, assemble client headers, and build the JSON request. It returns a typed `Prepared` value with credentials, base URL, headers, payload, compatibility, grammar properties and resolved retention. Credential, grammar and payload errors retain their typed causes. Models assigned to another provider API are rejected explicitly; Azure and Codex have separate entry-point/authentication contracts upstream.

The wire entry point instantiates sampling values and hook payloads with canonical `JsonValue`. Models, messages, schemas, tool declarations, options and errors keep their existing typed representations. No JS object runtime or generic serialization round-trip is used to represent these records. Preparation borrows the options and acquires no sockets, tasks or callbacks. Hooks and transport consume the prepared data through their existing layers; the final production assembly is still pending.

## Correctness

Twelve new laws cover lossless option extension/projection, preservation of successful preparation fields and typed payload failures, supported-model configuration and custom-API rejection, rejection paths without downstream effects, and absent/null/string field updates for arbitrary objects. The options laws quantify over every payload, choice, signal, telemetry, fetch and error type. The two template rejection-path laws quantify over every runtime input at the JSON-wire/Unit-diagnostics instantiation: Bend requires closed compile-time template arguments, so these do not assert type-parametric template theorems. Other diagnostic instantiations, successful conversion effects and IO termination are outside those two laws.

The [proof gate](proof-validation/2026-09-21-openai-responses-preparation.json) checks 305 public laws and 59 supporting lemmas and rejects 178 well-typed mutations. Full-root acceptance, open-obligation rejection and missing-proof rejection remain mandatory. Mutation checks include transitive proof dependencies and preflight every selected proof environment unmodified first, then require the same named contract to reject the modified implementation; proof modules importing global laws retain the full root. This avoids recompiling unrelated provider code for a queue mutation without relaxing the required rejection. The expanded import closure audits thirteen existing unsafe declarations and reports twelve concrete annotations. No new unsafe definition or unsafe proof was added, and these laws do not prove the imported recursive drivers/schema routines correct.

The [differential record](runtime-validation/2026-09-21-openai-responses-preparation.json) covers 372 preparation cases on native one/four threads and Bun, totaling 1,116 executions. The oracle executes the actual pinned upstream pre-hook wrapper block, transcript/tool/message converters and header policy with a recording SDK constructor. Cases cover transcript changes, strict/grammar/additional-tool/search compatibility combinations, credential error precedence, custom authorization, model-only authorization rejection, Copilot/OpenRouter headers, caller overrides and null deletion markers, explicit/scoped/process cache settings, every service tier and explicit null. Inputs use fixture credentials and perform no network requests. The existing parameter suite additionally passes 917 comparisons on each native thread count.

Integration exposed an older omission: `RequestOptions.serviceTier` could not represent explicit null even though upstream forwards it. The internal projection now distinguishes omission from null, and the generic field-update laws plus new reference cases cover both null and later sampling overrides. Invalid summary/tier strings are unrepresentable in the new public options variants. Lower-level parameter assembly still accepts wire strings and retains its existing numeric behavior; this milestone does not establish strict validation of every provider numeric option.
