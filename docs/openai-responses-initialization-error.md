# System initialization diagnostics

`packages/ai/src/api/openai-responses-initialization-error.bend` composes concrete resolver configuration and runtime initialization diagnostics. Resolver failures retain their immutable ordered diagnostic list. Entropy failures distinguish resolver random-index initialization from retry-seed initialization and retain OS codes/messages or the actual short-read byte count. Rendering does not substitute entropy, retry invalid configuration or alter the typed error.

The `messages` function exposes structured message collections. `format` presents them with semicolon separators. A manually constructed empty configuration diagnostic list gets the generic presentation `Invalid resolver configuration`; its typed value remains unchanged. A single diagnostic, including an empty string, is displayed unchanged. Provider integration must wrap this total string formatter in the existing typed formatting result.

Six standalone laws specify OS-cause preservation, actual short-read counts, configuration/runtime wrapping and unchanged singleton display. The singleton proof uses structural induction on the string. The [six standalone laws](proof-validation/2026-09-21-initialization-error-standalone.json) pass under the accepted isolated compiler; existing imports produce eighteen specialized unsafe annotations, with no new unsafe source declaration. All [30 runtime outcomes](runtime-validation/2026-09-21-initialization-error.json) pass across native one/four threads and Bun. No mutation tests were run. These six laws remain outside the completed 522-law root.
