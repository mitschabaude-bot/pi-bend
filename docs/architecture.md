# Architecture fidelity

The target is pi-mono revision `46c9de402`, including its library design. The current executable in `src/` is a bootstrap prototype: it verified Bend compilation, native effects, authentication and a live tool loop. It does not establish architecture parity. Canonical ports live under the corresponding upstream paths in `packages/`.

## Required boundaries

| Upstream package | Library responsibilities to preserve | Current gap |
| --- | --- | --- |
| `ai` | Typed messages, content, usage, models, provider factories, transcript normalization, credentials, injectable transports, streaming events and stream results | Shared Responses conversion and typed stream processing are implemented; provider wrappers, wire decoding and transports remain incomplete |
| `agent` | `Agent`, `AgentState`, `AgentContext`, `AgentMessage`, `AgentTool`, `AgentToolResult`, `AgentLoopConfig`, `StreamFn`, event subscriptions, tool hooks, queues, concurrent execution and settlement | Native Agent orchestration, loop entry points, streaming wrappers and tool lifecycle are assembled; full schema integration and broader package parity remain pending |
| `agent/harness` | Execution environment, filesystem/shell interfaces, resources, reducer/drive layers, typed results, session storage and conformance, compaction | Native OS calls exist; harness interfaces and lifecycle are unported |
| `tui` | `Component`, `Terminal`, editor interfaces, reusable components, screen implementations, differential renderer, input protocols and themes | Unicode/native terminal primitives exist; the library is unported |
| `coding-agent` | SDK/session orchestration, resources, settings, tools/renderers, print/JSON/RPC/interactive modes and extensions | Prototype CLI lacks the SDK and most lifecycle semantics |
| Supporting packages | Preserve dependencies used by these libraries, including chord and telemetry; assess protocol/client/server and storage entry points against the reference | Applicability and export inventory pending |

The `ai` root in this revision is explicitly side-effect free. Provider factories, API implementations, compatibility registration and OAuth entry points are separate. The agent stream contract uses a normalized transcript with system messages carrying prompts and tool declarations. Porting an older mental model of pi would miss these contracts.

## Representation rules

Typed upstream records and unions become Bend records and algebraic data types, preserving each field and variant. Optional values remain distinguishable from explicit false, zero and null. JSON belongs at serialization boundaries and at upstream fields intentionally typed as arbitrary data. It is not the replacement for `Message`, `Model`, `AgentState` or typed events.

Responses argument encoders return `schema-value.Value`, since provider arguments can contain any parsed JSON before tool validation, even when a tool declares an object schema. Replay preserves scalars, arrays and null for ordinary function calls; application-native argument records still use a pure encoder. Grammar calls require an object containing the configured string field. A null grammar argument returns the same typed missing-string error as other invalid arguments instead of reproducing JavaScript's property-access exception.

Upstream generic tools, custom messages and schema-validated arguments must retain their type relationships. Promise/callback/async-iterator APIs need documented Bend IO equivalents with the same cancellation, error, callback ordering, backpressure and settlement contracts. JavaScript declaration merging needs a typed Bend extension mechanism. These are implementation requirements, not reasons to discard extension points.

Complex dependencies belong in pure Bend, including HTTP/TLS, cryptographic operations, Unicode algorithms and numeric support. Missing language primitives should be added to Bend instead of replacing these libraries with C or JavaScript glue. The prototype C adapters are temporary migration liabilities. Operating-system primitives must remain injectable through the ported library interfaces so upstream mocked/conformance tests have equivalents.

## Runtime and standard-library implementation

We build the primitives and reusable Bend libraries needed by the port. Missing facilities are expected in a new language, not work deferred to someone else. Use minimal OS effects beneath idiomatic, functional Bend APIs; test resource ownership, cancellation, behavior and performance before adoption. Investigate actual defects encountered along the way in the Bend issue log.

The [owned timer implementation](../patches/experimental/timer/README.md) provides deadline, wait, cancel and close effects, composed into Bend abortable sleep and provider retry adapters. Lifecycle, race and original retry tests pass against isolated candidates. Remaining work is adoption validation and complete provider integration. HTTP/TLS and the remaining transport layers are likewise implementation work; the bootstrap's libcurl dependency is not the final design.

Numeric IPv6 connection establishment is now implemented in an [isolated additive primitive](../patches/experimental/ipv6-connect/README.md), with a pure Bend adapter for the existing address type. DNS, cancellable connect, TLS and endpoint-to-exchange integration remain our transport implementation work.

An [owned cancellable connection primitive](../patches/experimental/connect/README.md) now supports pending IPv4/IPv6 attempts in an isolated candidate. Its affine owner, cancellation capability and retirement rules are tested; pure Bend AbortSignal/deadline and transport integration remain to be composed.

## Module acceptance

For each module, record its upstream source and public exports; port the full data model and call contracts; port its tests; verify downstream composition; then migrate its callers. A module is not complete solely because a demonstration works. Track intentional language adaptations separately from remaining gaps.

The first canonical leaf module is `packages/agent/src/harness/utils/truncate.bend`. Public result field names and `truncateHead`, `truncateTail`, `truncateLine`, `formatSize` names match upstream. Bend has no optional call arguments, so head/tail take an explicit `TruncationOptions` record containing `Maybe` fields; `defaultOptions()` supplies the defaults. `truncateLine` takes an explicit limit, with `truncateLineDefault` supplying its default. Exported constants retain their names as nullary functions. Counts use `Nat`. This module still needs downstream integration; it does not imply the agent harness is ported.

## Native representation

Ordinary messages, content, schemas, tools, configurations, contexts, headers and usage/cost records are immutable Bend values. Lists are persistent lists; dictionaries preserve insertion order and compare native string keys. Typed optional fields carry absence explicitly. No prototype, descriptor, own-property, sparse-array or object-identity runtime is required.

Tool declaration comparison is structural, and streaming events retain immutable snapshots. Both intentional behavior changes were approved by Gregor. Hooks express changes through returned records: before-tool hooks return arguments/context, next-turn hooks return context/messages/model/thinking, and after-tool hooks return optional result overrides. See [native-bend.md](native-bend.md) for upstream contracts and coverage.

Synchronization stays in explicit effect resources: running-agent state, stream queues, callback factories, deferred results and cancellation observations. Resource handles currently require owner-directed disposal. Cancellation uses typed reasons and removable observations, without DOM event machinery. Full agent execution, cancellation integration and managed resource lifetimes remain open.

Pure-Bend numeric foundations implement binary64 arithmetic, exact integer/rational conversion, parsing and shortest formatting. JSON has its own codec boundary. These dependencies preserve numeric behavior without replacing pi's typed library architecture.

Current module status and limitations are recorded in [pi-ai](../packages/ai/README.md), [pi-agent](../packages/agent/README.md), [runtime](../packages/runtime/README.md) and [test coverage](../tests/UPSTREAM.md).

Native schema builders live in the schema builder section of `schema.bend`. A `Declaration` carries the JSON schema sent to providers, an executable schema constraint, and an explicit immutable conversion policy. Composition keeps those three representations together; runtime validation and conversion need no hidden host-language metadata. Primitive types, JSON-compatible literals, arrays, tuples, unions and objects have factories. Object fields explicitly wrap a declaration as required or optional. Object conversion uses the proposed literal-key dictionary policy; its differences from TypeBox await approval before public integration. `withOptions` supports annotations, numeric bounds, collection limits, uniqueness and boolean additional-property constraints. It returns a new declaration, recompiles its wire schema, and updates union candidate constraints. Structural overrides fail explicitly. Other options, schema-valued additional-property conversion and integration into AI tool validation remain unfinished.

the tool batch section of `agent-loop.bend` owns sequential batch scheduling independently of per-call execution. Each invocation receives the previous immutable state and returns the next state, one delivered message and its termination flag. The scheduler checks cancellation after completion and reduces termination across the processed batch. the tool call section of `agent-loop.bend` supplies the per-call adapter over the canonical preparation, execution, finalization and event-delivery stages. Its owner collection retains update callbacks through success or failure until callers retire tool-held aliases. Parallel batches use the tool batch parallel section of `agent-loop.bend`; public loop entry points remain pending.

`packages/runtime/src/concurrent-all.bend` supplies ordered concurrent collection for parallel batching. Each callback runs independently; a shared deferred result selects the first observed failure without cancelling siblings. A separate collector consumes every worker reply in input order. The run owner drains that collector before disposal, keeping result settlement distinct from resource lifetime. The parallel batch module now connects this collector to native tool preparation, execution, finalization and ordered result delivery.

the tool batch parallel section of `agent-loop.bend` prepares calls in sequence, preserving explicit context updates. Immediate outcomes emit execution-end events during preparation. Prepared calls then execute concurrently against the final preparation context, with a fresh cancellation check before invocation. After successful collection, result messages are created and delivered in call order. `start` returns an owned run, `result` delivers messages once, and `dispose` drains remaining workers before retiring the execution callback. A listener failure may settle the result while sibling tools keep running; callers retain captured resources and tool-update owners until those workers and retained aliases retire.

the tool execution section of `agent-loop.bend` is the common `executeToolCalls` entry point. It extracts calls from the assistant message and selects the execution mode from the original context/configuration before preparation begins. A matching tool’s sequential override routes the entire batch through the sequential adapter. An `Execution` value carries either an already settled sequential/preparation result or an owned concurrent run; callers consume `result` once and then `dispose` before releasing captured resources. Tool-update scopes remain in the separate `Capture.owners` collection; retiring their aliases and draining that owner is also required before releasing event resources. Before-hook context updates remain explicit in the returned batch. The public entries compose this dispatcher through the main loop.

the turn completion section of `agent-loop.bend` connects a settled tool batch to the post-response part of the main loop. It appends ordered tool results to the batch’s returned context and the generated-message history, emits `turn_end`, and supplies that immutable snapshot to the stop hook. A continuing tool batch or pending steering returns `Continue`; only an otherwise idle turn polls follow-ups. Normal exhaustion and stop-hook termination emit `agent_end` and return `Finished`. Listener, batch and hook failures stop subsequent events/polls. The caller records the assistant response beforehand and owns batch/update draining separately. The internal main loop composes this stage with request/next-turn preparation.

the tool changes section of `agent-loop.bend` implements `declareToolChanges` for native schema values. It splits pending messages around the last system record, removes only that record’s pending tool intent from the replay baseline, and reconciles replayed declarations with executable tools. Existing system content, sections and timestamps are preserved; a new timestamp is read only when inserting a new declaration. Structural schema equality follows the approved native policy. the turn preparation section of `agent-loop.bend` composes next-turn hook updates, conditional steering repolling, `turn_start`, declaration reconciliation and ordered message delivery. It returns context, configuration and generated history ready for the provider boundary. Its initial path skips the hook/repoll/extra turn-start because those belong to the outer entry flow. Neither path invokes `convertToLlm`. The internal main loop composes the request/response cycle.

the main loop section of `agent-loop.bend` assembles the internal `runLoop`: initial steering and declarations, provider streaming, assistant completion, normal or truncated tool batches, turn completion and subsequent preparation. Updated contexts and model/reasoning configuration reach subsequent requests. Failed or aborted assistant responses finish without tool execution or queue polling. Length-limited calls use the shared truncation helper, whose error details are now explicitly supplied in the caller’s native result type. The loop owns its running context cell. Its caller owns the execution collection and update scopes, drains executions before retiring callback resources, and retires retained tool-update aliases before disposing update scopes. This separates prompt failure settlement from sibling resource lifetime. Both public entry flows use this internal loop.

the loop entry section of `agent-loop.bend` provides `runAgentLoop` and `runAgentLoopContinue` with explicit or default-provider selection. Start reconciles prompt declarations before `agent_start`, then emits `turn_start` and ordered prompt message pairs before entering the shared loop. Continue validates the final agent-message role before emitting anything, starts with an empty generated history, and never re-emits existing context messages. Native continuation errors are typed values with the original error text; custom messages are accepted without invoking conversion during validation. Both entries use the same explicit batch/update ownership as the internal loop. Asynchronous event-stream wrappers are implemented in the loop stream section of `agent-loop.bend`.

`stream-fn.bend` ports the configurable default provider as a typed, host-owned registry. A host shares one registry wherever upstream shares its module default; independent hosts may own separate registries. `setDefaultStreamFn` installs, replaces or clears a borrowed callback, and `getDefaultStreamFn` returns it or the typed missing-default error with upstream text. `Selection` distinguishes an explicit provider from a registry fallback. Entries resolve this selection after successful initial event/prompt delivery and before entering the internal loop, retaining the selected callback across every turn. Registry changes during steering therefore affect future runs, not the current one. `Main.Services` contains shared runtime services; the entry capture contains an unresolved selection, while the main-loop capture contains the resolved provider. Registry disposal does not dispose provider callbacks; their owner retains them until all selected runs finish.

the loop stream section of `agent-loop.bend` supplies `agentLoop` and `agentLoopContinue` as owned asynchronous runs. It creates an event stream whose result is `Result<Error, Messages>`, starts the real entry flow in a background task, and exposes event iteration and repeatable result observation independently. Successful `agent_end` settles the generated history. Under the approved failure policy, a loop failure ends iteration and settles an error without synthesizing `agent_end`; ordinary assistant error/aborted messages still follow their existing event/history path. Continuation validation happens before allocation or launch. Disposal joins the loop, drains surviving tool batches and update scopes, then retires owned sinks, stream state and predicate/extractor callbacks. Provider/configuration callbacks are borrowed until disposal; callers retire iterators, result observers and retained tool-update aliases before disposing the run.

The generic event stream commits an event, its terminal flag and ownership of the first final result in one native `Ref.modify` transition. Predicate/extractor callbacks run outside that transition, and commit rechecks whether another operation closed the stream. This prevents a concurrent iterator from observing completion before the terminal event exists, discards a push suspended across closure, and prevents a later `end` from taking a terminal push’s result while its continuation is still running. No lock spans a user callback.

`openai-responses-stream-content.bend` implements immutable per-item transitions for Responses reasoning, text, function arguments and custom grammar input. Its `Block` variants hold private parsing state separately from canonical assistant content. Each `Signal` carries the value at its emission point; completing custom input can produce a delta with the previous namespace followed by an end signal with the final namespace. The stream-state module connects output slots and whole-message snapshots; terminal and async-driver integration passes its supplemental native comparisons. Reasoning items retain their opaque provider JSON for lossless signatures; other item fields are native records.

`openai-responses-stream-state.bend` separates provider output indices from assistant content positions using a persistent typed slot collection. It routes interleaved events through the content reducer, creates slots for done-only items, replaces reused indices without discarding earlier content, and emits canonical assistant events with immutable message snapshots. Completed reasoning IDs retain their content positions for terminal signature backfill. Failures retain the current state and earlier emissions for the IO driver to deliver before returning an error.

`openai-responses-terminal.bend` separates reasoning-signature backfill and base accounting from final stop-reason mapping. `openai-responses-stream-pricing.bend` invokes the borrowed tier resolver and pricing callback between those stages; pricing returns an immutable usage value. The shared public `processResponsesStream` entry point delegates to `openai-responses-stream.bend`, which awaits a typed reader and sink, preserves the emission snapshot on sink failure, and closes acquired iteration on early processing failures. Callers own callback disposal. The processor does not emit provider-wrapper start/done/error events; those remain a separate integration requirement. All 32 actual-source async-driver comparisons pass on one/four threads; 10 of 11 original terminal-event instances also pass, with the provider-wrapper early-EOF case explicitly pending.

`runtime/src/abortable-connect.bend` connects native numeric address values using an affine connection-attempt owner and an independently copyable cancellation capability. It composes these OS primitives with the existing typed AbortSignal and removable deferred observation, joining the single cancellation watcher before returning. Returned sockets transfer ownership to the caller; observed abort closes any completed socket and retains the original typed reason. The caller owns the signal. This layer contains no DNS, HTTP or TLS policy and currently uses the isolated additive connection candidate.

The connect-exchange section of `runtime/src/http-exchange.bend` composes numeric cleartext connection establishment and the socket-exchange section under one borrowed AbortSignal. It keeps address selection separate from the prepared request's authority and preserves the existing exchange owner and response API. Connection failures and exchange-start failures remain distinct typed variants. Socket adoption consumes the socket on every path and rechecks retained abort state during watcher handoff. Higher transport layers still own DNS, TLS selection, redirects and pooling.

`runtime/src/dns-name.bend` keeps DNS wire names separate from URL hostnames: native names are immutable lists of binary labels, not Unicode strings. A validated packet builds an immutable offset index shared across name decoding. Compression expands into a name plus the next original wire offset; explicit bounds and decreasing pointer targets constrain traversal. Encoding emits an uncompressed name. DNS transaction/message logic and hostname conversion remain separate resolver layers.

`runtime/src/dns-message.bend` parses counted DNS sections into immutable header, question and record values. Records retain data spans in the message's original indexed packet rather than losing compression context. The single-question encoder accepts explicit wire fields. This structural layer preserves unknown flags/types/classes; resolver transaction validation, record interpretation and network policy remain separate. Header inspection is available independently from strict complete-message parsing for truncated-response handling.

`runtime/src/dns-record.bend` interprets supported IN-class records using the message's immutable packet and bounds-checked data spans. A/AAAA reuse native address types; CNAME/NS/PTR and SOA retain native binary names. SOA numeric values are preserved without imposing cache policy. Unknown type/class combinations remain opaque with their original record metadata. Resolver acceptance and alias/address selection are separate from wire interpretation.

`runtime/src/dns-response.bend` correlates a single-question transaction with observed local/remote endpoint metadata and wire bytes. Native endpoint values include address family and IPv6 scope. The pure decision separates ignored input, matching truncation and a structurally complete matching message. Question equality uses ASCII-only DNS name comparison without altering stored names. Transport retry and response-code/record trust policies remain outside this matcher.

`runtime/src/dns-tcp-frame.bend` separates TCP message boundaries from DNS syntax and transaction identity. Its immutable reader retains a partial prefix or reversed partial payload. It yields one frame plus the unread input suffix, leaving backpressure and multiplexing to the socket driver. Encoder output includes the length prefix and complete payload together. The DNS parser handles payload validity and the transport owns EOF, cancellation and connection lifetime.

The DNS matcher exposes separate datagram (`inspect`) and established-stream (`inspectStream`) entry points. Both share endpoint/header checks and validate a present question. Only stream matching permits an absent question; it preserves the actual message rather than inventing query fields. This policy split is explicit at the transport boundary.

`runtime/src/dns-tcp-connection.bend` owns an abortable byte socket and immutable frame position. It preserves unread frames and terminal results, checks cancellation before buffered delivery, and exposes affine send/receive/close operations. Multiple sends may precede reads; responses remain in wire arrival order for a future transaction dispatcher. A single IO-driving loop awaits reads until a frame or terminal result is available. Socket adoption/connection establishment and resolver policy stay separate, and callers explicitly close to join the abort watcher.

Numeric socket metadata is exposed through `runtime/src/socket-endpoint.bend`: a pure typed adapter around the additive `Socket.endpoint` primitive. The effect observes local or peer address, port and IPv6 scope while returning the same affine socket on every path. DNS transaction matching can therefore use OS-selected endpoints rather than reconstructing them from wildcard binds or connection requests. The adapter is independent of DNS types; protocol-specific composition remains in the transport layer. Candidate code and validation scope live in `patches/experimental/socket-endpoint/README.md`.

`runtime/src/dns-tcp-peer.bend` composes observed socket endpoints with the owned DNS TCP connection. Its immutable route is the source of transaction endpoint metadata and of reverse-direction response inspection. Peer creation owns and closes the socket on inspection/adoption failure; successful creation returns the route alongside the affine connection. Frame reception remains an explicit operation on that connection, allowing a future pending-transaction dispatcher to select the expected transaction before calling `inspect`. The layer imposes no retry, cache or answer-trust policy.

`runtime/src/dns-pending.bend` is the immutable pending-transaction state for a single DNS TCP connection. Entries pair an expected transaction with a caller-defined data token. Registration is collision-checked, ignored replies preserve the state, and accepted replies/truncation return the token while removing exactly one entry. Socket IO and completion callbacks remain outside this pure module. The eventual driver owns sequencing, ID reuse, deadlines and completion delivery; an ID alone is not a stale-safe cancellation handle.

`runtime/src/dns-tcp-session.bend` owns a peer route, TCP connection, pending table and optional terminal failure. Submission registers before writing; receive dispatches one frame without an internal ignore loop. A terminal transport outcome empties the pending state and returns its entries once, while subsequent operations retain the failure. Explicit close joins the socket watcher and returns any unsettled entries. Affine ownership serializes IO operations; a higher-level driver must provide concurrent command admission, deadlines, ID allocation and completion delivery.

DNS registration returns a session-local cancellation ticket carrying the wire ID and a non-wrapping serial. Pending entries retain that ticket; cancellation matches both fields before removal. The affine session returns the cancelled entry without shutting down the shared connection. A stale ticket cannot cancel a newer registration in the same session history. Tickets do not distinguish delayed network replies after ID reuse, so the driver still owns reuse policy. Exhaustion is typed rather than wrapping the serial and reviving old tickets.

`runtime/src/deadline.bend` supplies an affine deadline scope using the owned timer and removable abort observations. It exposes a borrowed child signal with typed inherited-abort/expiry causes. Parent forwarding cancels the unused timer; close cancels remaining work, joins both tasks and disposes the child controller. The caller owns the parent and finishes child-signal users before closing the scope. This keeps deadline lifetime independent of DNS/provider policy without detached sleeps or watchers.

`runtime/src/dns-tcp-query.bend` is the dedicated-connection DNS exchange: it creates one deadline scope, uses its borrowed signal for connection setup and the session, waits through ignored replies without resetting the deadline, then closes the session before the scope. Its report separates the primary result, cleanup status and final deadline observation. It leaves address selection, query-ID allocation and resolver policy outside the transport. The lower-level owned session remains available for pipelining and future concurrent-driver work.

`runtime/src/dns-address-answer.bend` interprets matched complete IN address answers. An immutable owner index preserves DNS label boundaries and ASCII-only name equality; a visited index prevents rescanning alias cycles. Selection follows answer-section CNAMEs and returns the canonical name with ordered typed addresses and raw TTLs. It does not import authority/additional addresses or decide cache trust, negative answers or cross-response follow-up policy. The original parsed message remains available to callers needing alias/authority metadata for those later decisions.

`runtime/src/dns-address-lookup.bend` runs IN A/AAAA lookups against a caller-selected recursive server. It follows aliases across dedicated TCP exchanges under one deadline. `Answer.History` retains traversed alias owners across packets while leaving the unresolved terminal name available for a follow-up. `Query.exchange` borrows that deadline signal, closes each connection and returns its cleanup status. The higher-level lookup therefore detects cross-response alias loops without resetting its timeout or mixing replies from different connections. Resolver configuration, entropy, retries and caching remain separate responsibilities.
