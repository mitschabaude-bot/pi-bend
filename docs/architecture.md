# Architecture fidelity

The target is pi-mono revision `46c9de402`, including its library design. The current executable in `src/` is a bootstrap prototype: it verified Bend compilation, native effects, authentication and a live tool loop. It does not establish architecture parity. Canonical ports live under the corresponding upstream paths in `packages/`.

## Required boundaries

| Upstream package | Library responsibilities to preserve | Current gap |
| --- | --- | --- |
| `ai` | Typed messages, content, usage, models, provider factories, transcript normalization, credentials, injectable transports, streaming events and stream results | Prototype passes generic JSON through a single hard-coded provider |
| `agent` | `Agent`, `AgentState`, `AgentContext`, `AgentMessage`, `AgentTool`, `AgentToolResult`, `AgentLoopConfig`, `StreamFn`, event subscriptions, tool hooks, queues, concurrent execution and settlement | Prototype combines provider invocation, tool dispatch and session writes in one loop |
| `agent/harness` | Execution environment, filesystem/shell interfaces, resources, reducer/drive layers, typed results, session storage and conformance, compaction | Native OS calls exist; harness interfaces and lifecycle are unported |
| `tui` | `Component`, `Terminal`, editor interfaces, reusable components, screen implementations, differential renderer, input protocols and themes | Unicode/native terminal primitives exist; the library is unported |
| `coding-agent` | SDK/session orchestration, resources, settings, tools/renderers, print/JSON/RPC/interactive modes and extensions | Prototype CLI lacks the SDK and most lifecycle semantics |
| Supporting packages | Preserve dependencies used by these libraries, including chord and telemetry; assess protocol/client/server and storage entry points against the reference | Applicability and export inventory pending |

The `ai` root in this revision is explicitly side-effect free. Provider factories, API implementations, compatibility registration and OAuth entry points are separate. The agent stream contract uses a normalized transcript with system messages carrying prompts and tool declarations. Porting an older mental model of pi would miss these contracts.

## Representation rules

Typed upstream records and unions become Bend records and algebraic data types, preserving each field and variant. Optional values remain distinguishable from explicit false, zero and null. JSON belongs at serialization boundaries and at upstream fields intentionally typed as arbitrary data. It is not the replacement for `Message`, `Model`, `AgentState` or typed events.

Upstream generic tools, custom messages and schema-validated arguments must retain their type relationships. Promise/callback/async-iterator APIs need documented Bend IO equivalents with the same cancellation, error, callback ordering, backpressure and settlement contracts. JavaScript declaration merging needs a typed Bend extension mechanism. These are implementation requirements, not reasons to discard extension points.

Complex dependencies belong in pure Bend, including HTTP/TLS, cryptographic operations, Unicode algorithms and numeric support. Missing language primitives should be added to Bend instead of replacing these libraries with C or JavaScript glue. The prototype C adapters are temporary migration liabilities. Operating-system primitives must remain injectable through the ported library interfaces so upstream mocked/conformance tests have equivalents.

## Module acceptance

For each module, record its upstream source and public exports; port the full data model and call contracts; port its tests; verify downstream composition; then migrate its callers. A module is not complete solely because a demonstration works. Track intentional language adaptations separately from remaining gaps.

The first canonical leaf module is `packages/agent/src/harness/utils/truncate.bend`. Public result field names and `truncateHead`, `truncateTail`, `truncateLine`, `formatSize` names match upstream. Bend has no optional call arguments, so head/tail take an explicit `TruncationOptions` record containing `Maybe` fields; `defaultOptions()` supplies the defaults. `truncateLine` takes an explicit limit, with `truncateLineDefault` supplying its default. Exported constants retain their names as nullary functions. Counts use `Nat`. This module still needs downstream integration; it does not imply the agent harness is ported.

## Runtime prerequisites for the core types

Bend 2.0.4 provides `F32`, while TypeScript numbers use binary64. Provider costs, sampling values and other numeric APIs require a binary64 solution before those types can be considered faithful; silently substituting F32 is not acceptable. The prototype's decimal JSON tokens only preserve serialization and do not solve numeric operations.

`packages/runtime/src/u64.bend` provides pure-Bend 64-bit integer operations, `u128.bend` supplies exact products, and `f64.bend` uses them for binary64 arithmetic, comparison and unsigned integer conversion. Independent vector tests pass; decimal parsing and remaining numeric operations are still prerequisites for complete integration. Shortest base-10 formatting now uses exact intervals in `f64-decimal.bend`, with direct JavaScript spelling tests. This package is a language support dependency, not a replacement for pi's library boundaries. Content, usage/cost, user/assistant/tool-result messages, deferred handles and assistant-event declarations now live in `packages/ai/src/types.bend`; the module remains explicitly partial, with schema constraints and provider-option contracts still pending; model data and schema-data declaration comparison are implemented separately. Opaque upstream argument/diagnostic records use explicit type parameters; a common heterogeneous value representation and the complete schema relationships still need integration.

`AssistantMessageEvent.partial` is a shared live response object in upstream, not an event-time snapshot. Immutable copies alone would change that contract. The event-stream port therefore needs an explicit shared-state representation and tests for consumers that retain event references. `EventStream.result()` settlement and queued-consumer termination also need distinct tests.

Pure-Bend `Ref`, `Deferred` and reusable `Callback` primitives now provide the shared identity, settlement and callback foundations. They use standard Bend channels rather than custom foreign code. Native concurrency tests cover retained identities, atomic updates, fan-out and concurrent callback invocation. Their explicit disposal requirement is a temporary mismatch with JavaScript garbage collection; managed shared-object reclamation remains required. All five upstream generic event-stream cases now have separate passing native ports, including consumer registration order and explicit end behavior. The stream module preserves typed callbacks, the shared result promise, per-iterator request serialization and live payload references. The typed assistant-event specialization is implemented and has native identity/extraction tests. Generator return/throw, recoverable callback errors, general scheduler equivalence and downstream integration remain open; passing this suite does not complete those contracts. See `packages/ai/README.md` for the API adaptation and lifetime boundaries.

`AgentTool` exposes argument preparation, schema validation, streaming updates, abort signals, structured details, tool usage, replay policy and execution-mode overrides. The prototype's `ToolResult{text,error}` is insufficient and is not the target tool API.

The canonical input boundary now includes `Tool<Parameters>`, `SystemMessage`, the four-way `Message` union, `Context` and distinct `TranscriptContext`. Normalization retains the original message/tool handles and prepends shorthand prompt/tools only when needed. Text rendering uses a pure-Bend own-property record to preserve JavaScript section enumeration. All nine upstream replay-suite cases have passing ports. Replay/collapse and transport tool anchoring are implemented, with separate own-property and insertion-ordered map semantics. Full schema-object declaration integration, schema constraints, custom-role structural inputs and mutable collection aliasing are still open.

Faithful declaration comparison still depends on numeric serialization: upstream compares JSON round-tripped schema declarations. `packages/runtime/src/big-nat.bend` now supplies tested exact integer arithmetic and integer decimal conversion for the binary64 codec. This does not make the old raw-token JSON encoder suitable for canonical types; shortest binary64 formatting is now implemented, while decimal parsing, dynamic-value serialization rules and schema metadata handling remain necessary before completing declaration comparison.

Canonical `JsonValue` serialization now combines exact numeric spelling, own-property enumeration and UTF-16-compatible quoting. UTF-16 scalar/pair equivalence also applies to record and ordered-map keys, preventing duplicate properties with equivalent JavaScript names. This codec does not substitute JSON for typed messages, tools or extension objects. Their wire codecs and the dynamic schema projection that omits undefined/executable/symbol fields remain separate required work.

The runtime schema-data projection now explicitly models undefined, callable and symbol values plus property enumerability. Its finite-tree snapshot preserves JSON round-trip rules without decimal parsing, since shortest round-tripping preserves finite binary64 values except negative zero. It rejects unsupported callable `toJSON` hooks instead of erasing them. Live-object semantics, TypeBox schema relationships and full typed-tool declaration integration remain pending. Constrained-sampling configurations now retain both required-field orders explicitly, and grammar variants retain ordered optional properties. Their typed JSON codec is tested against JavaScript. Arbitrary extra runtime properties and shared mutable configuration objects still need extension-object integration before full dynamic-object equivalence.

`utils/schema-json.bend` bridges finite schema snapshots into the canonical JSON codec. The original schema tree remains separate from its JSON-visible declaration snapshot, so hidden metadata is not removed from the schema representation itself. Differential tests now include actual TypeBox 1.3.27 output; that version uses non-enumerable string metadata by default and can expose it through its `enumerableKind` setting. The TypeBox builder/validator port and static type relationships are still open.

The transcript module now exposes declaration projection/comparison for tools whose schema is represented by the finite schema-data tree. `tool-declaration.bend` uses the schema snapshot and canonical JSON codecs; it does not use structural equality or the prototype encoder. Recoverable `DeclarationResult` values distinguish upstream round-trip failures and unsupported live-object hooks, and comparison processes the left input first. Direct tests against pinned pi-mono verify output and error ordering. This schema-data boundary still requires the typed TypeBox and extended-tool adapters before the complete public contract is met.

Schema-data `getToolStateChanges` preserves the source algorithm’s distinct lookup maps, filtered source arrays and projected additions. It does not deduplicate returned entries or interleave filtering with projection. Tests compare directly with upstream and include the original replay-suite change assertions. Mutable input adapters and typed schema integration remain required.

Schema-data history redefinition detection keeps shared tool references rather than serialized snapshots. It compares repeated names even for identical references, ignores removals, skips schema serialization on first declaration and terminates at the first change/error. The original combined history test and direct upstream differential cases verify these behaviors. Replay tests now use the verified TypeBox data fixture throughout; the remaining schema/general extension-object adapters are still required for full library equivalence.

The initial canonical agent types now retain the complete tool/result field sets. The pure `agent/types.toTool` function provides an explicit structural base projection preserving declaration fields while omitting execution/display fields. The final upstream replay test uses this real type and verifies callback non-invocation. The schema/argument type relationship and execution runtime remain explicit gaps. Importing the agent types from ai tests exposed a Bend module-loader namespace bug; the locally applied patch and targeted regression live under `patches/` and `tests/module_imports.py`, with no foreign production adapter.

Model data now includes the full `Model`/`ImagesModel` field sets and compatibility/routing structures. A dependent `compat` field is indexed by the model’s API discriminator, so incompatible family records fail type checking instead of being admitted by an unrestricted union. Open API names round-trip through the model-api adapter; provider/catalog specialization and model behavior remain open. Upstream `calculateCost` mutates and returns the existing nested usage-cost object, so a value-only cost calculation would not complete that API; the canonical usage record now carries a shared cost reference to preserve that identity.

The initial `models.bend` leaf utilities use the complete model record: thinking support/clamping read its reasoning/mapping fields, and model identity reads id/provider. Runtime API matching uses canonical UTF-16 equality. The boolean predicate does not yet supply a dependent narrowing witness; provider specialization and registry methods remain required. Tests execute the unchanged pinned helper bodies with types erased and separately port the two standalone max-thinking assertions.

`calculateCost` now takes the full model/usage records and updates `Usage.cost` through its original shared handle. Numeric computation lives in `utils/cost.bend`, preserving source evaluation order and request-wide tier selection; the public function remains in `models.bend`. The result handle aliases the usage field, rather than representing a detached value. Native identity checks and the original upstream pricing case verify this boundary. General dynamic-object accessors/extras, automatic lifetime reclamation and provider integration remain separate work.

The model-store port requires abort preflight and faithful structured cloning. The initial runtime abort module supplies shared signal state and stable first-reason settlement, with recoverable results adapting exception propagation. It does not yet supply EventTarget listeners or pi's abort-race utility. Deferred observations now support atomic removal, and abort observations use it. Cancelled receiving tasks must still drain their tickets before disposal. This removes the retained-waiter obstacle, but it does not yet establish EventTarget callback semantics, promise-reaction ordering or abandoned-rejection handling for the source abort-race utility. Model-store cloning must preserve the supported value graph and reject unsupported values according to its source contract; JSON round trips are not an equivalent replacement. Neither the store nor the abort utility is marked implemented.

Exact callback identity is now available through a small Bend compiler primitive and pure shared-reference/callback wrappers. This is required for EventTarget duplicate/removal matching; equal callback code and captures are insufficient. Node 24.18.0 reference traces additionally show live linked-list dispatch behavior, including callbacks added during dispatch. The listener implementation must cache each next link before callback invocation, preserve removed nodes while an active traversal can reach them, and remove once listeners before reentrant invocation. A DOM-style frozen listener snapshot is not equivalent to this Node reference. The checked-in host oracle records these cases; native listener dispatch, event flags, exception reporting and other supported-runtime verification remain pending.
