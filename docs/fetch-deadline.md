# Fetch timeout and response lifetime

OpenAI SDK 6.40.0 `client.ts:fetchWithTimeout` creates a child abort controller, forwards parent cancellation, and clears the timeout when fetch settles. Successful fetch settlement is the response-header boundary, not the end of the streamed body. The SDK also uppercases the method here; the pure request envelope retains the earlier `buildRequest` representation. `tests/openai_fetch_timeout_reference.mjs` exercises the installed SDK with an injected fetch and fake credentials, checking both success and rejection without network access.

`runtime/deadline.disarm` now consumes a deadline scope and returns its successor with the timer cancelled and its worker joined. It retains the child controller and parent observation. An expiry that already won remains settled; after disarm returns, the retired timer cannot newly settle the child. Repeating disarm is safe, including for pre-aborted scopes that allocated no timer. Final `close` still retires parent forwarding and disposes the child, after all borrowers finish. The affine `Following` variant represents that only parent forwarding remains owned.

The parent worker retains a cancellation capability for the retired timer. This is safe because the native timer checks live state and generation, and the JavaScript backend retains the closed row object. A regression explicitly reuses a native timer slot before cancelling the original parent and requires the unrelated timer to expire normally. No primitive or compiler patch changed.

Validation uses the existing uninstalled `dns-transport-teles` compiler candidate: nine unmodified executions and 36 instrumented executions across native one/four threads and Bun. Cases cover early close, expiry, parent reuse, broadcast, parent/expiry and close/expiry races, repeated disarm, parent forwarding after disarm, settled expiry preservation, pre-aborted parents and timer-slot reuse. Native exit audits require zero live timers, timer waiters and channels; Bun audits timer owners/waiters, not channel rows. These are finite IO/resource checks, not universal concurrency proofs. The existing pure-law gate was not changed or rerun for this effect-only addition.

Evidence: [deadline lifecycle](runtime-validation/2026-09-21-deadline-disarm.json), [actual SDK probe](runtime-validation/2026-09-21-openai-fetch-timeout.json). Reproduce with `python3 tests/deadline_check.py build/bend-profiles/dns-transport-teles/bend2` and `node tests/openai_fetch_timeout_reference.mjs`.

This first milestone implemented the lifetime primitive needed for fetch dispatch. At that point, the provider fetch adapter, ownership transfer into the streamed response, timeout-range policy, native TLS, and complete request/retry/session assembly remained unfinished. In particular, disarm must occur at fetch settlement; close must wait for the response owner to retire. No upstream pi suite is promoted by this milestone.

## Transfer into response ownership

`runtime/http-fetch-scope.bend` now composes that primitive with the canonical HTTP response owner. `start` accepts literal milliseconds, a borrowed parent signal and an injected dispatch function; dispatch can capture a prepared request and either native or custom transport handles. A pre-aborted scope skips dispatch. Failed dispatch retains both the original typed error and the settled cancellation reason, then retires the scope. The dispatch contract requires it to retire its own partial resources before returning failure.

A successful dispatch disarms the timeout and transfers the scope into each open response's affine transport state. The response metadata and body-exposure flag are preserved. An already-closed response retires the scope immediately. The read adapter preserves transport events/errors and returns the successor owner; the close adapter retires the transport before disposing the signal it borrowed, retaining the transport's cleanup error. Existing HTTP response logic therefore handles natural completion, read failures, explicit close and repeated close without another body state machine. This layer does not relabel HTTP failures as connection failures or retry errors; provider-specific classification remains above it.

The injected integration fixture checks pre-abort, dispatch failure, fetch expiry, already-closed responses, a body surviving past its original timeout, parent cancellation after headers, read failure plus cleanup failure and repeated close. It uses the production response reader and resource primitives. The parent-cancellation read awaits the actual child signal, rather than relying on a scheduling delay. These effectful lifecycle contracts require execution/resource audits; no new pure algebra or theorem is claimed. Native/custom transport selection, the concrete Responses fetch signature, numeric timeout policy and full provider assembly remain pending.

All 105 executions pass: 21 unmodified runs and 84 resource-instrumented runs across native one/four threads and Bun. Each non-pre-aborted request allocates and closes exactly one timer; pre-aborted requests allocate none. Native audits report zero live timer rows, waiters and channels; Bun reports zero live timers/waiters. [Runtime evidence](runtime-validation/2026-09-21-http-fetch-scope.json) pins the source closure. Reproduce with `python3 tests/http_fetch_scope_check.py build/bend-profiles/dns-transport-teles/bend2`. The [compiler evidence](bend-issues/2026-09-21-http-fetch-scope-compiler.json) retains the 8 GiB guarded failure and successful unchanged-source build under 16 GiB. The existing pure-law gate is unchanged and was not rerun for this effect-only adapter.

The subsequent [Responses fetch adapter](openai-responses-fetch.md) now supplies the concrete injectable signature and exact native timeout conversion. Actual native HTTP/TLS transport selection and complete request/retry/session assembly remain pending.
