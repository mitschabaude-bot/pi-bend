# Native provider retry options

The public `StreamOptions` and `ProviderRequestOptions` retain binary64 numeric fields. The pure `provider-retry-config` projection selects signal, retry count and delay limit and delegates to `provider-retry-options`; the request keeps all unrelated settings and borrowed hooks. The stream projection reuses the canonical inherited-field projection in `types.bend`.

An absent retry count remains absent, preserving the retry driver's zero-retry default. A present count must be a nonnegative exact integer representable in the current Bend native Nat range, zero through 2^48−1. Signed zero becomes zero. The binary64 conversion checks an exactly re-encoded bounded candidate before constructing the Nat. Fractions, negative values, nonfinite values and overflow retain their original binary64 bits in a typed error. The representation limit is explicit; no smaller application-specific retry cap is imposed.

An absent delay limit preserves the existing 60-second default; zero disables the cap. Present limits must be finite and nonnegative. Fractional limits and signed-zero bits remain intact. Count validation precedes delay-limit validation. Actual sleep durations are validated separately by the [native retry timer adapter](retry-duration.md).

Generic laws cover accepted field preservation, retained errors, validation precedence, absent defaults and independence from the chosen signal. The canonical request projection law quantifies over all unrelated request settings and callbacks. These are honest control-flow/value-preservation contracts; the binary64-to-Nat arithmetic currently has independent boundary/reference tests rather than a universal arithmetic proof.
