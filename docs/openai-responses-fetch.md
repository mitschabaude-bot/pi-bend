# Responses fetch dispatch

`api/openai-responses-fetch.bend` connects the immutable request envelope to a borrowed injectable fetch callback. `Input<Reason>` contains the typed URL, uppercase method, normalized headers, serialized body and child abort signal. The pure projection retains every request field except the timeout, which owns scheduling outside the callback. This matches the SDK's `fetchWithTimeout` method normalization, following the earlier lowercase `buildRequest` stage.

`choose` selects an explicitly supplied custom callback or the caller's native default without invoking or disposing either. Both implement the same typed response-owner interface. `run` validates timer representability, then uses the existing fetch scope to acquire and return an affine HTTP response. Fetch errors retain the underlying typed cause and cancellation reason. Hooks, HTTP status interpretation, retries and provider session publication remain in their existing enclosing layers; this adapter does not duplicate them.

Native duration conversion is strict. `runtime/timer-milliseconds.bend` extracts a candidate U32, converts it back to binary64 and accepts only exact numeric equality with the original duration. Signed zeros are equal. Fractions, negatives, non-finite values and values above 4,294,967,295 milliseconds fail with the original value retained in a typed error. Conversion bounds its binary shift even for arbitrary IEEE-754 exponents. The runtime uses literal milliseconds, including zero. This deliberately avoids Node's timer clamping of zero or overflow to one millisecond, following the approved strict-input/native-value policy. The current timer's maximum representable duration is an explicit limitation; this change does not provide arbitrary-length timers.

Five generic laws cover conversion decision exactness, rejection of smaller/larger/unordered results, and the invariant that every accepted duration round-trips to the original numeric value. The invariant is proved for all binary64 inputs by case analysis on the numeric comparison, using one supporting lemma. It relies on the existing binary64 comparison/encoding operations; it does not prove those operations mathematically correct or prove that every representable duration is accepted. Three generic laws cover fetch field preservation and default/custom selection for all input values and callback types. Independent numeric testing covers signed-zero and range boundaries, adjacent representable floats, 600 random U32 integers and 600 raw binary64 patterns: 1,225 cases on each of native one/four threads and Bun. These finite comparisons supplement the laws rather than masquerading as universal arithmetic proofs.

The callback integration uses real Bend callback, deadline, abort and response owners with injected transports; it performs no network request. Twelve unmodified and 48 resource-instrumented executions pass across the three backends. They verify native fallback, custom precedence, uppercase method and serialized payload, invalid timeout rejection before timer allocation/invocation, pre-abort skipping invocation, closed-response retirement and caller-owned callback disposal. Native audits require zero live timer rows, timer waiters and channels; Bun audits timers/waiters. The separate [fetch-scope fixture](fetch-deadline.md#transfer-into-response-ownership) covers open bodies, expiry, cancellation after headers, dispatch/read/cleanup errors and repeated close.

Reproduce with `python3 tests/timer_milliseconds_check.py build/bend-profiles/dns-transport-teles/bend2`, `python3 tests/openai_responses_fetch_check.py build/bend-profiles/dns-transport-teles/bend2` and the full `scripts/check-proofs.py` gate. The completed full gate checks 379 public laws and 65 supporting lemmas, rejecting all 212 type-correct mutations as well as open obligations and a missing proof. [Proof evidence](proof-validation/2026-09-21-openai-responses-fetch.json), [numeric evidence](runtime-validation/2026-09-21-timer-milliseconds.json) and [callback/resource evidence](runtime-validation/2026-09-21-openai-responses-fetch.json) retain verified source hashes.

The default/native callback in this fixture is injected. The subsequent [cleartext callback](openai-responses-cleartext-fetch.md) connects real native HTTP transport through the same interface. TLS, content decoding and redirects, authentication refresh, retry/status/session assembly and the full modular coding agent/TUI remain unfinished. No upstream pi test suite is promoted by these integration checks. No compiler patch changed or was installed.
