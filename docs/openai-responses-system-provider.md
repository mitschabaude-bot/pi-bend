# System-owned Responses provider sessions

`openai-responses-system-provider.streamAt` connects actual transcript/credential preparation, caller-hook adaptation, lazy system-owned acquisition, scoped Responses processing and session finalization. It accepts canonical Responses options and the existing model/transcript types. The original preparation supplies grammar metadata even after a payload replacement. The producer owns its runtime; successful processing closes the response before retiring that runtime, while the existing owned acquisition/release paths handle earlier failures.

The new provider error domain preserves the complete typed acquisition cause, including initialization failures. Stream processing can additionally carry recursive reader, sink and pricing failures in the provider's own domain. It never attempts to narrow these into the smaller acquisition error type. Release and disposal causes remain separate. Three standalone laws establish affine success transfer and lossless acquisition/release cause wrapping. A fourth law establishes body-processor-before-runtime-retirement composition and preservation of the complete processing result. That law quantifies over arbitrary owners, messages, callbacks, models and preparations; closed callback templates specialize reason/hook types to `String` and metadata to `Unit`. It does not claim termination of the imported processor or runtime interpreter correctness.

The [integration record](runtime-validation/2026-09-21-system-provider.json) contains 108 successful executions across native one/four threads and Bun, each in plain and resource-audited builds. The fixture uses real preparation and the pinned pi preparation/stream processors as external references. Checks include non-default grammar properties after numeric/null payload replacement, exact tool-event order, original-hook usability after disposal, supplied/internal signal ownership, missing credentials, invalid retry options, payload/response-hook failures, invalid system configuration and malformed SSE JSON. Configuration paths are blocking FIFOs where preparation failures must skip loading. The finalizer closes supplied SSE callbacks before the completed run is observed. Audited channels, parked IO, sockets, timers and fixture file descriptors finish at zero.

The body composition and typed-error laws are now included in the [522-law root gate](proof-validation/2026-09-21-provider-rendering.json). The native compiler runner was terminated while its detached Clang children remained live. Those existing builds were monitored without restarting; their fresh outputs passed all 72 native cases. Full Clang-phase timing and exit-status measurements are unavailable; the runtime results and [compiler observation](bend-issues/2026-09-21-system-provider-compiler.json) distinguish these facts.

The factory still takes explicit SSE callbacks, timestamp, error renderer and final cleanup. It currently selects the owned cleartext transport. Default SSE policy, clock acquisition at the stream boundary, complete error rendering, custom-fetch selection, TLS and authentication lifecycle remain required for the complete public provider. This assembly does not promote an upstream suite or establish the full pi port.
