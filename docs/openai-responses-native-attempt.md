# Native Responses attempts and retry policy

`api/openai-responses-cleartext-attempt.bend` specializes the generic request-attempt adapter for the native resolver, socket exchange and affine response body. It performs one attempt. The existing provider retry driver still owns retry limits, server hints, jitter and abortable backoff; the new adapter does not introduce another retry loop. Successful bodies transfer unread, while failed HTTP statuses finish diagnostic consumption and release before retry handling.

`api/openai-responses-native-error.bend` classifies native typed errors. Invalid requests, rejected transport plans, invalid DNS setup and failed immutable hosts snapshots are terminal. Socket failures, exhausted address attempts, missing HTTP heads/completion and rejected HTTP header syntax produce connection failures. Rejection of malformed wire input remains strict; retrying the request does not accept the malformed response. Request and nested DNS deadline expiration produce timeouts. Explicit/default caller cancellation remains terminal and the retry driver observes the original parent signal.

The resolver already distinguishes exhausted network outcomes (`NoAnswer`) from terminal query failures (`QueryFailed`). The adapter preserves that distinction, including deadline reasons retained with an interrupted DNS query. Invalid setup is not overwritten by a concurrently recorded deadline. Cleanup failures combined with primary transport errors remain terminal, preserving both causes. Deterministic invalid configuration and explicit cleanup failures are not indiscriminately wrapped as retryable connection errors, unlike an SDK boundary that only sees a rejected generic fetch promise. This is the native typed policy under the approved strict-input/error handling approach. The full original native error, resolution trace and attempted addresses remain in `Attempt.FetchFailure`; categorization does not erase them.

The native fetch callback and resolver remain caller-owned for the complete retry operation and any returned response body. The adapter uses the existing [reusable HTTP callbacks](http-transport-callbacks.md), native fetch deadline and bounded diagnostic reader. It has no unsafe declarations. HTTPS is still rejected by the cleartext transport. This integration does not implement TLS, content decoding, redirects, authentication refresh or complete provider hook/session assembly.

Nine generic laws quantify over error payloads, source-error types, platform error codes/messages, nested cancellation reasons and simultaneous primary/cleanup failures. They constrain classification and precedence; they do not prove network progress or resource release. Three new typed mutations attempt to retry rejected plans, overwrite invalid DNS setup with a late deadline, and hide a cleanup failure. The full proof gate also continues checking the root, missing proofs and open obligations. Existing FIFO laws moved unchanged into `laws/fifo.bend`, allowing queue mutation proofs to depend on their local contracts instead of recompiling the entire provider dependency graph.

`tests/openai-responses-cleartext-attempt.bend` composes the actual native fetch, attempt classifier, retry driver and abortable sleep. Its loopback oracle verifies the complete POST target, host/header fields and UTF-8 request body, and requires the first peer to be released before accepting a retry. The 18 scenarios cover success, status/retry-header overrides, malformed headers, timeout, truncated and invalid-UTF-8 diagnostics, bounded diagnostics, retry-delay caps, hosts resolution/failure, HTTPS rejection, invalid read size and pre-abort. A loopback DNS responder additionally verifies A/AAAA questions across two attempts, negative replies and nested DNS timeout classification. Native audits check timer/channel/connect/UDP owner tables, parked IO and socket descriptors below 4096. Bun audits check timer/connect/UDP owners, their waiters and the channel/IO scheduler counters; they do not enumerate every process descriptor. Every checked residual must be zero. These are finite integration checks complementary to the laws, not proof of every IO interleaving or a completed upstream suite.

To reproduce, emit `tests/openai-responses-cleartext-attempt.bend` as `build/openai-responses-cleartext-attempt.c` and `.js` with the isolated compiler described in `docs/laws.md`. Use `scripts/run-rss-guarded.py` with a 24 GiB process-group guard for C and 12 GiB for JS. Then run:

```sh
python3 tests/transport_audit.py build/openai-responses-cleartext-attempt build/bend-profiles/dns-transport-teles/bend2 --compile
python3 tests/openai_responses_cleartext_attempt_check.py
BEND="$PWD/build/bend-profiles/dns-transport-teles/bend2/main.ts" python3 scripts/check-proofs.py
```

The audit helper instruments generated test programs only. Production networking and retry behavior remain Bend. `--js-only` and `--js-audit` select provisional Bun checks while native compilation is in progress; they are not substitutes for the complete backend matrix.

All 108 executions pass: 18 scenarios on native one/four threads and Bun, in both production and instrumented programs.
