# Structured parallel pairs

`io-pair.both` starts two operations before waiting for either and joins both children before returning a tuple in argument order. Its two result types are independent and may contain affine owned values. Typed errors are ordinary results: one failure does not abandon the other operation or its join channel. Operations retain responsibility for their resources and cancellation. The primitive does not kill an arbitrary callback that never finishes and does not recover from `IO.die` or a runtime trap.

`dns-search-parallel.run` adapts this ownership rule to the existing finite search cursor. Both callbacks receive the same candidate, including its origin and wire name, and a borrowed environment. The supplied protocol-aware merge receives both full reports only after both children have been joined. Only its resulting `Answer`, `Failed` or `Halt` reaches the existing search transition, so separate address-family callbacks cannot advance independently to different suffix candidates. Copyable local aliases preserve the ordinary callback argument quantities required by `dns-search-run`.

This is scheduling infrastructure for paired DNS candidates. It does not yet select shared servers, allocate paired identifiers, merge actual A/AAAA wire results, interpret `single-request`/`single-request-reopen`/`no-aaaa`, or construct a shared deadline. The native combined-family adapter must supply those policies; running two complete independent single-family searches would not implement this contract. Existing single-family resolution remains in use.

## Validation

The fixtures use symmetric channel handshakes to require concurrent startup. A separate channel fixes left-first or right-first completion without sleeps or timing assumptions. Pair checks return affine payloads or distinct typed errors in every combination. Search checks exercise paired candidate traces, both callback completion orders, exact merged results, typed halts and equal request counts through the same suffix cursor. The fixture's merge is intentionally a small scripted policy, not an oracle for production DNS response precedence.

Across native one/four threads and Bun, 768 pair cases and 4,374 paired-search cases pass. These are effectful integration checks, not proofs over IO semantics. The existing 135-law/94-mutation proof record's full source closure is unchanged; no new theorem is claimed for scheduling, liveness or channel lifetime.

Disposable native exit instrumentation counts live channel rows and parked computations. The Bun harness separately counts channel opens/closes and checks its live-operation/wait counters. The distinction matters: live-operation count alone does not detect an unclosed but idle JavaScript channel. The open/close instrumentation observes explicit ownership retirement; it does not measure garbage-collector retention. All counters are zero for the valid implementation.

Two well-typed runtime mutations validate those checks on all three backends. Replacing parallel startup with sequential execution deadlocks the symmetric handshake and is rejected by the runtime deadlock diagnostic or bounded process timeout. Receiving the second result without closing its join channel preserves output but fails the channel audit. The mutation runner works in a disposable checkout and does not edit production files. Final source hashes and compiler fingerprints are retained in the [integration record](runtime-validation/2026-09-20-io-pair.json) and [mutation record](runtime-validation/2026-09-20-io-pair-mutations.json). Builds use the installed compiler under an 8 GiB guard; no compiler/runtime patch or new unsafe annotation was needed.
