# Responses request attempts

`api/openai-responses-attempt.bend` connects the prepared fetch operation, affine HTTP response, bounded error diagnostics and provider retry interface. It implements one attempt; `utils/provider-retry` owns retry counts and delay policy. The existing `openai-responses-request` payload builder remains separate. Successful responses transfer unchanged and unread. Failed HTTP statuses consume and close their diagnostic body before the attempt returns a retry failure.

The adapter retains HTTP status and retry headers even when reading, decoding or bounding the diagnostic fails. The OpenAI SDK catches a failed diagnostic read and constructs its status error from the caught error's message; Bend retains the typed cause and response metadata. Cleanup errors remain nested in the existing body-consumer error. Diagnostic read or encoding failure therefore does not accidentally disable a server-requested retry or override a server-requested refusal.

Fetch errors retain their exact original typed value. A caller-supplied classifier distinguishes deterministic configuration failures, connection failures and timeouts. Invalid timer durations and deterministic configuration failures are terminal; a concurrent timeout does not turn an invalid configuration into a network failure. Fetch-scope expiry produces a retryable timeout, while caller cancellation stays terminal and the outer retry driver observes the parent signal. The [native transport adapter](openai-responses-native-attempt.md) now supplies a typed classifier; full hook/session composition remains pending. This generic module does not assume that every arbitrary fetch failure is a connection error.

Six universally quantified laws cover terminal configuration errors, parent cancellation, timeout cause retention, HTTP diagnostic and retry metadata preservation, and successful affine response transfer. They establish pure data transformations; they do not prove network liveness or resource retirement. The fixture composes this attempt with the actual Bend retry driver and injected fetch/read/close/delay callbacks to check effect ordering separately. It covers 429 retry, 400 rejection, explicit retry-header overrides, connection/configuration/timeout classification, diagnostic read and UTF-8 failures, simultaneous read/close failure, diagnostic size rejection, delay caps, pre-abort and first-attempt success.

Reproduce by compiling `packages/ai/test/openai-responses-attempt.bend` to `build/openai-responses-attempt.c` and `.js` with the isolated candidate compiler, then running `python3 tests/openai_responses_attempt_check.py build/bend-profiles/dns-transport-teles/bend2`. Run the generic proof and mutation gate with `BEND="$PWD/build/bend-profiles/dns-transport-teles/bend2/main.ts" python3 scripts/check-proofs.py`. The 14 injected cases now pass across native one/four threads and Bun, including 42 normal and 126 resource-audited executions. The BEND-024 application correction uses [reusable transport callbacks](http-transport-callbacks.md). The selected runtime regression record contains 3,069 passing cases, including live socket/SSE and native buffered-body resource audits. [Runtime evidence](runtime-validation/2026-09-21-http-transport-callbacks.json) and [compiler evidence](bend-issues/2026-09-21-http-transport-callbacks-compiler.json) pin the sources and programs. The full proof gate passes 390 public laws and 65 supporting lemmas and rejects 216 type-correct mutations, open obligations and a missing proof; [proof evidence](proof-validation/2026-09-21-http-transport-callbacks.json) pins the checked source closure. These checks do not establish complete-provider or upstream-suite completion. Native TLS, content decoding, redirects, authentication refresh and full provider/agent/TUI assembly remain unfinished.
