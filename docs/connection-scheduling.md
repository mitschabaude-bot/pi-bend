# Connection attempt ordering and scheduling

The local reference runtime is Node v24.18.0. Its `net` source and observed defaults are identified by version and source hash in the [ordering evidence](runtime-validation/2026-09-20-connection-order.json). Inspection of `lookupAndConnectMultiple`, `internalConnectMultiple`, `afterConnectMultiple` and `internalConnectMultipleTimeout` establishes the reference behavior for this work: group by address family, keep the first occurrence of each address, alternate families starting with the first valid input family, and try the resulting sequence. Non-final attempts receive a family-selection timeout; a failed or timed-out attempt is retired before advancing. The final attempt has no family-selection timer. The observed local default is enabled auto-selection with a 250 ms attempt timeout; no Bend application default is selected by this milestone.

`connection-order.prepare` implements ordering over native address values. An ordered candidate sequence determines preference from its first address, matching the reference's ordered resolver input. Paired DNS groups have no cross-family order, so their preference remains a required explicit argument. Within each family, the first occurrence and original relative order survive. The generic `list-interleave` primitive alternates heads and retains the remaining suffix when either list ends.

Duplicate identity is the native address value, including IPv6 scope. IPv4 and mapped IPv6 remain different families. Node compares canonical address strings in the exercised input corpus; this native API does not retain alternative textual spellings as distinct identities. Original resolution reports remain unchanged in the preceding candidate plan, including duplicate records and their metadata. Deduplication affects connection attempts only. The implementation uses immutable per-family lists and linear membership checks, giving the same quadratic worst-case duplicate-search complexity as the reference's array membership checks; no faster asymptotic claim is made.

The differential oracle runs the real local Node planner with an injected lookup callback and a BlockList covering all IPv4/IPv6 destinations. It observes actual BlockList checks and requires blocked errors, without copying the planner's sorting algorithm. There are 560 such planner calls, four empty-input controls that do not invoke Node, and two native scope-identity controls. All 566 results are checked independently on native one/four threads and Bun (1,698 cases total). Scoped identity controls are not claimed as Node differential evidence.

Four generic interleaving laws establish empty-side behavior, the ordered leading pair and preservation of the sum of both input counts, using two supporting natural-number lemmas. They do not prove the entire address deduplication algorithm; that layer currently has the external-reference and scope-identity checks. Timed connection driving, aggregate failures, cancellation/ownership integration and HTTP exchange adoption remain pending. This module orders attempts and opens no socket.

The [full proof gate](proof-validation/2026-09-20-connection-order.json) checks 181 public laws and 57 supporting lemmas and rejects all 117 typed mutations. Runtime and proof source hashes match the final files. Builds and proofs use the existing isolated compiler candidate under the runtime build's 8 GiB guard; no compiler/runtime patch or unsafe annotation was added.
