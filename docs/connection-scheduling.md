# Connection attempt ordering and scheduling

The local reference runtime is Node v24.18.0. Its `net` source and observed defaults are identified by version and source hash in the [ordering evidence](runtime-validation/2026-09-20-connection-order.json). Inspection of `lookupAndConnectMultiple`, `internalConnectMultiple`, `afterConnectMultiple` and `internalConnectMultipleTimeout` establishes the reference behavior for this work: group by address family, keep the first occurrence of each address, alternate families starting with the first valid input family, and try the resulting sequence. Non-final attempts receive a family-selection timeout; a failed or timed-out attempt is retired before advancing. The final attempt has no family-selection timer. The observed local default is enabled auto-selection with a 250 ms attempt timeout; no Bend application default is selected by this milestone.

`connection-order.prepare` implements ordering over native address values. An ordered candidate sequence determines preference from its first address, matching the reference's ordered resolver input. Paired DNS groups have no cross-family order, so their preference remains a required explicit argument. Within each family, the first occurrence and original relative order survive. The generic `list-interleave` primitive alternates heads and retains the remaining suffix when either list ends.

Duplicate identity is the native address value, including IPv6 scope. IPv4 and mapped IPv6 remain different families. Node compares canonical address strings in the exercised input corpus; this native API does not retain alternative textual spellings as distinct identities. Original resolution reports remain unchanged in the preceding candidate plan, including duplicate records and their metadata. Deduplication affects connection attempts only. The implementation uses immutable per-family lists and linear membership checks, giving the same quadratic worst-case duplicate-search complexity as the reference's array membership checks; no faster asymptotic claim is made.

The differential oracle runs the real local Node planner with an injected lookup callback and a BlockList covering all IPv4/IPv6 destinations. It observes actual BlockList checks and requires blocked errors, without copying the planner's sorting algorithm. There are 560 such planner calls, four empty-input controls that do not invoke Node, and two native scope-identity controls. All 566 results are checked independently on native one/four threads and Bun (1,698 cases total). Scoped identity controls are not claimed as Node differential evidence.

Four generic interleaving laws establish empty-side behavior, the ordered leading pair and preservation of the sum of both input counts, using two supporting natural-number lemmas. They do not prove the entire address deduplication algorithm; that layer currently has the external-reference and scope-identity checks. Timed connection driving, aggregate failures, cancellation/ownership integration and HTTP exchange adoption remain pending. This module orders attempts and opens no socket.

The [full proof gate](proof-validation/2026-09-20-connection-order.json) checks 181 public laws and 57 supporting lemmas and rejects all 117 typed mutations. Runtime and proof source hashes match the final files. Builds and proofs use the existing isolated compiler candidate under the runtime build's 8 GiB guard; no compiler/runtime patch or unsafe annotation was added.

## Owned timed and final attempts

`connection-attempt.timedWith` lends one child deadline signal to an injected connector, then closes the deadline scope and joins its timer/parent watcher before returning the connector's affine value. `timed` supplies the native socket connector. The callback must finish its borrowed work before returning. `finalWith` and `final` borrow the caller's signal directly and allocate no family-selection timer. The caller can still impose an overall deadline through that parent signal; this layer selects no timeout default.

`connection-attempt-result` distinguishes expiry, parent cancellation (including its default reason), socket errors with original code/message, and unexpected default child abort. A late child settlement remains a diagnostic beside the connector's result: cleanup does not overwrite a settled success or socket error. The eventual multi-address driver must additionally check retained parent cancellation before advancing or handing off a socket, closing a successful socket if cancellation wins that boundary. Aggregate errors and that driving loop remain pending.

The [runtime evidence](runtime-validation/2026-09-20-connection-attempt.json) contains 168 passing process runs / 2,148 attempt calls across native one/four threads and Bun, with both unmodified and audited generated programs. Real IPv4/IPv6 loopback peers cover success and caller socket closure, refusal, invalid port, supplied/default pre-abort, expiry against a full accept queue, and cancellation during a pending connect. Injected connectors deterministically settle the child deadline before returning success or a socket error to check late diagnostic retention. These injected cases are not a timing-race proof.

Audits require zero remaining timer/connection owners, waiters and channels; native checks also scan socket descriptors 0–4095 and the parked IO list, while Bun checks its live/waiting IO state. Every final attempt and every pre-aborted timed attempt allocates zero timers; all other timed cases allocate exactly one per call and never overlap their timer lifetimes across sequential calls. Six generic normalization laws preserve arbitrary socket metadata and parent reasons and distinguish the two child-abort boundary cases. The [proof gate](proof-validation/2026-09-20-connection-attempt.json) checks 187 public laws and 57 supporting lemmas and rejects all 120 typed mutations. This is not a universal proof of IO ownership or scheduling. Source hashes match; the existing isolated compiler candidate remains uninstalled and unchanged.

## Finite fallback driver

`connection-driver.runWith` now walks the supplied ordered address list and supports injected connectors and an owned-resource release callback. `run` composes the native timed/final attempt wrappers, with explicit port and attempt duration. Each call consumes one list cell; a finished state stops before the tail. This structural recursion passes Bend's termination checker without an unsafe annotation. The connector contract requires closing borrowed work before returning, so the next attempt cannot overlap a preceding attempt's owned timer or watcher.

Every completed attempt contributes an immutable entry containing its address, timed/final mode, original outcome metadata and retained deadline diagnostic. Entries return in execution order, including a successful connector whose resource was subsequently rejected at the parent-cancellation boundary. The report distinguishes no input addresses, exhaustion, parent/reported abort and an unexpected default child abort. Retained parent cancellation is checked before starting each attempt and after its connector returns; cancellation observed at the latter boundary releases a successful owned resource before returning an error. Abort after the final observation can still follow successful ownership handoff, as with the underlying connector.

The pure `connection-progress` policy accepts success, advances only on socket failure/expiry, and stops on either form of abort. Eight generic laws establish parent-abort precedence for every outcome, failure classification, success acceptance and timed/non-final versus untimed/final selection over arbitrary list element types and tails. They do not prove complete IO trace correctness. The [proof gate](proof-validation/2026-09-20-connection-driver.json) checks 195 public laws and 57 supporting lemmas; all 123 typed mutations are rejected.

All 1,560 [runtime checks](runtime-validation/2026-09-20-connection-driver.json) pass across native one/four threads and Bun, with unmodified and audited programs. The 1,512 injected cases vary list lengths zero through six and every stopping position (including beyond the end), checking exact call/history order, no work after stop, retained error/expiry diagnostics, pre-abort, reported abort, unexpected child abort and parent cancellation before success/failure handoff. Owned channel results are closed by the caller on success or exactly once by the release callback when rejected. The 48 real dual-family loopback cases exercise first-address success, refusal fallback, timeout fallback and exhaustion in both family orders. Timer counters require exactly one non-final timer and no final timer; all audited resources retire. Source hashes match and no compiler/runtime patch changed.

Connection ordering and this driver remain separate from resolver error priority. They select no application family preference, attempt timeout or total deadline default. HTTP resolution-to-connection orchestration, overall connection budgets, TLS/proxy transport and migration of the full HTTP/pi consumers remain pending; the bootstrap CLI remains a prototype.
