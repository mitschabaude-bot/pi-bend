# Native HTTP dates and retry hints

`runtime/http-date.parseAt` interprets IMF-fixdate, RFC 850 and asctime using the native calendar and rolling year resolver. All formats are UTC. It rejects invalid calendar fields, mismatched weekdays, unsupported syntax and zones, and leap-second fields outside 23:59:60. Errors retain their typed calendar/year causes. Surrounding and repeated spaces retain the existing syntax module's tolerance.

Ordinary timestamps retain exact signed millisecond words. A leap second is represented separately with the preceding ordinary second's timestamp; converting it to Unix milliseconds returns `LeapSecondNotRepresentable`. This preserves the supplied second instead of normalizing it into another instant. The interpreter recognizes the RFC's leap-second field form; it does not consult an external leap-second announcement table or prove that a leap second occurred on the supplied day.

`provider-http-date.create` supplies an owned native callback for the retry API. Each call reads the actual wall clock for the RFC 850 year window, then uses the pure parser and native binary64 conversion. Invalid dates and unrepresentable leap seconds become NaN at this numeric API boundary. The callback must be disposed after its retry users finish. The cleartext default dependency owner now owns this callback; full provider-session installation remains pending.

The reference record contains 5,463 cases on each of native one/four threads and Bun, with 86 callback create/call/dispose lifetimes per backend. Ordinary dates are compared against Python's UTC calendar across month ends, leap centuries, endpoints and random dates. It also checks exact numeric bits, incorrect weekdays, malformed fields/zones, year zero, all three leap-second forms and whitespace handling. This fixture does not instrument resource counts, so those lifetime executions alone do not establish leak freedom.

Five generic laws prove exact ordinary Unix conversion, explicit leap-second conversion failure, preservation of calendar/year errors, and rejection at the weekday-validation boundary. They use no unsafe annotations and are included in the 482-law root gate. They do not prove complete parsing, weekday arithmetic or calendar correctness; the runtime comparisons cover those finite cases.

This intentionally differs from permissive JavaScript date parsing, following the agreed strict-input policy. The recorded Node reference converts `Sat, 31 Dec 2016 23:59:60 GMT` to `2016-12-31T23:59:00.000Z`; Bun 1.4.0 was also observed to produce the same timestamp. Bend preserves the leap-second form and ignores that unrepresentable retry date hint. It also rejects ISO/non-HTTP date strings and contradictory weekdays instead of relying on host-dependent coercion. The applicable protocol grammar and two-digit-year rule are in [RFC 9110 §5.6.7](https://www.rfc-editor.org/rfc/rfc9110.html#section-5.6.7).
