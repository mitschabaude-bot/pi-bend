# Scoped Responses body processing

The generic `openai-body-responses-reader` consumes an owned HTTP byte source and owns the Responses reader above it. The source captures the concrete transport's read and close operations. Disposal closes the Responses reader before retiring source callbacks and the body owner; separate reader/body errors and simultaneous failures remain typed. `openai-http-responses-reader` delegates to this implementation while retaining its concrete entry points and result constructors.

`openai-responses-scoped-reader` supplies the existing fetch-scope read and close operations for a successful native attempt. Header acquisition has already disarmed the deadline. Caller cancellation remains observable until final body disposal, which closes the transport before retiring the parent observation. This adapter adds no IO primitive or foreign production implementation.

All 78 scoped-reader executions pass across native one/four threads and Bun, plain and audited: [runtime evidence](runtime-validation/2026-09-21-scoped-responses-reader.json). Cases cover fixed/chunked/EOF framing, early termination, an unread body, cancellation, truncated bodies, malformed JSON/events, provider errors, empty input and a body arriving 1.15 seconds after headers under a retired one-second deadline. Native audits check channels, parked IO, socket descriptors 0–4095, live timers and timer waiters. Bun audits check its instrumented channel/IO scheduler and timer rows; this is not a census of every process resource. Peers observe closure in every case.

The fixture opens its loopback TCP connection before entering the fetch scope. Its deadline case establishes response-body lifetime, not connection-timeout coverage or acceptance of the complete provider. The separate configured-acquisition fixture tests native request/hook/retry assembly. All 72 existing concrete-reader regression executions pass after delegation: [regression evidence](runtime-validation/2026-09-21-http-reader-delegated.json).

`openai-responses-process-result` converts processing output into the lifecycle driver's result while preserving the final immutable message and independently mapped primary/disposal causes. Its generic laws, and the generic reader's disposal laws, pass in the [full proof gate](proof-validation/2026-09-21-scoped-responses.json): 429 public laws, 67 supporting lemmas and 231 rejected typed mutations. The exact unsafe-source audit now includes the existing provider SSE loop, making twenty unchanged source declarations reachable; no unsafe declaration was added. `openai-responses-scoped-process` consumes an acquired response through the shared processor and provides unread-body cleanup for start-event failure. `openai-responses-scoped-session` composes this with the existing session producer and event stream. Their assembled session passes all 36 executions across native one/four threads and Bun, plain and audited: [session evidence](runtime-validation/2026-09-21-scoped-responses-session.json). Exact pi reference traces cover normal output, missing terminal events, malformed JSON after partial output, provider failure, length limits and a late body after header-deadline retirement. Retained immutable snapshots, final results and peer closure match; audited resource counters finish at zero. The existing concrete processor also passes all 90 regression executions after delegation: [processing evidence](runtime-validation/2026-09-21-http-process-delegated.json). The caller must retain borrowed signal, hook and pricing handles through producer completion.

The session fixture starts at dispatch and omits the oracle's preparation, request and response-hook log entries explicitly. Its acquisition program is supplied by the caller; full configured acquisition, self-owned provider dependencies, native TLS and authentication assembly remain unfinished. No upstream suite is promoted by these integration checks.

The [timer boundary regression](runtime-validation/2026-09-21-timer-u32-range.json) additionally checks durations 2³¹ and 2³²−1: both remain pending until explicit cancellation on native one/four threads and Bun. It does not wait for those full durations or prove general timing guarantees.
