# Native Responses request callback

`api/openai-responses-cleartext-request.bend` owns the callback that plugs a concrete native attempt into `openai-responses-acquire.run`. Each invocation passes the exact prepared envelope, borrowed parent signal and fetch callback, and diagnostic limit to the existing cleartext attempt. The surrounding provider/session supplies an error embedding function; the adapter does not convert native errors to strings or reconstruct their retry classification.

`utils/provider-retry-map.bend` maps only the original typed error in a request failure. Provider messages, status, retry hints and retry-delay fields stay unchanged. Terminal failures stay terminal, and successful affine response owners transfer untouched. Six generic laws establish identity, composition, metadata/category preservation and successful/failed result lifting. The [full proof gate](proof-validation/2026-09-21-openai-responses-native-client.json) checks 408 public laws and 65 supporting lemmas and rejects 223 well-typed mutations, open obligations and a missing proof. The two new mutations erase status or change terminal classification; the identity law rejects them before the more specific projection laws. No unsafe declaration was added.

The caller disposes the request callback after acquisition and retries finish. Its borrowed fetch, resolver and parent signal retain their own documented lifetimes. A returned response body owns its transport independently of the request callback. The acquisition fixture now uses this production factory, with a wrapper that only counts and forwards calls. It disposes both request callbacks before consuming a successful returned body. Existing upload, hook-order, retry, malformed-input and resource assertions are unchanged.

All 72 executions pass on native one/four threads and Bun, with production and instrumented executables. The [runtime record](runtime-validation/2026-09-21-openai-responses-native-client.json) pins the tested source closure and programs. All audited residual resource counters are zero, and every accepted peer closes before another request is accepted. Native audits cover socket descriptors 0–4095; Bun audits cover the instrumented runtime owners and scheduler, not every process descriptor.

Reproduce by compiling `tests/openai-responses-acquire.bend` to `build/openai-responses-native-client.c` and `.js` with the isolated compiler from `docs/laws.md`; the guarded builds use 36 GiB and 24 GiB limits respectively. Run `python3 tests/transport_audit.py build/openai-responses-native-client build/bend-profiles/dns-transport-teles/bend2 --compile`, then `python3 tests/openai_responses_acquire_check.py --prefix build/openai-responses-native-client`. The harness supports provisional `--js-only` and `--js-audit` runs while native compilation is pending.

This remains a cleartext transport adapter. TLS, complete provider/session assembly, authentication refresh and the remaining full-port requirements are unfinished. The older retry-sleep adapter still has Node's invalid-duration-to-one-millisecond conversion; that conflicts with the approved strict native policy and is the next correction. These request-callback checks do not validate that legacy conversion, and upstream suite statuses are unchanged.
