# Producer-owned session dependencies

`openai-responses-session.startWithCleanup` takes an affine cleanup program in addition to the existing acquisition, processing and release operations. After the driver settles the canonical stream and the producer retires its publication callbacks, it runs dependency cleanup before returning the task result. `Session.wait` joins that entire lifetime; observing the stream's final message alone does not establish that cleanup finished. The original `start` entry point delegates with an empty cleanup program, preserving caller-owned dependency lifetimes.

This finalizer is for retirement operations that return `IO(Unit)`, such as callback/controller disposal. It does not turn unrecoverable runtime faults into typed errors. Response-body cleanup failures remain independent typed results in the existing processor/lifecycle path; the finalizer does not discard or replace them.

The generic `dependency_cleanup_precedes_unchanged_result` law quantifies every result and cleanup program and fixes their effect order. The [full proof gate](proof-validation/2026-09-21-session-cleanup.json) checks 430 public laws and 67 supporting lemmas and rejects 232 typed mutations, including omission of the finalizer from that combinator. No unsafe declaration was added.

The [gated IO fixture](runtime-validation/2026-09-21-session-cleanup.json) covers success, acquisition failure, processing failure and body-cleanup failure. It observes the final stream result while cleanup is blocked, then releases cleanup and joins `wait`; a shared counter and real callback disposal check single retirement across repeated `wait` and final disposal. All four outcomes pass across native one/four threads and Bun, plain and audited. Native channel/parked-IO and Bun channel/live-IO/waiting-IO counters end at zero. A separately compiled producer that omits dependency cleanup fails the live test. This complements the generic law rather than proving every possible scheduler interleaving.

All 90 [existing provider-session regression executions](runtime-validation/2026-09-21-provider-session-cleanup.json) also pass against the pinned pi wrapper/processor, including retained immutable snapshots and resource audits. The oracle now makes its fixture-specific coupling of iterator closure to caller cancellation optional; its existing default preserves these older scenarios. Native request/session composition will use independent caller cancellation. The new composed native provider remains separate work; this milestone does not complete native TLS, authentication, provider factories or the full port.
