# Native cleartext provider dependencies

`openai-responses-cleartext-runtime` owns the resolver, fetch callback and retry runtime. Its caller supplies a borrowed date parser. `openai-responses-cleartext-default-runtime` adds the native date callback to that lifetime: partial initialization failure retires the callback, and successful disposal retires retry users before the callback. Applications must finish all requests before retiring the owner.

The default owner passes [48 plain/audited native/Bun executions](runtime-validation/2026-09-21-cleartext-default-runtime.json) through the real date parser, entropy-backed generator, wall clock, timer and loopback fetch. Success, early close, cancellation, timeout, bad headers and TLS rejection all retire audited resources. Injected completed initialization errors preserve their causes and retire the date callback. These injections do not simulate an OS entropy failure inside lower-level creation. Four [standalone laws](proof-validation/2026-09-21-cleartext-default-runtime-standalone.json) cover ownership transfer, failure cleanup, borrowed dependencies and disposal order.

`openai-responses-cleartext-system-runtime` supplies system configuration. `load` reads the resolver configuration through the existing Linux environment/hostname/interface policy, accepts strict UTF-8 and validated options, then reads hosts data. Resolver failure stops before hosts access. A hosts failure remains a typed source failure in the snapshot rather than an empty database; numeric-address requests do not use that source. `create` passes the snapshot into the default owner and retains it for inspection, including resolver diagnostics and hosts failures.

Paths and limits are explicit. `linuxFiles` selects `/etc/resolv.conf`, `/etc/hosts`, 4 KiB reads, a 1 MiB per-file limit, a 5-second DNS lookup budget and a 65,535-byte DNS response bound. Embedders can replace these settings. Transport options remain explicit, including connection ordering and HTTP framing limits.

The [system-loading record](runtime-validation/2026-09-21-system-settings.json) passes 117 audited executions on native one/four threads and Bun. It covers three chunk sizes, exact/exceeded file limits, strict decoding, malformed hosts/options, environment overrides and Linux missing-file policy. Resolver-error cases point hosts at a blocking FIFO; their timely return checks that hosts loading was skipped. Every process finishes with zero open fixture descriptors. These tests exercise `load`; creation of the full system owner and its use in a provider session remain pending. Five [standalone laws](proof-validation/2026-09-21-cleartext-system-runtime-standalone.json) establish failure ordering and complete snapshot/dependency retention.

This transport remains cleartext-only and rejects HTTPS. Native TLS, default SSE hooks, complete provider error rendering, custom transport selection and full provider-session installation remain required work.
