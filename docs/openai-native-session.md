# Native Responses acquisition and session

`openai-responses-native-session.start` composes configured request acquisition, the native cleartext attempt/retry adapter, scoped response-body processing, and the canonical asynchronous assistant-message event stream. It accepts an already prepared request and a borrowed context containing URL/header defaults, fetch, retry effects, pricing and SSE hooks. It returns the existing `Session.Run` owner rather than introducing another session state machine.

Cancellation is selected once. A supplied signal remains caller-owned; an absent signal gets a local controller. The selected parent is bound into canonical retry options and passed to native attempts and final session classification. The producer owns its cancellation-query callback and any local controller. It retires them after body processing and publication-callback retirement, before `Session.wait` completes. The borrowed context must remain valid through that boundary. Caller signals are neither disposed nor implicitly aborted when response iteration closes.

Retry-option validation precedes request-factory allocation. A valid acquisition owns one reusable request callback across all retries and disposes it before returning the successful affine body to the processor. Payload/response hooks, diagnostic-body retirement, retry timing and typed failure classification use the existing modules. Request factories do not own returned body state. The immutable error tree retains typed hook, envelope, attempt, acquisition, reader, processing, disposal and release causes. Rendering is an explicit caller function; it does not decide retries.

Eight generic laws specify supplied-signal selection/retirement, preservation of borrowed/local owners, transfer of successful response ownership, preservation of typed acquisition failures, selection of the retry signal, and preservation of all unrelated canonical options and hooks. The last two jointly specify signal binding; the latter uses an independent projection instead of repeating the implementation. The [full proof gate](proof-validation/2026-09-21-native-session.json) checks 438 public laws and 67 supporting lemmas and rejects 235 well-typed mutations, open obligations and a missing proof. No unsafe definition or compiler patch has been added.

The composed fixture passes 144 executions: 24 cases on each of native one/four threads and Bun, both plain and audited, against the pinned pi wrapper and processor. It exercises actual native Bend URL/header/payload construction, HTTP acquisition, status diagnostics, retries with native timers, SSE processing and concurrent canonical event consumers. Cases cover supplied/owned parent signals, ordinary completion, payload/response-hook failure, missing terminal events, malformed JSON, provider failure, length limits, retry success/exhaustion, strict invalid-option rejection, pre-aborted callers, and a body arriving after the retired header deadline. Audited channels, parked/live/waiting IO, native socket descriptors (0–4095), timers and timer waiters finish at zero, and peers observe closure. The [runtime record](runtime-validation/2026-09-21-native-session.json) pins the source, oracle dependencies and generated programs by hash. These finite executions supplement the generic laws; they do not prove universal resource retirement.

The reference uses OpenAI SDK 6.40.0's actual status-error constructor for these cases. It models the SDK's pre-dispatch abort check and keeps caller cancellation independent of iterator closure. The fixture uses the existing native HTTP error formatter, preserving SDK/pi status/body formatting. Strict invalid-option rejection is the previously approved adaptation: it emits an initial failed message without hooks or network requests. Immutable retained event snapshots remain the approved value-semantics adaptation.

This is an explicit prepared-request boundary. Public transcript/request preparation, default dependency ownership, complete default error rendering, authentication lifecycle, transport selection with native TLS, and the full coding-agent port remain separate unfinished work. The current context uses the cleartext transport; custom-fetch option interpretation belongs to the context's factory. No upstream suite status is promoted by this integration alone.
